# myotis-net, part 7: integration tests and probes

*Stop 15 · crate `myotis-net`, `tests/` and one example* · 21 files · 4,518 lines · about 2 hours 45 minutes

The black-box test layer, with three very different kinds of code. Six **offline** files run in every build: five conformance replays that feed bytes generated by the Java engine through one Rust layer and must reproduce Java's answer sheet exactly, and one allocation test that throws 10 MiB hostile frames at every eth and snap decoder. Fourteen **live** files talk to real networks and never run unless someone asks; four of their tests are the release gates from your CLAUDE.md. Last comes `snap_probe`, a diagnostic binary that crawls other EVM chains for snap servers. Tests are also where Rust's ownership rules show up in their simplest form.

## Rust you will practise

- **The test harness** `#[test]`, `#[tokio::test]`, `#[ignore]`, and why “a test fails if and only if it panics” has a surprising consequence for spawned tasks.
- **Ownership at task boundaries** `tokio::spawn` needs owned (`'static`) data; `join` and `buffered` can borrow; a semaphore permit lives exactly as long as its binding.
- **A custom global allocator** `unsafe impl GlobalAlloc`, `#[global_allocator]` and `thread_local!` counters, used to prove that a decoder does not allocate per element.

### How Rust organises tests *Tests · Crates, modules & features*

| Rust | What it means | JUnit / Gradle |
|---|---|---|
| `#[cfg(test)] mod tests { … }` inside a source file | Unit tests, compiled only for `cargo test`. They can see private items. | Tests in the same package, with package-private access. |
| every `*.rs` directly in `tests/` | An *integration-test target*: its own crate and its own binary, linking `myotis_net` like any outside user. Only `pub` items are reachable, and no `[[test]]` entry is needed. | A separate source set that depends on the finished jar. |
| every `*.rs` in `examples/` | A small binary with its own `main`, run with `cargo run --example name`. `cargo test` *compiles* examples (so they cannot rot) but does not run them. | A `JavaExec` task over the test classpath. |
| `#[test]` | A synchronous test function. **It fails if and only if it panics** (`assert!`, `assert_eq!`, `unwrap()`, `panic!`). There is no “skipped” status for tests that return early. | `@Test` |
| `#[tokio::test(flavor = "multi_thread")]` | A macro that rewrites an `async fn` into a plain `#[test]`, which builds a tokio runtime and `block_on`s the body. | A `runBlocking` wrapper. |
| `#[ignore = "reason"]` | Compiled and listed, but run only with `-- --ignored`. | `@Disabled`, but still runnable on demand. |
| `cargo test --release -p myotis-net --test live_cold_start -- --ignored --nocapture name` | Before `--`: Cargo's arguments (profile, package, test target). After: the test harness's arguments (run only ignored tests, show output live, filter by name, `--test-threads=1`). | `--tests "…"` plus JVM flags |

### What runs where *Tests · Crates, modules & features*

Gradle's `cargoTest` task is `cargo test --workspace`, and `check` depends on it. It self-skips on a machine without cargo. Your CLAUDE.md counts a failing `./gradlew check` as a PR-time failure, and its PR workflows (Build and Test in `ci.yml` among them) run on pull requests into any base branch. The workflow files are not in the snapshot, so take that part from CLAUDE.md. On every `./gradlew check` or `build` with cargo:

- the five conformance replays (one test each) and the twelve tests of `el_hostile_frames` **run**;
- the seventeen live tests in fourteen `live_*` files are compiled and reported as **ignored**;
- `examples/snap_probe.rs` is **compiled** (the crate's own dev-dependency on itself even turns on the `fixture-recorder` feature so that another example compiles), but never run.

Release step 3 in CLAUDE.md runs three commands, either by dispatching the `cold-start regression` workflow (preferred, because a runner is a clean host) or locally. They cover four test functions: 3a runs the whole `live_pins_alive` binary, which holds two tests (pins, then bootnodes, one at a time because of `--test-threads=1`); 3b and 3c each run one test of `live_cold_start` by name. The other live files are developer diagnostics with no schedule.

> [!WARNING]
> **A panic in a spawned task does not fail the test**<br>
>
> Tokio catches a panic inside a `tokio::spawn`ed task, and the task's `JoinHandle.await` returns `Err(JoinError)`. If the test ignores that `Err`, the failure is gone. This holds even under `--release`, whose workspace profile says `panic = "abort"`: Cargo ignores the `panic` setting for test targets, because the test harness needs unwinding. In production the same panic would abort the whole process.

### The ladder the tests climb *Protocol & domain*

| Layer | Offline (every build) | Live (on demand) | What the live test asserts |
|---|---|---|---|
| discv4 | `el_discv4_conformance` | `live_discv4` | a node beyond the seed list in 60 s; a per-bootnode census with a floor of 2 seeding |
| discovery filters | n/a | `live_enr_filter`, `live_dns_tree` | discovery produced something; the DNS tree yields dial candidates with no hash mismatch |
| RLPx | `el_rlpx_conformance` | `live_rlpx` | one peer returns a valid Hello within 90 s |
| eth + snap decoders | `el_eth_conformance`, `el_snap_conformance`, `el_hostile_frames` | `live_eth`, `live_snap` | at least one Status exchange (verified fetches are logged) |
| managed peer, pool | n/a | `live_managed_peer`, `live_pool` | a Status exchange; the pool attempted a dial or blacklisted a peer |
| reader + ladder | `el_verify_conformance` | `live_reader` | the reader starts; *if* a query is served, it says `beaconNotSynced` |
| dedicated node | n/a | `live_dedicated_node`, `live_pipeline_bench` | backfill-shaped requests are served consistently; timings only |
| CL sync | (in `myotis-consensus`) | `live_mainnet`, `live_pins_alive`, `live_cold_start` | SYNCED with finality advanced; release gates 3a–3c |

Public peers are unreliable, so each live EL test asserts only what can be reached reliably and logs the rest. That is a deliberate choice: a test that fails whenever mainnet peers are full would soon be ignored.

## Offline: one corpus, two engines

*[Tests](01-primer.md#primer-testing) · [Protocol & domain](01-primer.md#primer-domain)* Each Java twin has two modes. With `-Dmyotis.el.writeExpected=true` it *generates* vector files plus an `expected.txt` answer sheet into `rust/testdata/el/<layer>/`. Without the flag it replays them. The Rust test replays the **same bytes** and must reproduce the **same** `expected.txt`, key by key. That byte-level contract is what lets the Rust engine replace the Java one. Corpora are read at run time from a path built on `env!("CARGO_MANIFEST_DIR")` (the crate directory, filled in by the compiler), so a corpus refresh does not force a rebuild.

### myotis-net/tests/el\_discv4\_conformance.rs

*integration test · 166 lines · Java twin · ElDiscv4VectorConformanceTest*

Replays the discv4 corpus. Rust must *encode* signed Ping/Pong/FindNode packets byte-identical to Java (possible because both sign deterministically, with RFC 6979 low-s ECDSA, from a fixed key and expiry), accept and reject the same packets, and decode Neighbors with the same skip-versus-stop leniency.

`rust/myotis-net/tests/el_discv4_conformance.rs` · lines 31–49

```rust
#[test]
fn replay_reproduces_recorded_verdicts() {
    let corpus = corpus_dir();
    if !corpus.is_dir() {
        eprintln!("el/discv4 corpus not present at {corpus:?} — skipping");
        return;
    }
    let expected = parse_expected(&corpus.join("expected.txt"));

        !expected.is_empty(),
        "corpus present but expected.txt missing/empty — regenerate on the Java side"
    );

    // Same deterministic identity as the Java generator.
    let secret = keccak256(b"myotis-el-a3:discv4-key");
    let key = NodeKey::from_secret_bytes(&secret).expect("valid secret");

    let mut actual: BTreeMap<String, String> = BTreeMap::new();
    actual.insert("key.pubkey".into(), hex(&key.public_key_bytes()));
```

`rust/myotis-net/tests/el_discv4_conformance.rs` · lines 86–107


- *[Tests](01-primer.md#primer-testing)* **The replay shape shared by all five files.** If the corpus is missing, print and `return`. That is a *pass*, mirroring Java's `assumeTrue`, except that Rust has no “skipped” status. Next, parse `expected.txt` into a `BTreeMap` and compute every verdict into `actual`. Then check each expected key, and finally `assert_eq!(expected, actual)`, which also catches *extra* keys.
- *[Ownership & moves](01-primer.md#primer-ownership) · [Iterators & closures](01-primer.md#primer-iterators-closures)* `for (base, raw) in vectors(…)` destructures owned `(String, Vec<u8>)` pairs. `decode_neighbors(&raw)` only borrows. `.collect::<Vec<_>>()` (the “turbofish”) names the collection and lets `_` infer the element type. `ids` is then *moved* into the map.
- *[Enums & pattern matching](01-primer.md#primer-enums-patterns)* `match actual.get(k) { Some(got) => …, None => panic!(…) }`: `get` returns `Option<&String>`, so a missing key has to be handled explicitly.

### myotis-net/tests/el\_rlpx\_conformance.rs

*integration test · 208 lines · Java twin · ElRlpxVectorConformanceTest*

Pins three things across languages: ECIES decryption of the two canonical EIP-8 `auth` messages, session-secret derivation that must reproduce the spec's published AES and MAC secrets, and frame encoding and decoding under fixed secrets. Only the uncompressed Hello frame is byte-compared, because the Java and Rust snappy encoders produce different (equally valid) bytes; the compressed one is only decoded.

`rust/myotis-net/tests/el_rlpx_conformance.rs` · lines 163–173

```rust
fn decode_verdict(dec: &mut FrameCodec, frame: &[u8], want_code: u64, want_body: &[u8]) -> String {
    let body_end = frame.len() - 16;
    let len = match dec.decode_header(&frame[..16], &frame[16..32]) {
        Ok(l) => l,
        Err(_) => return "HEADER_FAIL".into(),
    };
    match dec.decode_body(&frame[32..body_end], &frame[body_end..], len) {
        Ok(d) if d.message_code == want_code && d.payload == want_body => "ok".into(),
        _ => "MISMATCH".into(),
    }
}
```

- *[Borrowing & slices](01-primer.md#primer-borrowing)* `&frame[..16]`, `&frame[16..32]`: borrowed windows into one buffer, nothing copied. `dec: &mut FrameCodec`: frame decryption is stateful (the CTR keystream position and a running MAC), so each decode advances it, and frames must go through one exclusive borrow *in wire order*.
- *[Enums & pattern matching](01-primer.md#primer-enums-patterns)* `match` is an expression: one arm yields `l`, the other `return`s from the whole function. `Ok(d) if …` is a guarded arm.
- *[Bytes, strings & formatting](01-primer.md#primer-bytes-strings)* `frame.len() - 16` would panic on underflow in a debug build for a frame shorter than 16 bytes. That is fine for committed vectors, but not a pattern for untrusted input.
- *[Crates, modules & features](01-primer.md#primer-modules-cargo)* The test imports `myotis_net::el::rlpx::frame::FrameCodec`, but the code lives in `myotis-wire` now (#505). `el/rlpx/frame.rs` is a one-line `pub use myotis_wire::rlpx::frame::*;`, a re-export that keeps the old path working. Java has no equivalent; the nearest is a type alias per class.

- *[Protocol & domain](01-primer.md#primer-domain) · [Result, ? and panics](01-primer.md#primer-error-handling)* **Decoders know what was asked.** Since #454, `decode_block_headers(bytes, requested)` and `decode_receipts69(bytes, requested)` keep at most `requested + 1` items (one extra, so over-serving is visible) and only check the rest. ### myotis-net/tests/el\_hostile\_frames.rs

*integration test (allocation regression) · 317 lines*

The regression test for #454. A peer sent frames that were 10 MiB lists of one-byte elements (492 KB as snappy on the wire), and decoding one into an owned RLP tree cost 547 MB of heap. Every decoder a peer can reach must now stay flat on such a frame: the handshake and read-loop paths (request id, Hello, Status, gossip, control messages) and the responses to our own requests (headers, bodies, receipts for eth/66–70, block access lists, snap ranges and codes). The file counts allocations with its own global allocator, which is why it is a separate test binary: a `#[global_allocator]` applies to the whole binary.

`rust/myotis-net/tests/el_hostile_frames.rs` · lines 18–33

```rust
thread_local! {
    static ALLOCATIONS: Cell<usize> = const { Cell::new(0) };
    static BYTES: Cell<usize> = const { Cell::new(0) };
    /// Bytes allocated and not yet freed on this thread, and their high mark.
    static LIVE: Cell<isize> = const { Cell::new(0) };
    static PEAK: Cell<isize> = const { Cell::new(0) };
}

/// Counts every allocation and reallocation made on the calling thread.
struct Counting;

fn note(bytes: usize) {
    // `try_with`: allocations can happen while the thread's locals are torn down.
    let _ = ALLOCATIONS.try_with(|n| n.set(n.get() + 1));
    let _ = BYTES.try_with(|n| n.set(n.get() + bytes));
}
```

- *[Threads, Send & Sync](01-primer.md#primer-concurrency) · [Interior mutability](01-primer.md#primer-interior-mutability)* **Per-thread counters.** The test harness runs tests in parallel on several threads. `thread_local!` gives each thread its own copy of every counter, so one test never sees another's allocations. Like Java's `ThreadLocal`, but declared statically. `Cell<usize>` allows `set` through a shared reference with no locking, which is safe because a thread-local is never shared.
- *[unsafe & FFI](01-primer.md#primer-unsafe-ffi)* `const { Cell::new(0) }` initialises the slot at compile time. A lazily initialised thread-local could itself allocate on first use, inside the allocator, and recurse. `try_with` instead of `with` returns an error rather than panicking when the thread's locals are already being torn down, which can happen during the last allocations of a thread.

`rust/myotis-net/tests/el_hostile_frames.rs` · lines 42–72

```rust
// SAFETY: every call is forwarded unchanged to `System`, which upholds the
// `GlobalAlloc` contract; the counters are const-initialised thread-locals
// without destructors, so touching them never allocates or re-enters.
unsafe impl GlobalAlloc for Counting {
    unsafe fn alloc(&self, layout: Layout) -> *mut u8 {
        note(layout.size());
        live(layout.size() as isize);
        System.alloc(layout)
    }

    unsafe fn dealloc(&self, ptr: *mut u8, layout: Layout) {
        live(-(layout.size() as isize));
        System.dealloc(ptr, layout)
    }

    unsafe fn realloc(&self, ptr: *mut u8, layout: Layout, new_size: usize) -> *mut u8 {
        note(new_size);
        live(new_size as isize - layout.size() as isize);
        System.realloc(ptr, layout, new_size)
    }
}

#[global_allocator]
static COUNTING: Counting = Counting;

/// `(allocations, bytes requested)` made by `f` on this thread, and its result.
fn counted<T>(f: impl FnOnce() -> T) -> (usize, usize, T) {
    let (a0, b0) = (ALLOCATIONS.with(Cell::get), BYTES.with(Cell::get));
    let out = f();
    (ALLOCATIONS.with(Cell::get) - a0, BYTES.with(Cell::get) - b0, out)
}
```

- *[unsafe & FFI](01-primer.md#primer-unsafe-ffi) · [Traits, generics & dyn](01-primer.md#primer-traits-generics)* **An `unsafe` trait.** `GlobalAlloc` is declared `unsafe trait`: implementing it is a promise the compiler cannot check (return properly aligned memory, never unwind). So the impl is `unsafe impl`, and the `// SAFETY:` comment says why the promise holds: every call is forwarded unchanged to `System`, the platform allocator. fn decode_update(config: &ChainConfig, raw: &[u8]) -> Result<LightClientUpdate, String> {
```rust
    if raw.is_empty() {
        return Err("an empty answer (no update)".to_string());
    }
    if let Some((code, msg)) = codec::leading_error(raw) {
        return Err(format!("result code {code} {msg:?}"));
    }
    let chunks = codec::decode_multi_chunk_response_with_digests(raw, 1)
        .map_err(|e| format!("{} B that do not frame: {e}", raw.len()))?;
    let (digest, chunk) = chunks
        .into_iter()
        .next()
        .filter(|(_, c)| !c.is_empty())
        .ok_or_else(|| format!("{} B carrying no update", raw.len()))?;
    let fork = config.lc_fork_of_chunk(&digest, chunk.len(), LightClientUpdate::GLOAS_SIZE);
    LightClientUpdate::decode_for(fork, &chunk)
        .map_err(|e| format!("an update that does not decode: {e}"))
}
```
