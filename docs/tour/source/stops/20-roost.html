roost: the light-client server

A daemon that the project runs itself. It pulls light-client objects from a local Nimbus beacon node over loopback REST, keeps them in a durable archive plus an in-memory cache of pre-encoded responses, and serves them to wallets over myotis-net's own libp2p stack. This is the carve-out in your CLAUDE.md: roost relays self-verifying objects and never has to be trusted, because every wallet checks every update against sync-committee signatures. Rust-wise it's a textbook async application: #[tokio::main], anyhow, one select! loop, and very little shared state.

Rust you will practise

An application, not a library#[tokio::main], anyhow::Result with context, typed errors only where callers branch on them.
Minimal sharingstate confined to one task; Arc<LcStore> with a std::sync::RwLock; lock poisoning under panic = "unwind".
Bytes you don't trustpanic-free parsing with get, checked_add, let … else, and an append-only file format.
What changed since September

Little, and all of it at the edges. participation_of in main.rs now picks the Gloas or pre-Gloas decoder by length, so Gloas periods are judged instead of reading as undecodable. serve.rs sets three new HostConfig fields (listen_quic, cl_fork_watch, traffic) to None. The codec, protocol names and fork-digest arithmetic roost imports from myotis_net::{codec, protocols, status} now live in myotis-wire (Stop 5); myotis-net re-exports them at the old paths, so roost's imports did not change. The other six files are byte-for-byte the same.

Declares the modules, parses the command line by hand, and dispatches to four commands: probe (read-only upstream diagnostics), ingest (fill the archive without listening), serve (the daemon) and enr (print the ENR it would publish). It also holds the pure rules for “is this stored update provisional?” and find_window_floor, which the daemon reuses. Every error is an anyhow::Error.

  • async cli #[tokio::main] turns async fn main into a plain main that builds a multi-threaded runtime (a work-stealing pool, like ForkJoinPool) and block_ons the body. When main returns, the runtime is dropped, and so are any tasks still running.
  • error-handling anyhow in a binary. Result<T> here means Result<T, anyhow::Error>: any error plus a chain of context, like a Java Exception with causes. ? converts any standard error type automatically. myotis-net's Result<_, String> needs .map_err(|e| anyhow!("{e}")), because String isn't an error type. If main returns Err, the process prints it and exits with status 1.
  • enums-patterns iterators-closures An Option chain for --port: the bounds-checked get(i), then ok_or_else + ?, then parse().ok(), then filter (rejects 0), then ok_or_else + ?. Each step either continues or produces a helpful error.
  • borrowing ownership command.as_deref() turns Option<String> into Option<&str>, so string literals work as patterns without moving command. key_path is moved in two arms, which compiles because only one arm ever runs: moves are tracked per control-flow path.

enums-patterns error-handling domain Choosing a decoder by length. At the Gloas fork the light-client header changed shape: it now carries only the execution block hash, and the whole update has a fixed size, LightClientUpdate::GLOAS_SIZE. A wallet picks the decoder from the chunk's context bytes. roost only needs the participant count, so it uses the fact the doc comment states: no pre-Gloas update has that length. let fork = if … { LcFork::Gloas } else { LcFork::PreGloas }; is an if used as an expression, like Kotlin's. decode_for(fork, ssz) returns a Result; .ok() discards the error, and .map(…) reaches into the decoded update only on success. The decoded value is a temporary, dropped at the end of the statement once its count has been read. Before this change every Gloas period decoded as None, so should_replace below would have frozen the first copy ever stored.

domain enums-patterns Pure rules with table tests. A wallet refuses an update signed by fewer than ⅔ of the 512-member committee (342 is the lowest acceptable count), so ingest refetches a period that isn't held, is still in progress, is stored below that bar, or can't be decoded. stored.is_none_or(below_supermajority) passes a function where a closure is expected. should_replace accepts only strictly more participants, which makes a rerun idempotent. pub(crate) exposes them to serve.rs only.

  • async iterators-closures has is a closure that returns a future. Each call creates a new, lazy future holding p and a reference to client, and nothing runs until it is awaited.
  • error-handling traits-generics Ok::<bool, anyhow::Error>(…): an async block can't declare its return type, so without the turbofish the ? inside wouldn't know which error type to convert into.
  • domain A binary search for the lowest period Nimbus still serves, which assumes the servable window has no gaps.

roost's only upstream: an async client for Nimbus's beacon REST API. REST bypasses Nimbus's libp2p peer table and connection semaphore entirely. The four light-client endpoints are fetched as SSZ (Accept: application/octet-stream), so roost stays a byte cache that relays exactly what Nimbus produced. The JSON endpoints cover head and finality, config/spec, the genesis root, peers and addresses.

  • modules-cargo error-handling A smart constructor through privacy. The fields are private, so other modules can't write ChainParams { slots_per_epoch: 0, .. }, and from_spec, which refuses missing, zero or overflowing values, is the only way in. The doc records the bug this prevents: with pub fields, a zero compiled and later divided by zero. It's the Java private-fields-plus-static-factory idiom, enforced by the compiler. Copy makes it a small value type.
  • error-handling bytes-strings checked_mul, not saturating: a saturated product would make every period number 0 and silently mis-key the irreplaceable archive. read is a closure that borrows spec and declares -> Result<u64>, so ? works inside it.
  • error-handling enums-patterns Typed errors where a caller branches. anyhow is fine for failures that are only reported. FetchError exists because serve.rs must decide: requeue a Transient bootstrap, or give up on an Unavailable one. A variant wrapping anyhow::Error keeps the message chain. impl std::error::Error for FetchError {} is empty because every method has a default, and it lets ? convert the error into anyhow.
  • domain HTTP 408 and 429 are 4xx codes but retryable. Treating them as “unavailable” would mark a wallet's pinned checkpoint as permanently refused after a single rate-limit answer.
  • async bytes-strings while let Some(chunk) = resp.chunk().await…? is the async version of an InputStream.read loop. A chunked response has no Content-Length, so the 32 MiB cap is enforced as the data arrives. &chunk deref-coerces from &Bytes to &[u8]. .map(str::to_string) uses a method path as a function.
  • async async fn get_ssz(&self, …) returns a future that borrows self, and nothing is sent until it's awaited, unlike an eager CompletableFuture. There is no retry code at all: the 12-second tick simply runs failed work again.

The in-memory serving cache that the libp2p responder reads. It holds fully encoded libp2p responses (result || digest || varint || snappy), so serving is a lookup plus a copy, and compression happens once, at ingest. It also bounds bootstrap handling: a FIFO-evicted cache, a queue of misses for the background filler, and a record of roots already attempted.

  • concurrency async Why a std lock. respond_inbound in myotis-net is synchronous and runs inline on the single swarm task. An async lock can't be awaited there, and a block_on inside a runtime worker would panic. So: std::sync::RwLock, and no method ever returns a guard, so none can be held across an .await.
  • interior-mutability error-handling Poisoning is real here. roost unwinds on panic, so a panic while the lock is held poisons it, and every later read().unwrap() would panic too. unwrap_or_else(|e| e.into_inner()) takes the guard anyway, which is justified because the entries are immutable byte blobs: “serving stale-but-valid bytes beats serving nothing”. Java has no equivalent; finally { unlock(); } just releases the lock. (The “cheap to clone” doc is stale: LcStore isn't Clone; it's shared through Arc.)
  • lifetimes RwLockReadGuard<'_, Inner>: the guard borrows self, and '_ lets the compiler infer the lifetime.

smart-pointers borrowing Temporaries die at the ;. self.read().updates.get(&period).cloned()? drops the read guard at the end of that statement, before the slow snappy decode. self.write().finality = Some(wire); is a one-statement critical section. Arc<[u8]> is an immutable, reference-counted slice in one allocation, and cloning it only bumps the count, like sharing a Java reference to an immutable byte[]. The encoding happens before the lock is taken. (The doc on lines 145–147 describes insert_update but is attached to update_ssz.)

  • concurrency borrowing Read first, then write, then re-check. This runs on the swarm task for every miss, so the common “nothing to do” case needs only a shared lock. The inner { } drops the read guard before the write lock is requested: std's RwLock can't upgrade, and asking for the write lock while holding the read lock on the same thread can deadlock or panic. The state may change in the gap, hence the second check.
  • borrowing interior-mutability A clone that satisfies the borrow checker. In clear_bootstraps, both field accesses go through the same guard (Deref/DerefMut). Iterating inner.bootstrap_order while calling inner.bootstrap_attempted.remove looks to the compiler like a shared and a mutable borrow of inner at once, so it rejects it. Cloning at most 64 roots avoids that; reborrowing let i = &mut *inner; would allow disjoint field borrows instead.

bytes-strings enums-patterns The hot path. A caller controls start and count (both u64), so everything is bounded: at most 128 updates, 8 MiB in total, nothing outside the held window, and a stop at the first gap. let (&lowest, _) = inner.updates.iter().next()?; destructures a reference in a pattern and uses ? on an Option. period.checked_add(1) avoids overflow at u64::MAX, and a partial run is a legitimate answer.

traits-generics smart-pointers Implementing another crate's trait. The orphan rule allows it because LcStore is local. The trait is Send + Sync, which holds automatically because RwLock<Inner> is. Both the inherent method and the trait method are called bootstrap; LcStore::bootstrap(self, …) picks the inherent one (which returns an Arc). A miss queues the root and answers None (ResourceUnavailable), and the wallet's retry hits.

A durable, append-only file of per-period LightClientUpdate SSZ plus fork digest. Periods below Nimbus's light-client floor can never be regenerated, so this file is irreplaceable. On load it checks the header (magic, version, chain id), verifies an FNV-1a checksum per record, repairs a torn tail by truncating it, and scans past corrupt regions to save the records after them. It stores raw SSZ, so a codec change never invalidates it.

  • ownership concurrency Ownership instead of locking. append(&mut self) requires exclusive access, so the compiler guarantees a single writer. Only serve's main task holds mut archive: no Mutex, no Arc. Dropping the Archive closes the file, like an automatic try-with-resources.
  • traits-generics path: impl AsRef<Path> accepts &Path, PathBuf or &str. The tuple return value is destructured by callers: let (mut archive, records, report) = Archive::open(…)?;.

bytes-strings error-handling bail!(…) is shorthand for return Err(anyhow!(…)). A record is RREC | kind | period (u64 LE) | digest | len (u32 LE) | ssz | fnv64, built in memory and written with a single write_all. flush runs sync_data (fdatasync) once per batch; a torn tail is recoverable by design. There is no OS file lock, so nothing stops two processes from appending to the same file.

  • enums-patterns A data-carrying enum. RecordRead::Ok { record, next } has fields; Torn and Corrupt don't. Elsewhere, if let RecordRead::Ok { .. } = … ignores the fields.
  • bytes-strings error-handling Panic-free parsing. buf.get(a..b) returns None where buf[a..b] would panic. Arithmetic overflow means corrupt; running out of bytes means torn. Both are plain values. try_into().unwrap() is used only on slices whose length was just checked. ssz is borrowed from the file buffer and copied with to_vec() only once the checksum matches.
  • domain A corrupted length field in the middle of the file looks exactly like a torn tail, so parse first checks whether an intact record follows. Without that check it would truncate, and delete, irreplaceable records.

Computes the 4-byte fork digest (“context bytes”) for any slot, and the 16-byte ENRForkID, from the chain's own /eth/v1/config/spec. A name→digest table won't do: since EIP-7892 the digest also mixes in the active blob parameters, so one fork name can have several digests. Forks are discovered from key names (X_FORK_VERSION + X_FORK_EPOCH). The arithmetic is myotis_net::status::fork_digest_bpo, the twin of Java's BeaconLightClient.computeForkDigest. Since the September tour that function lives in myotis-wire's eth2::status; myotis-net's status module is now a one-line pub use of it.

  • error-handling Two failure policies in one return type. The outer ?s are fatal (a failed fetch, unusable geometry). The inner Result<Self> is returned as a value, so the caller can fall back to the digest it observed on the wire.
  • iterators-closures ownership Result::map takes an FnOnce, which runs at most once, so the closure may move the captured blobs vector. It only borrows spec. params is used twice because ChainParams is Copy.
  • ownership traits-generics Consuming builders. fn with_blob_schedule(mut self, …) -> Self takes ownership, changes the value and returns it, with nothing copied. Java “withers” usually copy. That's what makes from_spec(..)?.with_…(..).with_…(..) chains work.
  • domain The Gnosis lesson. Gnosis's BLOB_SCHEDULE is empty, so roost stamped the bare Fulu digest, and every peer answered Goodbye(IrrelevantNetwork): the server was live, reachable and invisible. The implicit Electra entry fixed it. A wrong digest costs reachability, never correctness.

iterators-closures rfind searches from the back of a double-ended iterator, and .copied() turns Option<&Fork> into Option<Fork>. unwrap_or(self.forks[0]) evaluates its argument on every call (use unwrap_or_else for anything expensive), and the indexing can't panic, because the private constructor refuses an empty fork list.

Splits Nimbus's light_client/updates REST body (u64 LE length | digest | SSZ, repeated) into per-period chunks, trusting only the length prefix, and re-frames them as a libp2p multi-chunk response with myotis-net's own encoder (myotis_net::codec, a re-export of myotis-wire's eth2::codec). The digest is re-emitted as received, never derived. It uses the same protocol stack the wallets are tested against.

  • error-handling A typed error in an anyhow binary. Every variant carries the failing offset. impl std::error::Error lets anyhow callers use ? (split_updates(..)?). #[derive(PartialEq, Eq)] lets tests assert_eq! exact errors. This file spells out Result<_, FramingError> and never imports anyhow.
  • bytes-strings Checked conversions. usize::try_from(u64) can fail on 32-bit hosts, and checked_add guards every offset. ok_or(…) builds its error value eagerly, which is fine for a small enum with no allocation; ok_or_else would defer it. The subtractions inside can't underflow, thanks to the loop guard and the successful get just before.
  • ownership lifetimes Why copy. chunk borrows the caller's body. The digest is copied into a 4-byte stack array and the payload into a new Vec, so UpdateChunk owns its data, needs no lifetime parameter, and can outlive the HTTP buffer on its way into the archive and the store.
  • domain An empty body is Ok(vec![]), which is how Nimbus answers for a period below its window. Chunks vary by a few bytes, so a fixed stride would be wrong.

roost serve. At startup it loads the archive into the store, fills missing periods, resolves digests, starts myotis-net's libp2p host with the store plugged in as the light-client responder, and joins discv5. Then, on a 12-second tick, it refreshes live objects, fills requested bootstraps and the new period, keeps status honest, tracks its external IP, and publishes the ENR once every gate passes.

error-handling domain Strict startup. The genesis root and the chain geometry are required before the archive is opened, because every record key depends on them. for (period, rec) in &records iterates by reference: *period copies the key, and &rec.ssz borrows the bytes. Best-effort steps (the initial fill, live objects, discovery) only log.

smart-pointers traits-generics Plugging the store in. store.clone() is an Arc<LcStore> reference-count bump, and the field type Option<Arc<dyn LcResponder>> coerces it into a trait object (a pointer to the data plus a vtable), like passing an object as its interface type. The spawned swarm task and this task now share the store and the status. What comes back is an actor mailbox (net: an mpsc channel with oneshot replies), the peer id, and the swarm task's JoinHandle.

methods domain Every field, spelled out. A Rust struct literal must name every field, unless it ends with ..base to copy the rest from another value. roost writes all seven, so when myotis-net added listen_quic, cl_fork_watch and traffic, this call stopped compiling until someone decided each one. That matters here: HostConfig::default() is the wallet's shape and opens an ephemeral QUIC listener, which a server must not do, because the relay forwards no UDP port for it and the ENR does not advertise one. ..HostConfig::default() would have accepted that silently. Java has no equivalent check; a builder with a new optional setter compiles everywhere.

  • async select! in a loop. It waits for whichever future finishes first and runs only that arm; the others are dropped. Arm bodies are ordinary code in the enclosing function, not closures, so return leaves serve. interval fires its first tick immediately, and MissedTickBehavior::Skip prevents a burst of catch-up ticks after a slow one.
  • async ownership A JoinHandle polled by &mut. Passing swarm_task by value would move it into the first select!, and the next iteration wouldn't compile (“use of moved value”). Hence let mut swarm_task = swarm_task; and &mut swarm_task.
  • error-handling concurrency The real containment story. Under panic = "unwind", a panic in the swarm task arrives here as a value: Err(e) if e.is_panic(). The daemon logs it and returns Err, so the process exits non-zero and systemd (Restart=on-failure) restarts it. Without this arm, the process would keep polling Nimbus with no listener, an outage no supervisor could see. All connections still drop: requests are answered on that one task.
  • ownership concurrency archive, digests, external, published and ticks are plain locals of this future. Nothing else can reach them, so they need no locks, like state confined to a single-threaded executor. publish_refusal: Option<&'static str> stores literals, so they can be compared to log a refusal only when it changes.
Two shutdown caveats
  • tokio::signal::ctrl_c() is created afresh on each iteration, and per tokio's documentation it completes only for a Ctrl-C received after it was first polled. While a tick body is running, that future has already been dropped, so a Ctrl-C pressed during a tick can be missed; press it again. Creating it once and polling it by &mut, as with swarm_task, would fix that.
  • Only SIGINT is handled. systemctl stop sends SIGTERM, whose default action ends the process without running this path. The append-only archive with torn-tail repair tolerates that.

error-handling enums-patterns domain A wallet's first request is always for its own pinned checkpoint, which no pre-population can guess. So a miss is queued, and here, at most 4 per tick, it is fetched. match on the typed FetchError: Unavailable keeps the root marked as attempted (no refetch storms), while Transient puts it back at the front of the queue, so one hiccup can't block that checkpoint for good. store: &LcStore is borrowed straight through the Arc via deref coercion.

A persisted, strictly increasing ENR sequence number. The DHT keeps only the highest-sequence record per node, so a counter that reset on restart would make every later record, including an IP change, silently ignored. load starts at 1 if the file is missing and fails hard on a corrupt file.

  • enums-patterns error-handling Err(e) if e.kind() == NotFound => 1 is a guarded arm on an I/O error kind. return Err(e).with_context(…) adds a message to a plain io::Error. .context(…) on an Option (from checked_add) turns None into an error.
  • ownership A scoped block limits both the use std::io::Write; and the File: the file is closed at }, before the rename. with_context(|| …) builds its message only on failure.
  • domain Persist before use. Write the temp file, fsync it, rename it, then fsync the directory. A number that was handed out but not safely stored could be issued again after a crash, and the DHT would ignore every record until the count climbed past it.
