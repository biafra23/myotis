myotis-core: bytes, hashes and tries

RLP, keccak-256, secp256k1 identities, block headers, ENRs, fork ids, Merkle-Patricia proofs, blooms and the EIP-1559 base fee. These are the pure primitives under every execution-layer (EL) network message. There are no threads, no Arc and no async in this crate, and since September it also compiles without the standard library. It is the best place to get comfortable with which bytes are borrowed and which are owned, and with lifetimes that point at a caller's buffer.

The crate's promise

“Sans-I/O by rule” (lib.rs, lines 4–7): every function is a pure function over caller-supplied bytes. There are no sockets, files, clocks or entropy. That is why key generation is not here, and why k256 is built without its std feature. Decoding untrusted bytes never panics, because the workspace's release profile sets panic = "abort" and a panic would end the host process. The newer half of the promise is no_std: with the std feature off, the compiler itself refuses any use of the standard library.

What changed since September

The crate became no_std + alloc with a default std feature. rlp.rs grew allocation-free readers (View, ViewIter, ListBuf, validate, raw_list_prefix) after a 10 MiB peer frame cost 547 MB of heap (#454), plus differential tests that pin them to the decoder. header.rs decodes through a View and reads Amsterdam's two new fields. forkid.rs now computes CRC32 to step the pinned fork id across one known fork and to invert it. trie.rs can return the eth_getProof path, and uses a BTreeMap instead of a HashMap. fees.rs and tests/rlp_alloc_bound.rs are new.

Cargo.toml: one feature, three layers of library

Rust's standard library is really three crates stacked on each other. core needs nothing from the machine: slices, arrays, Option, Result, iterators, formatting traits. alloc adds what needs a heap: Vec, String, Box, BTreeMap, the format! and vec! macros. std adds what needs an operating system: files, sockets, threads, clocks, and HashMap, whose default hasher is seeded from OS randomness. A crate marked #![no_std] links only core (plus alloc if it asks), so it can run on firmware or a bare-metal target. There is no JVM equivalent: a Java library always gets the whole JDK.

A Cargo feature is a named compile-time switch, declared in [features]. Code tests it with #[cfg(feature = "std")], and the compiler removes the code that is switched off before type checking. Think of a Gradle build variant, except that it works per crate and inside the source file. myotis-core declares one feature, on by default:

  • modules-cargo A feature can switch on features of dependencies. std = ["sha3/std"] means “when my std is on, turn on sha3's std”. sha3 is declared with default-features = false so that its own default does not pull std in behind the crate's back. k256 (line 39) gets no std at all, because that chain would end in getrandom, an entropy source.
  • modules-cargo Features unify. Within one build, Cargo compiles each crate once, with the union of every feature any dependent asked for. myotis-wire depends on myotis-core with default-features = false and forwards its own std (myotis-wire/Cargo.toml, lines 19 and 29). myotis-net and myotis-evm depend with defaults, so any build that contains them gets myotis-core with std on. Features are additive switches, never exclusions.
  • modules-cargo version.workspace = true and rust-version.workspace = true (lines 3 and 5) inherit the values from the workspace's Cargo.toml, so every member reports one version and one minimum compiler.

modules-cargo A target-specific dependency: the [target.'cfg(…)'.dependencies] table applies only when compiling for a matching target. myotis-core never uses sha2 itself. The entry exists to set a feature (force-soft) on a crate that arrives transitively through k256, and only for bare-metal targets. The comment records why: sha2's SIMD code fails at codegen there. The promise is checked by the root Gradle task cargoBuildNoStd (build.gradle.kts, lines 869–892). It runs cargo build --target x86_64-unknown-none -p myotis-core -p myotis-wire --no-default-features, a target that has no std at all. A stray std:: import or a HashMap fails there and nowhere else, because every host builds the crate with std on.

A hand-written RLP codec. RLP encodes two kinds of value, byte strings and lists, each behind a one- to nine-byte header that gives its kind and length. This file now offers three ways to read the same bytes. decode builds an owned Item tree. View checks the bytes once, then reads them in place. raw_list_items and raw_list_prefix split a list into sub-slices of the input, because the wire layer must hash exactly the bytes a peer sent, never a re-encoding. All of them are strict about structure: minimal length prefixes, exact consumption, nesting depth at most 32, and no leading zeros in integers. The module docs (lines 4–10) explain why this is not alloy-rlp.

Owned tree

ownership enums-patterns Item owns its bytes. It has no lifetime parameter, so a decoded tree can outlive the network frame it came from. as_bytes(&self) -> Result<&[u8], _> lends a view into the tree: matching on self: &Item binds b: &Vec<u8>, which automatically dereferences to &[u8]. The elided lifetime ties that slice to &self, so it is valid only while the Item lives. The doc comment above the enum now warns that this is expensive for peer bytes and points to the alternatives below.

A checked, borrowed view

  • lifetimes borrowing View<'a> holds one field, raw: &'a [u8]. The 'a is a name for “however long the caller's buffer lives”. The struct is two machine words (pointer and length), owns nothing, and derives Copy, so passing it by value is free and leaves the original usable.
  • lifetimes Look at the return types. raw(&self) -> &'a [u8] and as_bytes(&self) -> Result<&'a [u8], _> name 'a explicitly. Without the annotation the result would be tied to &self, the borrow of the small View value. With it, the slice is tied to the buffer, and stays usable after the View itself has gone. Compare Item::as_bytes above, which must be tied to &self because the bytes live inside the tree.
  • error-handling View::new runs validate once. After that, the accessors trust the structure and read headers with the unchecked header helper. .get(start..).and_then(|p| p.get(..len)).unwrap_or_default() still cannot panic: if the impossible happens, it yields an empty slice (the default &[u8]).
  • traits-generics iterators-closures Implementing Iterator takes one associated type (type Item = View<'a>) and one method, next. Every adaptor (map, take, count, collect…) then comes for free, like a Kotlin Sequence. Note that Item here is the trait's associated type, not the rlp::Item enum.
  • lifetimes borrowing next(&mut self) borrows the iterator only for the call, yet it returns a View<'a> that lives longer. That is legal because the bytes do not belong to the iterator: self.list is a &'a [u8], and slicing it gives another &'a [u8]. An iterator that handed out slices of its own buffer could not do this.
  • error-handling Each ? on an Option returns None, ending the iteration. FusedIterator is a marker trait with no methods: a promise that after the first None every later call also returns None, which some adaptors use to skip a check.

ownership ListBuf (lines 198–245) is the owned counterpart. It keeps the encodings of its items back to back in one Vec<u8> plus a count, and iter() hands out a ViewIter over its own buffer. Here the lifetime is elided: iter(&self) -> ViewIter<'_> ties the views to the ListBuf. In this snapshot it has no users outside its own test.

The unchecked header reader

  • enums-patterns let Some(&first) = raw.first() else { return (0, 0); }; is a let-else: bind the pattern or run the else block, which must leave the function. It replaces a nested if let.
  • enums-patterns match first uses integer ranges. The five arms cover all 256 values of u8, and the compiler proves it, so no _ arm is needed. The same five ranges appear in decode_item and skip_item.
  • iterators-closures borrowing The closure long captures raw by shared reference. It folds the big-endian length bytes into a usize, and map_or(0, …) gives 0 when they are missing.

Where the bytes become owned

  • borrowing ownership payload is a temporary view into data. payload.to_vec() is the exact moment bytes are copied into the tree. The new position travels back in a tuple (Item, usize), like threading an int offset through Java code.
  • error-handling data.get(pos) returns Option<&u8>, and Some(&b) copies the byte out. Plain data[pos] would panic on truncated input. The depth guard exists because a stack overflow aborts the process; there is no catchable StackOverflowError.

error-handling skip_item (lines 469–505) is the same function with every Item removed: the same checks in the same order with the same error strings, returning only the end offset. validate (lines 289–303) is skip_item plus the “no trailing bytes” rule, so it accepts exactly what decode accepts while allocating nothing. The cost of that design is duplicated logic, which the differential tests below keep honest.

Zero-copy splitting, with a cap

  • lifetimes borrowing Spelled out, the signature is fn raw_list_prefix<'a>(data: &'a [u8], max: usize) -> Result<Vec<&'a [u8]>, CoreError>. Each element (&data[pos..next]) points into the caller's frame, so the caller cannot drop the frame while using the list. The eth layer does exactly that: split a response into raw headers, hash each raw slice, then copy what it keeps.
  • error-handling checked_add(…).filter(…).ok_or_else(…)? turns an overflowing or mismatched length into an Err. *data.first().ok_or_else(…)? dereferences the &u8 to copy the byte.
  • domain Why max. Every element is still walked and checked, but only the first max are kept. A Vec of slices costs 16 bytes per element, and a peer can pack millions of one-byte elements into one frame. raw_list_items(data) (line 316) is simply raw_list_prefix(data, usize::MAX). myotis-wire's gossip handlers call it with a cap (stop 5).

borrowing slice (lines 524–529) is where sub-views are cut for the decoder. Its guard Some(end) if end <= data.len() makes the indexing &data[start..end] provably in bounds.

Decodes an execution block header. The 15 mandatory fields come first, then the optional fork fields are read by what remains in the list, not by fork detection. requestsHash must be a byte string and is then discarded. Since September the decoder also reads Amsterdam's blockAccessListHash and slotNumber when they are well-formed, and tolerates anything after them. hash() always hashes the raw bytes as received; encode() re-encodes only the fields through parentBeaconBlockRoot.

  • bytes-strings Three storage choices appear in the struct: [u8; 32] for roots (inline), Vec<u8> for big scalars kept as minimal big-endian bytes (Java uses BigInteger), and Option<…> for fork-dependent fields, where Java uses a -1 sentinel.
  • macros traits-generics The struct derives Debug, Clone, PartialEq, Eq, Default (line 25). Default gives a zeroed header, and the tests use it with struct-update syntax, ..BlockHeader::default() (line 284), to fill the fields they do not name.
  • domain slot_number is the beacon slot that the EVM's SLOTNUM opcode returns. Its doc says the EVM refuses an Amsterdam block whose slot is None rather than guessing.
  • borrowing lifetimes Two doors, one implementation. decode(&[u8]) builds a View and calls decode_view. A caller that already holds a checked View, such as one header inside a peer's BlockHeaders response, calls decode_view directly and skips a second validation. rlp::View<'_> says “a view of some buffer; the name of its lifetime does not matter here”.
  • iterators-closures let mut f = top.as_list()?; is a ViewIter used as a cursor: each f.next() yields the next field, and once the list ends, the optional fields become None. f.clone().take(15).count() counts up to 15 fields on a copy of the cursor, so f itself has not moved. ViewIter derives Clone but not Copy, the usual choice for iterators, so a copy is always visible in the source.
  • ownership lifetimes The header copies every field. BlockHeader has no lifetime parameter, so it can hold only owned data. It cannot keep the &'a [u8] slices the view hands out, and the helpers copy each field into an array or a Vec. This is a choice: a BlockHeader<'a> would avoid the copies but could never outlive the frame it came from.

EIP-2124 fork ids. Every node announces a 4-byte fork hash (a CRC32 over the genesis hash and every past fork's activation) and a forkNext, and peers disconnect on a mismatch. myotis does not compute its hash from genesis. It pins one per network (mainnet, gnosis, chiado, sepolia, lines 29–46) together with the one next fork it knows. What changed since September is that the CRC32 arithmetic now lives here too, for two narrow jobs: stepping the pin across that one known fork (fork_id_at), and, for myotis-net's fork watch, recovering the activation that would turn our hash into a peer's unknown one (activation_of).

domain Sepolia's SEPOLIA_FORK_NEXT is Amsterdam at 2026-10-06 13:53:36 UTC, so a Sepolia node has announced the successor hash since then (the doc on line 45 gives it as 0x6c1d9423), while mainnet, gnosis and chiado have forkNext = 0 and keep their pins. Activation values below TIMESTAMP_THRESHOLD are block numbers and never switch here.

  • ownership Computed at compile time. A const initialiser is evaluated by the compiler, and the 256-entry table ends up as data in the binary, like a Java static final array that needs no static initialiser. Const evaluation allows while but not for, because a for loop calls Iterator::next, a trait method that cannot run at compile time. Hence the hand-counted n and k.
  • bytes-strings !crc is bitwise NOT on an integer (Java's ~). b as u32 widens a byte. activation.to_be_bytes() gives the 8 big-endian bytes EIP-2124 feeds into the CRC.
  • domain The comment on crc32_update names the point: it resumes from a previous checksum, which java.util.zip.CRC32 cannot do. So the hash after a fork follows from the hash before it plus the activation alone.
  • domain Running CRC32 backwards. One CRC step is new = T[idx] ^ (old >> 8). The top byte of old >> 8 is zero, so the top byte of new is the top byte of T[idx], and the 256 table entries all have distinct top bytes (TOP_INDEX, lines 125–135). So the target fixes each step's table index. The first loop feeds the four zero high bytes of a 32-bit activation; the second walks the target back four steps to learn the indices; the third picks each activation byte so that (a ^ byte) & 0xff lands on its index.
  • borrowing for slot in idx.iter_mut().rev() yields &mut u8 references into the array, last to first, and *slot = … writes through each one.
A placement is not proof

The module doc (lines 22–23) and the test every_hash_places_somewhere_so_a_placement_is_not_proof make the limit explicit: every 32-bit hash has exactly one activation below 232 that produces it. Inverting a peer's hash tells you where a fork would have to be, not that one exists. The test's comment adds that the fork watch votes by network and weighs dissent instead of trusting one placement.

Verifies Merkle-Patricia proofs. This is the state trust anchor for everything snap peers serve. Input: a trusted root, the un-hashed key (callers pass keccak(address) or keccak(slot)), and a peer's node list. Output: Found(value), Absent or Invalid(reason). It never panics and never returns Err. The walk is iterative, unlike the recursive Java one, so a hostile proof cannot grow the stack. New since September: verify_proof_path also returns the nodes the walk visited, root first, in the shape eth_getProof (EIP-1186) lists them. The file also decodes verified account and storage leaves; per its docs, it is “THE ONLY legitimate source of storage_root/code_hash”.

Design decision

The lookups counter guarantees termination structurally, even though a keccak cycle is cryptographically infeasible (the comment on lines 107–112 says so). When the consequence of a bug is an app abort or a hang, the code prefers guarantees it can see to arguments it has to trust.

Builds an ordered trie root bottom-up, with keys RLP(index) (not hashed). This is how a block's transactionsRoot and receiptsRoot are checked against a trusted header without trusting the peer that served the body or receipts. Children under 32 bytes are inlined; larger ones are referenced by hash. Since September it accepts any iterator of slices instead of a &[Vec<u8>].

  • traits-generics lifetimes items: impl IntoIterator<Item = &'a [u8]> accepts anything that can be iterated into byte slices, such as an array of slices or vec.iter().map(Vec::as_slice). The caller no longer has to build a Vec<Vec<u8>> first, which would copy every transaction. The named 'a lets the slices be stored in entries.
  • ownership borrowing Vec<(Vec<u8>, &[u8])> pairs a freshly owned nibble key with a borrowed item, so no transaction bytes are copied while building.

New since September. The regression test for #454: a 492 KB snappy frame decompressed to a 10 MiB list of one-byte elements, and building its tree cost 547 MB of heap in about ten million allocations (module doc, lines 1–4). The test installs a counting allocator and asserts that validate, raw_list_items on a nested list and raw_list_prefix allocate (almost) nothing on a list of just under 10 MiB. A control test first proves the counter works: an owned decode of 4,096 elements must show at least 4,096 allocations.

  • unsafe-ffi Replacing the allocator. #[global_allocator] on a static makes every heap allocation in the binary go through Counting. That is why this test lives in its own file: each file under tests/ is a separate binary, so the counting allocator does not slow the other tests. GlobalAlloc is an unsafe trait: the compiler trusts an implementation to return valid memory and cannot check it, so the implementer writes unsafe impl and a SAFETY: comment saying why the contract holds. Here every call is forwarded to System, the platform allocator. See the primer.
  • interior-mutability concurrency Per-thread counters. thread_local! gives each thread its own Cell<usize>, so tests running in parallel threads do not see each other's allocations. A Cell allows set through a shared reference without a lock, which is safe because a thread-local is never shared. The const { Cell::new(0) } initialiser avoids lazy setup, which could itself allocate inside the allocator. Java's ThreadLocal<Long> is the closest twin.
  • error-handling try_with instead of with: during thread teardown the locals may already be gone, and try_with returns an error there instead of panicking. let _ = discards it on purpose.
  • iterators-closures traits-generics counted<T>(f: impl FnOnce() -> T) runs the closure once and returns the counter differences with its result. FnOnce is the most permissive closure bound, since a closure called once may even move what it captured. ALLOCATIONS.with(Cell::get) passes the method Cell::get as the function to apply.
