myotis-net, part 5: EVM bridge, log index and transactions

The execution-layer services that sit just below the reader facade. The EVM's network bridge turns revm's synchronous state lookups into hedged, proof-checked snap requests. The eth_getLogs index, the new address-activity follower and the new fee memo are pure state machines that the reader feeds with verified data. The transaction modules decode, gate and track what the wallet sends. Almost every file here is pure and clock-injected; the one that is not, evm.rs, is where synchronous and asynchronous Rust meet.

enums-patterns error-handling Match guards, in order. joined is owned, so Err(EvmError::Reverted { data }) moves the revert payload out of the error into the new variant: no copy. The next three arms bind the whole error as e and test it with if guards; arms are tried top to bottom, so the order is the policy. A refusal (a call this build can never answer) becomes Refused, which the host serves as the permanent -32602; an infeasible call (out of gas, fee cap, funds, #509) is an answer served as geth serves it; everything else is the retryable Unavailable. This is the CLAUDE.md rule “applied or refused, never silently ignored” in type form. The four sibling types repeat the same match.

The bridge

The sync→async bridge, step by step
  • The async reader builds the oracle in snap_oracle (reader.rs): a snapshot of pool.snap_peers(), Handle::current() (a cloneable handle to the engine's runtime), the quality sink and the read stats. PoolOracle::new also calls Operation::current(). That task-local is visible only while the request's future is being polled, and task-locals do not reach spawn_blocking threads, so it is captured here, eagerly.
  • The reader runs revm through request::blocking(move || …) (Stop 12), on a thread from tokio's blocking pool.
  • revm calls fetch_account, fetch_storage and the rest synchronously. Each one ends in wait.
  • wait calls self.handle.block_on(…). The blocking thread polls that future itself and parks between polls; the sockets and timers it waits on are driven by the runtime's drivers and the peer connection tasks on the worker threads.
  • Why not on a runtime worker? Handle::block_on panics when it is called from inside an async execution context. Even if it did not, a worker parked in it would stall every task queued on that worker.
  • async traits-generics future: impl std::future::Future<Output = T> is argument-position impl Trait: an anonymous generic parameter, so each call site gets its own monomorphized wait. The async block captures future and self by reference or move as needed.
  • async lifetimes block_on needs neither Send nor 'static. Its signature is just fn block_on<F: Future>(&self, future: F) -> F::Output, and it returns only when the future is done. So the futures handed to wait may borrow self and locals of the calling function. tokio::spawn would demand 'static, because a spawned task may outlive its spawner.
  • error-handling op.wait(future) (request.rs) re-checks the request's deadline and cancel flags every 10 ms while it polls future, and returns Err(String) when they fire. map_err(|reason| OracleError::Cancelled { reason }) turns that into the oracle's error type, which revm propagates like any other state error.
  • borrowing interior-mutability Memo first, no lock across I/O. In if let Some(cached) = self.leaf_memo.lock().unwrap().get(&address), the temporary MutexGuard lives until the end of the if let, and cached borrows through it. cached.clone() copies the value out before the guard drops. The network fetch below runs with no lock held; a second fetch of the same address in the same call is possible, and harmless.
  • borrowing async let peers = &peers; shadows the owned Vec with a reference. The async block given to wait is not move, so it borrows peers, asked, quality, state_root and self. That is legal because of the block_on property above.
  • ownership async smart-pointers The closure |peer: Arc<ManagedPeer>| async move { … } is the race's per-attempt factory. hedged_race (reader.rs, Stop 14) starts the first peer and adds another every HEDGE_DELAY (3 s) without an answer, up to three in flight; the first answer the accept closure approves wins. Each attempt gets its own Arc clone, and async move moves it, the &[u8; 32] reference and a copy of address into the future.
  • enums-patterns out.accepted.map(|(_, outcome)| match outcome { … }) yields an Option<Option<AccountLeaf>>: the outer None means no peer proved anything (StateUnavailable), Some(None) means the account is proven absent. The memo stores the inner Option, so a proven absence is cached too.
  • methods Self::record_race(&quality, peers, &out, self.finalized) is an associated function with no self parameter. It takes exactly the parts it needs, so it can be called while other parts of self are borrowed. It feeds the pool's reputation sink: the winner served, each miss failed (witnessed when someone else served), each loser the winner outpaced. On a finalized-root call, a miss caused by the peer not holding that old root is excused.

concurrency domain A per-call ask order. order, lost and silence_reported are Mutex<Vec<…>> fields indexed by peer id. After each race, learn_order moves the winner to the front and the losers to the back (next_order), so a dead first peer costs one hedge delay per call instead of one per state read. The helpers are pure functions over slices, which is why they can be unit-tested without peers. Two small idioms: first_time uses !std::mem::replace(flag, true), a non-atomic “get and set”, and demoted uses Iterator::partition to split &usize items into two Vec<usize>s (a Vec<T> of a Copy type can be extended from &T items).

Timing the waits

lifetimes ownership An RAII guard that borrows. WireTimer<'a> holds &'a AtomicU64, a reference into the oracle's WireCounters, so the compiler guarantees the timer cannot outlive the counter it adds to. impl Drop for WireTimer<'_> uses the anonymous lifetime because the impl does not need to name it. Each fetch starts with let _timer = self.wire.serial();: the name _timer keeps the guard alive to the end of the function, and its drop adds the elapsed time however the function leaves, including an early ? return. Relaxed ordering is enough for counters that nothing else synchronizes on. u64::try_from(…).unwrap_or(u64::MAX) saturates a u128 nanosecond count instead of panicking.

The prefetch wave

domain The executor's convergence loop runs discovery passes: an EVM run that collects the accounts, slots and code it reached, then one prefetch wave that fetches them all at once (prefetch_batch), so the real runs mostly hit the caches. The account items are cut into chunks of 64; each chunk is pinned to one peer per attempt, with up to three attempts across peers; every wire request needs one of 48 semaphore permits; and the whole wave is bounded at 30 s. Failures are silent per item, because the serial per-item path re-fetches whatever is missing. A chunk's first ask goes to a peer that has not lost a race or gone silent in this call (wave_ladder, wave_peer). keep_discovering bounds how long the loop may keep starting such passes (15 s, DISCOVERY_TIME_BUDGET).

  • async Polling one future across loop iterations. tokio::pin!(request) pins the request future on the stack. A future that has been polled may hold pointers into itself and must not move again; pinning makes &mut request pollable, repeatedly, without moving it. Each select! races the request against a sleep. When the sleep wins, the request is not dropped (it lives outside the loop); the loop just re-evaluates the silence.
  • domain concurrency Silence, not age. sent is an Arc<OnceLock<Instant>> that the peer code fills when the request frame is actually written (scope_send_marker, a task-local scope in peer.rs). The clock starts at the later of that send and the peer's last delivered response. Only after WAVE_SILENCE_DEADLINE (6 s) of complete silence does the function return Err(Silent { … }), dropping the request. A request that has not gone out yet is never cut, because dropping it inside the shared writer would tear the connection for every request on it.
  • traits-generics iterators-closures The two impl Fn parameters are callbacks that the wave fills with || peer.last_response() and |since| self.link_heard_after(&peer, since). link_proven records whether some other peer of the call delivered during this silence, which is the evidence that the silence was the peer's and not our own link.
  • async smart-pointers The per-future clone pattern: each async move future gets its own Arc clones (peer, sem), its own clone of leaf and its own position array. join_all polls them all on the one blocking thread that called block_on, like CompletableFuture.allOf without a thread pool.
  • lifetimes async These futures still borrow state_root, self and the cache sinks from the enclosing frame (the move copies the references in). That is fine because they are never spawned, only driven to completion before prefetch_batch returns.
  • ownership concurrency let Ok(_permit) = sem.acquire().await else { … }; keeps the permit until the end of the block, after the request. Binding it to _ instead would drop it at once, and the 48-request limit would do nothing. A closed semaphore fails the item; it never bypasses the bound.

async Two nested cancellation layers: a 30 s timeout on the warm-up wave, inside wait's request-level deadline. Both results are ignored on purpose (let _ =), because warm-up is best-effort and whatever landed in the caches stays there. When the timeout fires, the wave future is dropped, and with it every chunk future and every in-flight request; the peer's pending-request guard discards late answers.

The pure state behind the opt-in, scoped eth_getLogs. It holds a host-supplied watch list, per-entry contiguous coverage, a BTreeMap log store keyed by (block, log_index), and the backfill walk's trust cursor. Since September a watch entry can be an address (every log the contract emits) or a topic value (#673: every log, from any emitter, that carries the value at one of the entry's topic positions, 1 to 3; that is how a token transfer names a wallet). The file also provides filter matching, an explicit unwatch, an atomically written, versioned binary snapshot (MLIX v2, or v3 when a topic entry exists) with portable import, export and merge, and a finality-claim sidecar. It does no networking and no verification: callers feed only logs that passed the header and receiptsRoot checks. The appender, the walker and the checkpoints live in reader.rs.

enums-patterns borrowing One rule for indexing, scanning and merging. match self.key reads a field through &self, and the arms bind a and v by value. Moving out of a borrowed place is normally forbidden, but WatchKey's arrays are Copy, so the bytes are simply copied. topics.get(p as usize) == Some(&v) compares two Option<&[u8; 32]>s without indexing (no panic past the log's last topic). An empty topic0s means “any event”.

  • error-handling domain All-or-nothing. The first loop only checks: a gap against any affected entry returns Err before anything changed. Only then are logs stored and spans extended. That is why the second extend_up can ignore its result with let _ =. An empty logs vector still advances coverage, which is what makes an empty answer honest.
  • ownership for log in logs consumes the Vec by value, so each StoredLog (with its topics and data) is moved into the map, never copied. A mislabeled log is dropped, not stored under its own number.
  • borrowing Disjoint field borrows: line 736 zips self.config.watch.iter() (shared) with self.coverage.iter_mut() (mutable) at the same time. The borrow checker allows it because they are different fields of self.
  • domain error-handling Coverage honesty in code. A range that is not fully indexed is Err(OutOfCoverage { key, covered }), never []. A wallet would read [] as “no events” and silently corrupt event-sourced state such as a commitment tree. It is the same principle as the #314 state-override fix: a parameter is applied or refused.
  • domain Two ways to answer: a topic entry whose value the filter pins at one of its positions answers the whole filter, whatever addresses the filter lists; otherwise every address the filter names must be an address entry that covers the range. Either way scan returns every stored log the filter matches, whichever entry stored it.
  • enums-patterns let WatchKey::Topic(v) = w.key else { continue; }; is let-else with an enum pattern: skip address entries in this loop. Some(t @ QueryError::OutOfCoverage { .. }) => t binds the whole matched value to t while testing its shape.
  • iterators-closures borrowing address_refusal is a closure that borrows topic_refusal and clones it when called. .map_err(address_refusal)? passes the closure itself where a function is expected. The rule it encodes: a topic entry's “not covered yet” beats an address refusal, because the caller can wait it out.

iterators-closures ownership Only the part of the range at or after the entry's from_block must be covered; below it the config itself asserts there are no logs (a deployment block, a wallet's creation block). self.logs.range((from, 0)..=(to, u32::MAX)): tuple keys compare lexicographically, so this is a TreeMap.subMap scan with an inclusive per-block upper bound. .cloned() returns owned logs. A Vec<&StoredLog> would keep the index borrowed, and in the reader locked, for as long as the caller holds the answer.

Unwatch

  • ownership Rebuilding two parallel vectors in place. You cannot move a Vec out of a field you only reach through &mut self. std::mem::take swaps an empty Vec in and hands back the full one. The loop then moves each WatchEntry either into dropped or back into self.config.watch, keeping coverage parallel. Nothing is cloned.
  • borrowing let (watch, coverage) = (&self.config.watch, &self.coverage); takes shared borrows of two fields, and self.logs.retain(…) then borrows a third field mutably. Disjoint fields, so this compiles. (In edition 2021 a closure that wrote self.config.watch would also capture just that field; the local names make the split visible.)
  • domain A log stays when no dropped entry selected it, or when a surviving entry both selects it and covers its block. A transfer from a watched wallet on a watched token belongs to both entries and outlives either one's unwatch. The fingerprint changes with the entries, which makes any backfill batch computed against the old list discard itself.

The snapshot file

error-handling concurrency let write = || -> std::io::Result<()> { … }; is a closure with its own return type, so ? works inside it, and one cleanup path covers all three failure points. The temp file is removed on any failure: the likely trigger is a full disk, and a leftover temp at snapshot size keeps it full. The temp name comes from next_tmp_path, which appends the pid and a static SEQ: AtomicU64 counter. A static inside a function is still one process-wide value. Per-call names became necessary once the fsync moved out from under the index lock: two writers in one process would otherwise share a temp file, and one could truncate the other's or write into the renamed live file.

Merge

ownership for s in &mut sources holds each source by &mut, and std::mem::take(&mut s.logs) moves its whole map out, leaving an empty one. Iterating taken by value then moves each log into the output, so a store that may be gigabytes is never cloned. Self { coverage, logs, cursor, ..ix } is struct-update syntax: it moves the remaining field, config, out of ix, which is allowed because LogIndex has no Drop impl. The merged index is canonical (every span ends at one global high, the cursor at the deepest resumable edge), because that is the only shape the appender and walker can resume from.

Deeper: finality claims and resumable walks

A checkpoint is clamped at finality: coverage above it is only verifiable against an in-memory tail record that does not survive a restart, so serialize_clamped leaves it out of the file. But a restart restores the beacon store from a snapshot that may be hours old, so the first finality after a start can trail the checkpoint, and the file alone cannot say its top was final. The sidecar <index>.final records, for one exact file (SnapshotId: chain tag, fingerprint, payload checksum), the finality its writer clamped it at. It never travels with an exported file.

walk_resumable states when the single descending walk can still finish every entry from a cursor: each present span is complete or has its low at or below the cursor, and each absent span belongs to an entry starting above the global high. When that fails, adopt_config, unwatch and merge drop the cursor and the appender re-seeds it at the top. The doc records that getting this backwards once wedged the walker.

New since September (#691). A host watches up to 256 addresses; the follower in reader.rs (ensure_activity_follower) keeps the last 256 verified headers as one contiguous, parent-linked run ending at the anchored head. This module is that state and the report built from it, with no I/O. It reports two kinds of coverage. Log: each header's logsBloom is probed for the address as a log's emitter and as an indexed topic; a miss is definitive, a hit means “maybe”. Account: the block's access list (BAL, EIP-7928), fetched over eth/71 or snap/2 and verified against the header's blockAccessListHash, lists every account the block changed with its post-block values. A host then re-proves an address's state only when a block touched it. On top of that, an account proven once at block N is followed: each verified BAL carries its values forward, so a read near the head can be answered without a new proof.

New since September (#510, #532). A per-head memo for the verified fee reads, eth_gasPrice / eth_maxPriorityFeePerGas (FeeEstimate) and eth_feeHistory (FeeHistory), so a wallet's fee poll is answered from memory instead of re-downloading and re-verifying blocks on the request path. The soundness argument is short: every cached value is a pure function of the anchored window top (number, hash) it was computed against, plus the request shape. While that top is unchanged the value is Fresh. After the head moves it is Stale for at most 5 blocks and 75 s while the reader's follower task refreshes it; the base fee moves at most 12.5% per block, so a few-blocks-old fee is a better answer than a timeout. A reorg (same number, other hash) or a head that moved backwards is a Miss, never stale. The module is pure state; the reader holds it in a std::sync::Mutex<FeeCache> and owns the computes and the follower.

  • traits-generics Slot<T> is generic over the cached value. Its Default is written by hand (lines 94–98) instead of derived, because #[derive(Default)] on a generic struct adds a T: Default bound that FeeEstimate need not meet. The lookup methods sit in impl<T: Clone> Slot<T>: the bound applies only where a value is cloned out.
  • enums-patterns borrowing let Some((at_head, value, at)) = &self.cached else destructures a tuple behind a reference, so all three names are borrows; *at_head == head dereferences to compare. Lookup<T> is the generic result: Fresh(T), Stale(T, Staleness) or Miss.
  • iterators-closures head.0.checked_sub(at_head.0).filter(|&b| b > 0) is “strictly older” as an Option chain: None when the head went backwards (underflow) or did not move. |&b| destructures the &u64 that filter passes.
  • domain store drops a late compute for a top that is no longer current when the cached value is for a higher block or for the current top. A head that really moved backwards (a re-anchor, a reorg to a shorter chain) is current, so its value is stored.
  • borrowing Clone the key so the borrow ends. self.histories.iter().min_by_key(…) yields references into the map. .map(|(k, _)| k.clone()) turns the victim's key into an owned value, which ends the shared borrow, so self.histories.remove(&victim) can borrow the map mutably on the next line.

Pure decoders over raw, consensus-encoded transactions. effective_tip reads just the fee fields, for gas-price suggestions. decode_summary returns every transaction field a receipt or eth_getTransactionByHash needs, including sender recovery: it rebuilds the signing preimage from the raw item bytes, for typed transactions and for legacy and EIP-155. New since September (#531). The pure half of the pre-broadcast check of eth_sendRawTransaction. A transaction its sender cannot pay for, or whose nonce is already used, is never mined, and the eth protocol sends no word back when a peer drops it. geth, Nethermind, Besu and Reth refuse such a transaction before answering, and wallets classify errors by geth's message text, so this module reproduces geth's two txpool verdicts in geth's order and words. The reader (judge_read, Stop 14) supplies the sender's verified account, and judges only when the account was proven against the head's own state root. The check fails open: anything that stops it from judging (an undecodable or blob transaction, a stale head, a slow read, Tor-routed reads, too many reads in flight) broadcasts the transaction as before, because a node that lags the chain must never block a send.

  • domain Two clocks. A head is fresh only if its proven timestamp is within two block times plus 6 s of the wall clock and this node saw it advance within that bound on its own monotonic clock (adopted_ago). A wall clock set wrong cannot fake the second test: a stalled light client's head ages there whatever the wall clock says. A head never seen to advance (None, such as one restored from a snapshot) is not fresh.
  • error-handling In max_cost, tx.gas_price? inside a match arm returns None from the whole function when the field is missing; _ => return None does the same for a blob transaction, whose blob fee the summary does not carry. In verdict, max_cost(tx)? then means “cost unknown: judge the nonce only”.
  • iterators-closures (balance < cost).then(|| format!(…)) turns a bool into an Option, building the message only when it is needed. cost - balance cannot underflow inside that closure, since it runs only when balance < cost.
  • domain A nonce above the account's is not an error: geth queues it, and wallets send several transactions in a row. Each transaction is judged alone against the balance, because this node does not see what geth's pool already holds for the sender.

Two small, pure, clock-injected state machines for the wallet's own broadcasts. SentTxTracker watches each broadcast (180 s TTL) until it is seen in gossip, confirmed mined, or expired; the reader uses it for rebroadcasts and to bound receipt scans, and since #531 logs a watch that expires unseen as “likely dropped”. A re-send of a transaction the network already echoed stays seen. PendingNonceTracker makes eth_getTransactionCount("pending") return max(verified mined count, own highest nonce + 1) for up to 90 s. Neither is proof-backed, and neither needs to be: one only gates a rebroadcast of self-signed bytes, and the other only raises a pending answer above the verified floor. Neither is ever consulted for settled tags. The file also has the 0x… hash formatting for the send log lines.

interior-mutability ownership The trackers contain no locks; their mutating methods take &mut self, and the caller decides how to share them. The watch is SharedSentTxWatch, an Arc<std::sync::Mutex<SentTxTracker>> held by the reader and by every peer's read loop (gossip sightings); the guard provides &mut through DerefMut. The nonce tracker lives inside the reader's SentTxState, behind sent_txs: std::sync::Mutex<SentTxState>. A std mutex fits because every access is “a brief map poke, never held across I/O”.

iterators-closures borrowing retain takes an FnMut closure. This one mutably borrows the local unseen vector while retain mutably borrows self.watched; they are different objects, so both borrows can coexist. *hash copies the 32-byte key out of the map entry. The boundary is inclusive (<=), mirroring the Java > test for expiry.

  • borrowing Non-lexical lifetimes across match arms. In record, the get_mut borrow is live only in the arms that bind e. In the None arm nothing borrowed survives, so insert on the same map is allowed. In overlay, e is a shared borrow, yet remove compiles: on the path through the if, e is never used again. On the other path e is used at the last line, and no remove happens there. The borrow checker reasons per control-flow path.
  • enums-patterns Some(e) if nonce >= e.nonce followed by Some(_) => {}: a guarded arm and its fallback, the Java merge with >=.
  • error-handling saturating_add(1): a nonce of u64::MAX must not wrap (release) or panic (debug).
