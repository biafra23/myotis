myotis-bls: BLS through blst

The smallest real crate, and a good warm-up. It verifies a sync-committee aggregate signature with Supranational's blst. The Java engine calls it through JNI, and myotis-consensus calls it as a plain Rust function. You will see slices, a Vec of references that borrows another Vec, a JNI export that needs no unsafe, and, new since September, the two lines that let the crate build without the standard library.

Rust you will practise

Slices and chunks&[u8] parameters, chunks_exact, and a Vec<&T> that borrows another Vec.
Features and FFI#[cfg(feature = "jni")], #![cfg_attr(not(feature = "std"), no_std)], #[no_mangle], extern "system" and lifetimes on JNI handles.
Never-panic styleEarly return false, and Option with .ok()? instead of exceptions.

Some domain first. An Ethereum sync committee is 512 validators chosen for about 27 hours. Every slot, the members that saw the block sign its root, and their signatures are combined into one BLS aggregate signature. A light client checks that single signature against the participating members' public keys. That one check, fast_aggregate_verify, is all this crate does. BLS keys and signatures are points on the BLS12-381 curve, sent in compressed form: 48 bytes for a public key, 96 for a signature. The DST (domain separation tag) is a fixed byte string mixed into the hash-to-curve step, so a signature made for one scheme cannot be replayed under another. Ethereum uses the "proof of possession" (POP) variant.

Two public functions and a feature-gated JNI module. fast_aggregate_verify is the production entry: the POP ciphersuite, with the committee flattened into one 48 × n byte buffer. It forwards to fast_aggregate_verify_with_dst, which exists so the conformance tests can use the NUL ciphersuite the fixtures were generated with. Any malformed input gives false, never a panic.

Building without std

  • modules-cargo macros A crate-level conditional attribute. #![...] with a ! applies to the enclosing item, here the whole crate. cfg_attr(condition, attr) adds attr only when the condition holds. So the crate is #![no_std] exactly when the std feature is off, which happens only when a dependent turns the defaults off and does not ask for std (Stop 2 shows how myotis-consensus forwards it). jni implies std in the manifest, so the JNI build always has the standard library.
  • modules-cargo alloc::vec::Vec. extern crate alloc; makes the allocation layer of the standard library available by name. std::vec::Vec is only a re-export of alloc::vec::Vec, so importing it from alloc gives the same type in both builds, and the function bodies do not change.

The verify core

  • borrowing Read-only parameters. All four byte parameters are &[u8]: the function only reads. The caller keeps ownership, and nothing is copied at the call. A &[u8] is a pointer plus a length, a view into someone else's bytes, a bit like a read-only ByteBuffer slice.
  • ownership borrowing A vector of references into another vector. pks owns the decoded keys. pk_refs: Vec<&PublicKey> is a second vector of references into pks, because blst's API wants a slice of references. The compiler guarantees that pks outlives pk_refs and is not changed while pk_refs is in use. Drop or push to pks before the last use of pk_refs and it will not compile. Both vectors are dropped at the end of the function; no key is ever copied.
  • iterators-closures chunks_exact(48) yields 48-byte sub-slices without copying. The length check just above guarantees there is no remainder. pks.iter().collect() builds the reference vector, and the target type comes from the annotation on the left.
  • error-handling Manual early return. match … { Ok(pk) => …, Err(_) => return false } is the manual version of ?. It is needed because the function returns bool, not Result, so ? has nothing to convert the error into.
  • domain Two trust levels. PublicKey::uncompress skips the subgroup check, which is expensive and repeated 512 times, because the keys arrive Merkle-proven against a header the client already trusts. The signature comes from a peer, so the final call passes true for sig_groupcheck. The crate docs (lines 11–13) say the Java path makes the same trade-off.
Design decision

The count is capped before n * PK_LEN is computed. On a 32-bit Android device usize is 32 bits, so a huge count could wrap around the length check and trigger a gigantic with_capacity. Under the workspace's panic = "abort" that would end the host app, not throw an exception it could catch.

The JNI export

  • modules-cargo A feature-gated module. #[cfg(feature = "jni")] removes the whole module when the feature is off, which is how myotis-consensus gets a JNI-free build. The use jni::… lines inside the module disappear with it, so the optional jni crate is never referenced.
  • unsafe-ffi An exported symbol. #[no_mangle] keeps the symbol name exactly as the JVM expects (Java_<package>_<Class>_<method>), and extern "system" selects JNI's calling convention. There is no unsafe block: the jni crate wraps the raw pointers in typed handles.
  • lifetimes 'local. It ties every handle (JByteArray<'local>) to this call's JNI local-reference frame. Storing one in a global for later would not compile, which rules out a whole class of JNI crash bugs at compile time. In verify the lifetimes are elided: the compiler fills them in, and they still cannot escape.
  • borrowing &mut env. The export lends its JNIEnv to verify as &mut for the duration of the call; the borrow ends when verify returns. In jni 0.21 the methods that create new local references take &mut self, but convert_byte_array takes only &self, and a &mut reference can always be used where a shared one is wanted.
  • error-handling .ok()?. env.convert_byte_array(&pubkeys) copies a Java byte[] into a Rust Vec<u8> and returns a Result. .ok() turns it into an Option, and ? returns None early on failure. Some(true) => JNI_TRUE, _ => JNI_FALSE maps None and Some(false) alike to false.
  • bytes-strings A signed count. Java has no unsigned int, so the count arrives as jint (i32). count.max(0) as usize clamps a negative value to 0 before the cast; a plain as usize on -1 would produce a huge number. The cap is checked here too, so an absurd count is refused before three array copies.
JVM lens

On the Java side this is a static native boolean nativeFastAggregateVerify(byte[] pubkeys, int n, byte[] msg, byte[] sig) in NativeBlsBackend, loaded with System.loadLibrary("myotis_bls"). Passing the whole committee as one flat array means a single boundary crossing per verification.

Replays the same fixture files the Java tests use (consensus/src/test/resources/bls_fixtures.txt and a captured real mainnet failure), embedded at compile time. It covers NUL-ciphersuite aggregate and single-signer vectors, and a real 511-of-512 signature that must be rejected on the POP path. It also checks that each aggregate vector fails under POP, which proves the DST parameter is really used, that a corrupted signature fails, and that infinity encodings are rejected. Vectors that would only test blst against itself are skipped on purpose.

  • bytes-strings lifetimes include_str! pastes the file into the binary as a &'static str, so the test never depends on the working directory. The path is relative to the source file, and it reaches into the Java module's test resources.
  • borrowing iterators-closures A map of views. parse_kv returns HashMap<&str, &str>: every key and value is a view into text, and no characters are copied. trim and split_once return sub-slices of their input. Lifetime elision ties the map's lifetime to text, which is fine here because the input is 'static.
  • testing An integration test. The file lives in tests/, so cargo compiles it as a separate crate. It can only call the crate's public API (fast_aggregate_verify, fast_aggregate_verify_with_dst, the constants). It is built with the default features, so the library it links has std and jni on.
