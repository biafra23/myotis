myotis-node: the Node.js addon

A napi-rs addon for Electron and Node hosts, built as myotis-node.node. It calls the engine's C functions (Stop 16) by Rust path. Lifecycle and status calls are synchronous; verified reads return Promises that the addon's own worker threads settle, never libuv's. Since September the addon has grown from 20 to 42 JavaScript functions: it now exports every read a dApp provider needs (#503), and because no JSON-RPC router stands in front of it, it makes the routers' argument checks itself. The heart of the crate is still scheduler.rs, a small hand-written thread pool: Java's synchronized/wait/notifyAll, rewritten with Rust's guarantees, plus raw pointers handed back and forth with Node.

What changed since September

scheduler.rs and admission.rs are byte-for-byte unchanged. lib.rs grew from 340 to 1,078 lines: 22 new exports (blocks, receipts, transactions, fee history, code, storage, eth_getProof, logs, the log index, the transaction-object calls, block-hash resolution, network metering, the pending-nonce overlay) and a block of small pure validators with nine unit tests. Cargo.toml gained one dependency, serde_json, used only by those validators.

A Cargo build script: Cargo compiles and runs build.rs before building the crate, and the cargo: lines it prints configure the build, much like a small Gradle task. napi_build::setup() adds the platform linker flags a Node addon needs. On macOS, for example, it lets the library find Node-API symbols in the host process at load time.

modules-cargo crate-type = ["cdylib"] produces a C-compatible shared library, which you rename to .node (the README's build steps do exactly that). [build-dependencies] are available only to build.rs. default-features = false, features = ["napi8"] picks exactly the Node-API level the addon uses. serde_json is new: the addon now parses two JSON arguments itself (reward percentiles and import paths) before it hands them to the engine.

Forty-two JavaScript functions: catalog, lifecycle, weak-subjectivity and EL-seed controls, 25 calls that return Promises (the verified reads and the log-index administration), and one synchronous nonce lookup. Engine failures stay in-band ({"error"}, negative handles, false), exactly as on the JVM and iOS routes; only Node-API and scheduler failures throw. Each handle belongs to the Node environment that created it. New since September: the binding refuses malformed arguments itself, as permanent {"error", "code": -32602} objects, because on the other hosts a JSON-RPC router makes those checks before the engine is called, and here nothing does.

Stale or inaccurate comments

Lines 68–70 are c_arg's doc comment ("A JS string crossing into C…"), but the constant NUL_INVALID_PARAMS was later inserted between that comment and the function. A /// comment documents the next item, so rustdoc now shows both paragraphs on the constant, and c_arg has no documentation at all.

  • lifetimes unsafe-ffi Keep the CString alive. n.as_ptr() only borrows the buffer, and the compiler doesn't connect that raw pointer to n's lifetime. Binding the CStrings to n and d keeps them alive past the C call. By contrast, let p = CString::new(s).unwrap().as_ptr(); frees the temporary at the end of that statement, so p dangles by the next line (rustc even has a lint for this).
  • error-handling Two ways to fail. A scheduler (infrastructure) failure propagates with ? and becomes a JS exception; an engine refusal is an ordinary value such as Ok(-1). The environment is set up before the handle exists, so a failed setup never leaves an orphaned handle.
  • macros #[napi] generates the JS binding and a TypeScript declaration under a camelCase name (statusJson, createWithCheckpoint). napi-rs supplies the env: &Env argument, and returning Err throws.

bytes-strings A JS number is an f64. Before as u64, the code checks that it is finite, a whole number, and between 1 and 2⁵³−1 (Number.MAX_SAFE_INTEGER), because as casts from float saturate silently. let (Ok(n), Ok(d), Ok(r)) = (…) else uses a tuple pattern: all three conversions must succeed, or the else block (which must leave the function) runs.

concurrency ownership pause and stop first cancel the handle's requests and wait for its running job (cancel_handle), then call the engine, then call cancellation.finish(env). Cancelled jobs normally settle their Promises through the thread-safe function like any other result. finish handles the rare case where that hand-off failed: it poisons the scheduler and settles those Promises directly. Cancellation is marked #[must_use], so the compiler warns if a caller ignores it, and finish(self, …) takes it by value, so it can be finished only once. cancellation.owned && unsafe { … } short-circuits, so the engine is never called for a handle this environment doesn't own. resume cancels nothing; it only asks the engine for a warm restart. Lifecycle calls are otherwise serialised simply by being made on the environment's single JS thread.

A read, and where its arguments are checked

  • ownership iterators-closures concurrency A closure that travels. Nothing here blocks: the function packages the work and returns a Promise immediately. The move closure takes ownership of address and block (and copies handle, an i64, which is Copy), because submit requires FnOnce() -> String + Send + 'static: it will run later, on another thread. block.unwrap_or_default() runs first, on the JS thread, turning Option<String> (an optional JS argument) into a plain String (empty when omitted).
  • error-handling domain The checks run inside the closure, on a worker. So an unknown handle is answered first (submit refuses it with "handle does not belong to this environment"), and a malformed address still takes an admission slot and waits behind a running job on the same handle before it is refused. The refusal is the project's permanent -32602: the address is applied or refused, never read loosely.
  • lifetimes Object<'env>: the returned JS handle can't outlive the &'env Env borrow, a lifetime that mirrors Node's own handle-scope rules. ts_return_type sets the TypeScript type by hand, because the Rust type is an untyped object.

The validators

The comment at lines 554–567 states the rule: each check is "the engine's own parse or a router's rule, so what this binding refuses, the other hosts refuse too". The helpers are small pure functions, which is why they could be unit-tested without Node.

  • bytes-strings error-handling invalid_params escapes its message by building a serde_json::Value from the &str and formatting it, so a quote in the reason can't break the JSON. In format!, {{ and }} are literal braces.
  • domain Why bare digits are refused. The engine reads a block-number selector as hex, so "23500000" from a JS caller who meant decimal would name a block far past the head, or a smaller number would silently name the wrong block. A refusal is the only safe answer.
  • bytes-strings iterators-closures strip_prefix("0x").or_else(|| s.strip_prefix("0X")).unwrap_or(s) borrows: every step returns a &str slice of the caller's string, and nothing is copied. .bytes().all(|b| b.is_ascii_hexdigit()) checks bytes, not chars, which is enough for ASCII hex and avoids UTF-8 decoding. hex_bytes also caps the input at 1 MiB, as the engine's parser does.
  • error-handling iterators-closures Result<String, String>: Ok is what to hand the engine, Err is the finished refusal JSON. not_an_array is a closure stored in a variable, so it can be reused: map_err(|_| not_an_array()) calls it, and ok_or_else(not_an_array) passes the closure itself, which is called only on None.
  • bytes-strings Re-serialised on purpose. parsed.to_string() hands the engine the numbers as serde writes them, so a list of very long numerals can't exceed the engine's 4 KiB bound (the test at lines 1029–1032 pins exactly that). (0.0..=100.0).contains(&d) is an inclusive range used as a predicate.

Nested patterns

enums-patterns error-handling reward_percentiles(…).map(|p| c_arg(&p)) has the type Result<Result<CString, String>, String>: the outer error is a refusal, the inner one a NUL byte. One match takes it apart: Ok(Ok(p)) binds the CString, Ok(Err(_)) is the NUL case, and Err(refusal) => return refusal returns the finished JSON. The CString p lives until the closure ends, so the pointer passed to the engine stays valid. block_count as i64 is safe only because safe_integer ran first.

enums-patterns borrowing let Some(Ok(p)) = storage_word(&position).map(|w| c_arg(&w)) else { … }: an Option<Result<CString, String>> must be Some and Ok. The padded word w is a temporary String that lives only inside the closure; c_arg copies it into the CString, which is what survives. In the first tuple, Ok(_) checks the raw position for a NUL byte without binding it, so that CString is dropped at the end of the statement.

testing #[cfg(test)] mod tests is compiled only by cargo test, and use super::* brings the parent module's private functions into scope: privacy in Rust is per module, and a child module may see its parent's items. expect_err(bad) panics with bad as the message if the result is Ok, so a failing case names itself. .as_deref() turns Result<String, String> into Result<&str, &String>, which can be compared with Ok("").

The log-index functions (lines 891–948) also run on the workers, because installing a config or importing a snapshot takes the index's write lock, which can be held for a while. The comment at lines 897–901 is candid about the cost: an import is neither bounded by the 90 s budget nor cancellable, so it occupies its handle's one execution slot, that handle's reads queue behind it, and stop/pause wait for it.

A generic job queue with one rule: at most one running job per handle. A queued job may overtake an older one whose handle is busy, so a slow chain doesn't block the others. The queue has no lock of its own; the scheduler's Mutex protects it. Cancelling queued jobs never frees the slot of a job that is already running.

  • traits-generics impl<T: HasHandle> Admission<T> is roughly class Admission<T extends HasHandle>. Unlike Java, the compiler generates separate code for each concrete T (monomorphisation), so there is no boxing or casting. pub(crate) means visible inside this crate only.
  • borrowing Borrows end early. In take_ready, the read-only borrows of queued and active end as soon as position returns an index, so the mutable remove on the next line is allowed. The two ? operators return None instead of panicking.
  • borrowing iterators-closures cancel_queued walks by index, because a deque can't be changed while an iterator borrows it. handle.is_none_or(|h| …) treats None as "cancel everything".
  • testing The two tests (lines 54–95) pin the rule that matters: cancelling a queued sibling must not release the handle that is actually running.

A worker pool per Node environment: two OS threads (capped at eight across the process), an Admission queue behind a Mutex + Condvar, per-request deadlines and cancellation flags, and a Node-API thread-safe function (TSFN) that carries results back to the JS thread. It also handles pause/stop draining, environment shutdown, and a fail-safe "poisoned" state. Unchanged since September.

  • unsafe-ffi concurrency Pointers stored as usize. A Job moves to a worker thread, so every field must be Send. Raw pointers aren't Send, but integers are, so the Promise handle (deferred) and the TSFN are stored as numbers and cast back where Node-API is called. It works, but it tells the compiler nothing, so correctness rests on the surrounding invariants.
  • interior-mutability concurrency thread_local! + RefCell: each thread has its own map from environment to state, so no lock is needed. RefCell checks the borrowing rules at run time and panics on a violation. static LIVE_WORKERS: AtomicUsize is a process-wide counter.

The worker loop

  • concurrency interior-mutability Java's monitor pattern, made safe. This is while (!ready) cond.wait();. self.changed.wait(inner) takes the guard, releases the lock while sleeping, and returns the guard with the lock held again. Because the guard is moved into wait and handed back, inner can never be used without the lock. unwrap_or_else(|e| e.into_inner()) keeps using the data even if the lock is poisoned (a thread panicked while holding it); the engine's host.rs takes the opposite approach and fails.
  • enums-patterns loop is an expression, and break job supplies its value. The guard is dropped at };, so the lock is released before the job runs.
  • ownership smart-pointers mem::replace. A boxed FnOnce must be called by value, but job is still needed afterwards for finish. So the closure is swapped out and a harmless placeholder left in its place; Box::new(String::new) works because String::new is itself an FnOnce() -> String.
  • smart-pointers A drop guard. struct Slot, whose Drop decrements LIVE_WORKERS, runs however the loop exits: by return, by falling off the end, or, in builds that unwind, by a panic. It's try/finally without the finally block. self: Arc<Self> means each worker thread owns its own Arc handle to the shared state.
  • async concurrency A cancelled or expired job never reaches the engine. Otherwise submitted(job.submission.clone(), run) sets a thread-local in myotis-net for the duration of the call (below).

async concurrency smart-pointers How the deadline and cancellation flag reach the network code. submitted stores the Submission in a thread-local and restores the previous value through a drop guard (Restore), even on an early exit. The closure then checks its arguments and calls the C ABI → host.rs → rt.block_on(…). block_on runs the request future on this same thread, so when Operation::new (request.rs lines 68–87) reads SUBMISSION, it sees Node's values, takes the earlier of the two deadlines, and Operation::check watches the cancellation flag. The engine re-exports both names as myotis_engine::capi::{submitted, Submission}, which is how scheduler.rs imports them.

Results back to JavaScript

  • smart-pointers unsafe-ffi ownership Handing a Box to C and back. Box::into_raw gives up ownership and produces a raw pointer that Node queues. On the JS thread, complete takes ownership back with Box::from_raw, and *completion moves the value out of the box. If the hand-off fails, the box is reclaimed immediately (*Box::from_raw(completion)), so nothing leaks and nothing is freed twice.
  • concurrency Non-blocking on purpose. A worker never waits for the JS thread. The TSFN queue itself is unbounded, and admission's limit of 32 is what bounds it.
  • error-handling If a Node-API call fails, the scheduler is marked poisoned and refuses new requests. A broken invariant on a worker thread ends in fatal_completion() -> ! (lines 735–746), which calls napi_fatal_error and then abort. The ! ("never") return type tells the compiler the function doesn't come back.

Submitting and cancelling

  • concurrency The Promise is created before taking the lock, because Promise hooks may call back into the addon. A refused request still gets a Promise, resolved at once with {"error"}; drop(inner) releases the lock before that. The first pending request "refs" the TSFN, which keeps Node's process alive until the work is delivered.
  • smart-pointers interior-mutability Arc::new(AtomicBool::new(false)) is shared between the request table (so cancel_handle can set it) and the job's Submission (so the engine can check it). checked_add turns id overflow into an error instead of wrapping.
  • unsafe-ffi Raw Node-API calls (sys::napi_create_promise, napi_resolve_deferred) are each wrapped in check(…)?, which maps a status code to a Result. run: impl FnOnce() -> String + Send + 'static in argument position is a generic parameter written briefly; Box::new(run) then erases the concrete type into a Work.

concurrency cancel_handle sets the flags of that handle's running requests, removes its queued jobs (their Promises resolve with "request cancelled"), and then waits on the Condvar until the handle's running job returns. That wait blocks the JS event loop. Native work that can't be interrupted may take longer than 90 s, a trade-off the README states plainly: cleanup "cannot preempt indivisible work", and a host that needs a hard shutdown deadline needs a separate process. drop(inner) releases the lock explicitly before the struct is built.

concurrency smart-pointers A lock-free reservation. fetch_update is a compare-and-swap loop: the closure proposes n + 2 and returns None (via bool::then_some) when the process-wide cap of 8 would be exceeded, so at most four environments can have workers. Initializing is another drop guard, which clears its flag even when a ? returns early. An environment is identified by the numeric value of its napi_env pointer. The rest of state (lines 422–569) creates a preallocated fallback error, the TSFN (its context is a Box<Arc<State>> handed to Node and freed in finalize), the two threads, and finally the environment cleanup hook; every failure path undoes what was already done.
