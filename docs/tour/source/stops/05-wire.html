myotis-wire: the protocols as pure functions

Every byte Myotis sends to or reads from a peer is shaped here: discv4 packets, the RLPx handshake and its encrypted frames, the eth and snap messages, the proofs that make a snap answer trustworthy, and the eth2 req/resp framing. None of it opens a socket, reads a clock or draws a random number. The crate was split out of myotis-net so that a host without tokio (firmware, a browser, a blocking client) can drive the same code. Along the way you will see how one crate builds with and without the standard library, and how a decoder can read a 10 MiB peer message without copying it.

Why a crate with no I/O

Until issue #505 this code lived inside myotis-net, mixed in with the tokio tasks that drive it. It was already written “sans-I/O”: the codecs took entropy and time as parameters, and only a few service types touched sockets. The split made that a crate boundary. myotis-wire has no tokio, no sockets, no clock and no entropy. A caller passes in every random value (the ECIES ephemeral key, the IV, the EIP-8 padding) and every timestamp (a discv4 expiry). In return it gets plain functions from bytes to bytes or to typed values.

Two things follow. First, the crate builds as no_std + alloc with --no-default-features: it needs a heap allocator, but no operating system. The Gradle task cargoBuildNoStd proves it by building for x86_64-unknown-none, a target that has no std at all, and cargoCheckWasm checks it for wasm32-unknown-unknown. Second, myotis-net keeps working unchanged: it depends on myotis-wire and re-exports each moved module at its old path through tiny shim files, which you meet at the end of this stop.

The crate manifest

The manifest is the best summary of the design. Read the feature table first.

  • modules-cargo Features are additive switches. default = ["std", "eth2"] is what you get unless a dependent writes default-features = false. A feature can turn on features of dependencies ("myotis-core/std") and optional dependencies ("dep:snap"). The question mark in "myotis-consensus?/std" means “turn on std in that crate if it is already enabled for another reason”, so std alone does not drag in the consensus crate.
  • modules-cargo domain Why eth2 is optional. The consensus wire needs a few SSZ helpers from myotis-consensus, which depends on myotis-bls, which compiles the blst C library. An execution-layer-only host can switch eth2 off and avoid cross-compiling C for its target. The no_std canary builds exactly that combination: no std, no eth2.
  • testing modules-cargo test-util exposes test helpers to other crates. #[cfg(test)] code is only compiled for this crate's own tests, so myotis-net's tests could not see it. myotis-net turns test-util on in its [dev-dependencies] only, so production builds never contain the helpers. The comment names SessionSecrets::test_pair; the feature also gates discv4::encode_packet_for_test.

modules-cargo Every dependency is pinned with = and has default-features = false. Most RustCrypto crates turn on std by default; leaving one default on would pull std into a no_std build and fail only on the canary. snap is the exception: it needs std, so it is optional and enabled only by this crate's std feature. The remaining lines of the manifest (43–48) force the software SHA-2 backend on bare-metal targets, where the SSE-enabling code cannot be compiled.

New since the old tour. Snappy is the compression both peer-to-peer stacks use: RLPx compresses each message with the raw format, and eth2 req/resp uses the framed format (a stream identifier, then checksummed chunks). With std, every function here forwards to the snap crate, exactly what myotis-net used before. Without std (the snap crate needs it) a small in-house codec takes over: a complete raw decoder, a literal-only raw encoder, and a framed encoder and decoder that write uncompressed chunks.

  • modules-cargo Two bodies, one survives. #[cfg] works on blocks inside a function as well as on items. After configuration only one of the two blocks remains, and it becomes the function's tail expression. That is how one signature gets two implementations with no runtime if and no trait.

  • domain A literal-only encoder is still valid Snappy. Snappy output is a sequence of “literal” (copy these bytes) and “copy” (repeat earlier output) elements. An encoder that emits only literals never compresses, but every decoder accepts it. The doc comment argues that a light client's outgoing RLPx messages are a few hundred bytes, so the lost ratio does not matter, and having no match-finder leaves nothing to get wrong.
  • bytes-strings traits-generics Readers stack like Java InputStream wrappers. &[u8] implements Read, FrameDecoder decompresses it, .take(n) caps it at limit bytes, and read_to_end fills a Vec. The use std::io::Read; sits inside the block, because the trait (and std itself) only exists in that configuration.
  • domain limit is how the eth2 codec bounds memory: it passes the declared length plus one (see eth2/codec.rs). The initial capacity is capped at 1 MiB, so a large declared limit does not allocate up front. The built-in framed decoder applies the same limit, and also refuses a chunk with more than 64 KiB of uncompressed data, as snap does.

borrowing bytes-strings This is the “copy” half of the built-in raw decoder: repeat l bytes starting off bytes back in the output. The obvious line, out.extend_from_slice(&out[start..start + l]), does not compile: it borrows out immutably (the slice) and mutably (the push) at the same time, error E0502. It would also be wrong, because in Snappy a copy may overlap its own output (l > off, for example “repeat the last byte 20 times”). The byte loop handles both: let b = out[start + i]; copies one u8 (a Copy type), so the immutable borrow ends on that line, and out.push(b) then has out to itself. start + i is always below out.len(), because the vector grows by one each round.

  • error-handling ? on Option. The function returns Option<Vec<u8>>, so input.get(pos)? and pos.checked_add(2)? return None early, like Kotlin's ?: return null. get instead of indexing and checked_add instead of + mean a hostile input yields None, never a panic or an overflow. The earlier literal arm (lines 242–257) does the same, and the function refuses a declared length above max before it allocates anything.
  • ownership (out.len() == len).then_some(out) moves out into Some when the length is exactly right, and drops it otherwise.

testing The built-in codec runs in no production build that has std, so the tests are its only exercise on a normal machine. They run it against snap both ways. The property test builtin_raw_decoder_agrees_with_snap_or_refuses feeds 3,000 random inputs and many mutated snap encodings, generated with a deterministic xorshift so a failure reproduces, and asserts that the built-in decoder either returns what snap returns or returns None. The let mut next = move || { … } closure owns its state x and mutates it, which makes it an FnMut.

The discv4 packet codec, moved out of myotis-net::el::discv4. A packet is hash(32) ‖ signature(65) ‖ type(1) ‖ RLP data. The file has encoders for Ping, Pong, FindNode, and the EIP-868 ENR request and response, and decoders for what comes back. The Kademlia routing table, the ping rate limiter and the UDP service stayed in myotis-net (stop 11), which re-exports this module with pub use myotis_wire::discv4::*;.

  • domain Two hashes, two jobs. The leading hash covers everything after it and only detects corruption. The signature covers type ‖ data, and recovering the public key from it gives the sender's node id. There is no separate “from” field to trust: the identity is whatever key signed the packet.
  • bytes-strings borrowing The length check at the top makes every fixed range below safe to index. copy_from_slice copies into stack arrays ([u8; 32], [u8; 65]); it panics on a length mismatch, which the ranges rule out. packet[98..].to_vec() is the one heap copy: Parsed owns its data, so the caller's receive buffer can be reused at once.
  • enums-patterns error-handling let … else. let (Ok(ip), Ok(udp), Ok(tcp), Ok(node_id)) = (…) else { break; }; builds a tuple of four Results and binds all four values only if every one is Ok. Otherwise the else block runs, and it must leave the scope (break, continue, return). It reads like a guard clause in Kotlin, but it also destructures.
  • domain Java's leniency, reproduced. A structurally broken entry stops the walk and keeps the nodes so far (break). An entry with a wrong IP length or a UDP port above 65535 is skipped (continue), because that is where Java's InetAddress construction throws. The cross-language corpus in rust/testdata/el/discv4/ pins this behaviour.
  • bytes-strings udp as u16 is a truncating cast, safe here only because the line above already rejected values over 65535.

Declares the four RLPx modules: ecies, handshake, frame and hello. RLPx is the encrypted TCP transport under the eth and snap protocols. Only the initiator side exists, as in the Java reference. The doc comment states the contract: “the caller owns the socket and the entropy”. The tokio dialer that does own them is myotis-net/src/el/rlpx/transport.rs (stop 11).

ECIES encryption for the handshake's auth and ack messages: 0x04 ‖ ephemeral pubkey ‖ IV ‖ ciphertext ‖ MAC, with a concat-KDF over SHA-256 (counter first), AES-128-CTR, and HMAC-SHA256(SHA256(macKey), IV ‖ ct ‖ aad). The ephemeral key and IV are parameters, which keeps the tests deterministic. The file is unchanged since the old tour except for the alloc imports.

  • borrowing bytes-strings The IV, ciphertext and MAC are views into the input, and nothing is copied. The length check at the top guarantees that split_at and the index ranges can't panic.
  • ownership ciphertext.to_vec() is the one deliberate allocation: a mutable copy that apply_keystream(&mut plain) decrypts in place. The IV slice is copied into a fixed array because the cipher's .into() conversion is defined for arrays, not for slices of unknown length.
  • domain The MAC is verified before anything is decrypted, and in constant time: ct_eq from the audited subtle crate returns a Choice, so LLVM can't turn the comparison into an early-exit loop that leaks, through timing, how many bytes matched.

The initiator side of the EIP-8 auth/ack handshake. build_auth signs staticShared ⊕ nonce with an ephemeral key, RLP-encodes the auth body, and ECIES-encrypts it with the 2-byte size prefix as associated data. process_ack decrypts the reply and derives aesSecret and macSecret through a keccak chain. The raw auth and ack bytes are kept in SessionSecrets, because they seed the frame MACs.

  • lifetimes A struct that borrows. Initiator<'a> mixes a borrowed field (local_key: &'a NodeKey) with owned ones. The compiler proves that the key outlives every Initiator built from it. The key is only needed for one handshake, so a checked borrow is enough and no Arc is needed. In Java you would hold a reference and hope nobody clears the key in the meantime.
  • enums-patterns error-handling auth_wire: Option<Vec<u8>> works as a precondition: calling process_ack before build_auth returns an Err instead of panicking. .as_ref() turns &Option<Vec<u8>> into Option<&Vec<u8>>, so the check borrows the vector instead of moving it out of self.
  • borrowing ownership build_auth(&mut self, …) records the wire bytes, while process_ack(&self, …) only reads them, so the receiver type documents which call changes state. Because process_ack only borrows self, it cannot move auth_wire into the result: auth_wire.clone() copies it, and ack_wire.to_vec() copies the caller's slice. SessionSecrets then owns both.
  • error-handling rlp::decode(&plain).or_else(|_| decode_prefix(&plain))? tries the strict decode first and, only on error, a tolerant one that ignores trailing bytes, because some peers pad the ack body.

The encrypted, framed channel after the handshake: header ‖ header-mac ‖ body (padded to 16) ‖ body-mac. It uses AES-256-CTR with a zero IV and one continuous keystream per direction, streaming Keccak-256 MACs advanced through AES-256-ECB, and Snappy for every payload except Hello. The codec splits into an egress half and an ingress half, so a reader task and a writer can each own one. Compression now goes through crate::snappy instead of the snap crate directly.

  • ownership concurrency Splitting one value into two. split(self) takes the codec by value and moves its two fields out. That is allowed because FrameCodec has no Drop impl; a type with one can't be taken apart (error E0509). Afterwards the codec no longer exists, and the halves are independent values that can go to different tasks without a lock.
  • borrowing concurrency The doc says “NOT thread-safe”, and the types enforce it: every encode and decode method takes &mut self, because each call advances a keystream and a MAC chain. Two concurrent users of one encoder don't compile. There is nothing like Java's synchronized here; exclusive access is a compile-time fact.
  • borrowing new(secrets: &SessionSecrets) only borrows the secrets. The ciphers copy the key material they need, so the caller keeps its SessionSecrets.
  • domain The header data must be 0xc2 0x80 0x80, not 0xc0. Nethermind disconnects otherwise, which is fatal on gnosis, where most nodes run Nethermind.
  • domain Order matters, irreversibly. Encrypt the header, MAC it, encrypt the body, MAC it: each step mutates self.encrypt and self.egress_mac. A frame written only halfway therefore corrupts every later frame. That is the reason for the torn flag in myotis-net's peer code (stop 12).
  • bytes-strings Above this excerpt, (body_len + 15) & !15 rounds the body up to a multiple of 16, and [u8; 16] lives on the stack.

ownership domain Reading the current MAC digest (current_digest_16, line 316) clones the hasher first, because finalize() takes the hasher by value and would end the chain. decode_body checks a peer's declared decompressed size with snappy::decompress_len before it decompresses, so a 6-byte Snappy header that claims 4 GiB can't make the process allocate 4 GiB and abort. A payload that fails this check, or fails to decompress, is passed up raw; the RLP layer above then rejects it. The bomb test builds its header with a bare 0xc0, which also shows that the decoder never looks at the header-data bytes.

New file, moved here from myotis-net::el::rlpx::transport: the p2p base message codes (Hello 0x00, Disconnect, Ping, Pong), the client id, and the Hello encoder and decoder. Hello is the first framed message in both directions. It names the client and lists its capabilities; the eth session in myotis-net then picks the highest eth and snap versions both sides share. transport.rs re-exports every item by name.

  • macros A version string built by the compiler. env!("CARGO_PKG_VERSION") reads an environment variable that Cargo sets while compiling, and concat! joins string literals at compile time. The result is an ordinary &'static str constant such as "myotis/0.1.19". The Java engine derives its Hello id from the same Gradle version, and the build task verifyCrateVersions keeps the two equal.

Its parameter types are written out because the body calls a method on name, and the compiler type-checks a closure's body where it is defined, before it has seen any call.
  • domain The capability list advertises eth/66–71 and snap/1–2. eth/70 (EIP-7975, receipts that can be continued) and eth/71 (EIP-8159, block access lists) exist only in the Rust engine. encode_hello_as exists for the Tor path, whose Hello names the software without its version.

bytes-strings error-handling decode_hello (lines 79–114) first refuses a body over MAX_CONTROL_MSG_SIZE (16 KiB) before it builds an RLP tree (#454). It then reads strings with String::from_utf8_lossy(…).into_owned(): from_utf8_lossy returns a Cow<str> that borrows the input when it is valid UTF-8 and owns a repaired copy when it is not, and into_owned() turns either into a String. Status: optional fields for version-specific data

enums-patterns One struct serves both layouts: the eth/69-only fields are Option<u64>, None on 67–68. That is Kotlin's Long?, except that the compiler makes every reader handle the None case. A few lines further down, HeadersOrigin (lines 239–242) is a data-carrying enum, like a Kotlin sealed class: a header request starts either at a block number or at a hash. decode_status and the other control decoders call check_control_size first, so a 10 MiB “Status” is refused before it is decoded into a tree.

Headers: read in place, copy what is kept

  • borrowing lifetimes Zero-copy parsing. request_and_payload returns a rlp::View, a checked, borrowed window into rlp_bytes (stop 4 covers View in myotis-core). headers.as_list()? walks its elements without building anything, and raw.raw() is a slice of the caller's buffer. Bytes are copied only at raw.raw().to_vec(), for a header that is kept.
  • domain header::hash(raw.raw()) hashes the exact wire bytes, never a re-encoding: a block hash is keccak over what was sent.
  • domain error-handling Check everything, keep a little. Every header is decoded, so a malformed one fails the whole response exactly as before. Only the first kept(requested) (the number asked for, plus one so a caller can still see a peer that over-serves) are stored. A peer that sends a million headers costs a walk, not a million allocations.

Receipts: the count is checked before any work

  • smart-pointers ownership lifetimes Cow: borrow when you can, own when you must. Cow<'_, RawList> (“clone on write”) is an enum with two variants. For eth/66–68 the stored list already holds the receipts-trie values, so expand returns Cow::Borrowed(list) and copies nothing. For eth/69 every receipt must be rebuilt with its bloom, so it returns Cow::Owned(out), a new list. The caller uses either as a &RawList. The '_ ties the borrowed case to &self, so the borrow checker stops it from outliving the BlockReceipts it points into.
  • domain Why the count comes first. eth/69 (EIP-7642) removed the 256-byte logs bloom from each receipt, because it can be recomputed from the logs. Recomputing adds 256 bytes to every receipt, however small. If the count were not checked first, a peer could send millions of tiny receipts and make the node expand them. canonical demands exactly the transaction count of the block's verified body; canonical_at_most (for a caller without the body, #544) accepts at most a bound taken from the trusted header. expand is private, so every way in checks a count.
  • enums-patterns len() (line 562) uses an or-pattern, BlockReceipts::Canonical(list) | BlockReceipts::Eth69(list) => list.len(), which is allowed because both arms bind list with the same type.
  • enums-patterns Slice patterns. [] matches an empty slice, and &[b] if b <= 0x7f matches a one-element slice and binds the byte, with a guard. One match checks length and content together. A multi-byte type is rejected instead of truncated to its last byte, which is what the Java code would do.
  • borrowing lifetimes The function returns (u8, [rlp::View<'_>; 3]): an array of three views into the same wire buffer. View is Copy (it is just a slice reference), so returning three of them costs nothing. The elided lifetime ties them to wire.
  • domain Lines like status_or_state.as_bytes()?; discard the value and keep only the check. The canonical form later copies these fields as they arrived (canonicalize_eth69_receipt), which is correct only because they were checked here.

RawList: a list that costs what it weighed

  • ownership bytes-strings A newtype. pub struct RawList(rlp::ListBuf); wraps one value and keeps it private. ListBuf stores the items' encodings back to back in a single Vec<u8>, plus a count. The previous Vec<Vec<u8>> paid a heap allocation and about 50 bytes of overhead per element, which a body of millions of one-byte “transactions” turned into hundreds of MiB (#454).
  • iterators-closures lifetimes traits-generics An iterator that lends slices. RawListIter<'a> yields &'a [u8], slices that borrow from the RawList itself. impl<'a> IntoIterator for &'a RawList (lines 834–841) makes for tx in &list work, like Java's Iterable. Because the iterator tracks left, it can implement ExactSizeIterator, and collect() can size its vector in one go.
  • error-handling item.as_bytes().unwrap_or_default() cannot actually fail: every item was checked on the way in. The default for &[u8] is the empty slice.

They only feed the “seen in gossip” signal of the sent-transaction watch, never a trust decision, so a malformed announcement yields the hashes that can be read, or none, and at most 256 per message.

The eth2 req/resp protocol ids, exactly the set and versions the Java engine speaks, plus three lookups: whether responses carry 4 context bytes (the fork digest), whether a request is a root list this node never reads, and the exact SSZ size of each request body (used by the responder to refuse inflated requests). domain bytes-strings The fork digest is the 4-byte network tag on every eth2 message: the first 4 bytes of a hash over the fork version and the genesis validators root. Since Fulu, a “blob parameter only” fork changes the digest without a new fork version, so the active BPO epoch and blob limit are hashed and XORed in. base[..4].try_into() copies 4 bytes out of the 32-byte root into a [u8; 4]. The CUSTODY_GROUP_COUNT constant above it (line 99) is a deliberate overstatement of what this node stores, with the reason written out: Lighthouse bans a peer that advertises less than the custody requirement.

Byte-level framing for eth2 req/resp, with no I/O and nothing async: varints, Snappy framed compression, request encode and parse, single- and multi-chunk response decode, and response encode. Every function borrows a byte slice and returns owned bytes or an error. Java-generated golden vectors keep the two engines byte-compatible. Compression now goes through crate::snappy, and the multi-chunk decoder now keeps each chunk's fork digest.

domain error-handling Allocation is bounded before it happens. Snappy can expand data about 21 times, so a hostile peer could turn a 16 MiB frame into hundreds of MiB. The declared length is checked against 10 MiB first, the reader is capped at declared + 1 (one extra byte reveals an overrun), and any mismatch is rejected, as the spec requires. .map_err(|e| CodecError(format!(…)))? converts the String error from snappy into this module's error, then propagates it.

bytes-strings Narrowing safely. as usize truncates silently, like (int) someLong, and on armv7 Android usize is 32 bits. So the code compares in the wide type (u64) first. Once the values are known to be equal, the narrowing cast is provably lossless. read_varint(raw, 0).ok()? turns a parse error into an early None.

Declares snap's two modules: messages (the codecs) and fetch (verification of what a peer returns). snap shares the eth peer's RLPx connection; the two protocols are told apart by message code, and snap's codes start right after the last eth code.

Pure snap codecs: account ranges, storage ranges (one account at a time), bytecodes, empty responses, and, new since the old tour, snap/2 (EIP-8189) and block access lists (EIP-7928): the per-block record of which accounts a block changed, and to what. A decoded “slim” account body is only the peer's claim and is never trusted. A single-account query asks for [keccak(addr), 0xff…] with a small byte budget, so the peer returns one account plus the boundary proof. Like eth.rs, the decoders now read in place and keep at most MAX_RANGE_ENTRIES entries and MAX_PROOF_NODES proof nodes.

lifetimes borrowing A struct that borrows from the message. SlimFields<'a> holds balance: &'a [u8], a slice of the peer's message, not a copy. The slim body comes in two forms (a nested list, or a byte string wrapping that list's RLP), and let body = if body.is_list() { body } else { rlp::View::new(body.as_bytes()?)? }; unifies them by shadowing: the new body is a view of the inner bytes. That compiles because View::as_bytes returns &'a [u8], tied to the original input, not to the temporary view. The old version of this decoder built an owned tree and had to declare a holder variable before the match so the borrow would live long enough; with views there is nothing to own. decode_account_range copies the balance (to_vec()) only for the entries it keeps.

  • iterators-closures borrowing A closure that borrows mutably. let mut field = |name: &str| fields.next()… captures the iterator fields by mutable reference, so field is an FnMut and must itself be mut. While the closure is still going to be used, nothing else may touch fields. After its last call (line 492), the borrow ends, which is why line 493 may call fields.next() directly. The compiler works this out from where the closure is last used (“non-lexical lifetimes”).
  • domain error-handling previous.is_some_and(|p| p >= address) compares two [u8; 20] arrays lexicographically, which is the address order the BAL spec requires. Out-of-order accounts are an error, never a partial answer, because these values are applied to proven state. The shims left behind in myotis-net

Nine files in myotis-net are now four lines long. Each says where its code went and re-exports it. Here is one; the other eight differ only in the path.

  • modules-cargo A glob re-export. pub use myotis_wire::eth2::codec::*; makes every pub item of that module visible as if it were declared in myotis_net::codec. Nothing is copied: myotis_net::codec::CodecError and myotis_wire::eth2::codec::CodecError are the same type, so values pass freely between code that uses either path. Items that are pub(crate) (such as eth::kept) or exist only under #[cfg(test)] are not carried.
  • modules-cargo Why keep them. Many users still name the old paths: roost (myotis_net::codec, myotis_net::status), tor-poc (el::snap::fetch), myotis-net's own examples and conformance tests, and modules inside myotis-net itself (crate::codec in reqresp.rs and sync.rs). roost and tor-poc are separate Cargo workspaces, so a path change there is easy to miss. The shims let the move land with no change to any of them.

Re-exports myotis-wire's eth2/codec.rs as myotis_net::codec. Kept for roost (its framing.rs, store.rs and main.rs), the CL examples, tests/live_pins_alive.rs, and reqresp.rs and sync.rs inside myotis-net.

Re-exports eth2/status.rs as myotis_net::status. roost's serve.rs and forks.rs use the old path, as do reqresp.rs, sync.rs and cl_fork_watch.rs inside myotis-net.

Re-exports eth2/protocols.rs as myotis_net::protocols, for reqresp.rs, sync.rs and the CL examples (lc_crawl, period_census, probe_updates).

Re-exports rlpx/ecies.rs at myotis_net::el::rlpx::ecies. The cross-language RLPx corpus test tests/el_rlpx_conformance.rs still imports it from here.

Re-exports rlpx/frame.rs at el::rlpx::frame. transport.rs next to it imports FrameCodec and its halves through super::frame, and eth/session.rs, reader.rs and the conformance test use the path too.

Re-exports rlpx/handshake.rs at el::rlpx::handshake, for transport.rs (super::handshake::Initiator), eth/session.rs and the conformance test. Re-exports snap/messages.rs at el::snap::messages, for peer.rs, reader.rs, activity.rs (which uses BalAccountChange), the session, the conformance and hostile-frame tests, and snap_probe.
