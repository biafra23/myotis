myotis-rpcd: a JSON-RPC daemon in Rust

A new crate since September, and a binary crate: one executable that links the engine as a library and answers standard Ethereum JSON-RPC over HTTP, with no JVM and no upstream RPC to fall back on. It exists for hosts that only need a local endpoint: a server, a Raspberry Pi, a container, or a Swarm Bee node. Every answer is one the engine verified; anything it cannot verify is an error. The design is deliberately synchronous: the engine owns its tokio runtime and every read is a blocking call, so the daemon is a blocking HTTP server with two thread pools in front of a router that ports the strict path of the Kotlin RpcRouter.

Rust you will practise

A binary cratemain.rs + mod files, clap's derive macros, Result<(), String> and ? with From, #[cfg(unix)]/#[cfg(windows)], and a drop guard that stops the engine on every exit path.
Threads and channelsArc, a bounded mpsc::sync_channel shared through Arc<Mutex<Receiver>>, try_send giving the value back, atomics, and Cell for per-request state that never leaves its thread.
Traits as seamsA Send + Sync Engine trait with a real and a fake implementation, a generic Router<E: Engine>, a Read decorator, a Fail enum mapped to error codes in one place, and checked arithmetic over attacker-controlled bytes.

The crate at a glance

There is no lib.rs: a package with only src/main.rs is a binary crate, and cargo build -p myotis-rpcd --release produces target/release/myotis-rpcd. The six mod lines at the top of main.rs pull in the other files; rpc.rs in turn declares mod tests;, whose source lives at rpc/tests.rs (the Rust 2018 layout: a module rpc may keep its children in a directory named after it, with no mod.rs). Being a workspace member, the binary inherits the workspace release profile, including panic = "abort": a panic ends the process, and the data dir resumes on restart.

Cargo.toml: five dependencies

Five dependencies, each with a comment that says why. The engine comes in as an ordinary path dependency (an rlib), so the daemon calls its functions directly as Rust: the ffi module's (which also carry #[uniffi::export] for the JVM hosts) and two capi ones. Nothing crosses a language boundary.

  • modules-cargo No HTTP framework and no async runtime. tiny_http is a small blocking HTTP/1.1 server: you call server.recv() and get a Request, and you answer it with request.respond(response). The comment states the reasoning: every engine read blocks, so a fixed worker pool over a synchronous server is the whole design. The http.rs module doc adds that an async server "would only add a second runtime whose every handler is spawn_blocking around the same calls".
  • modules-cargo cli Feature selection to keep the lock file small. clap is already in the lock through uniffi, so it costs nothing new, but its default color feature would add six crates, so default-features = false and an explicit feature list. signal-hook gets only iterator, which exists only off Windows. serde is listed only for IgnoredAny (see the call log in rpc.rs).

Parses the command line, checks every input before the engine starts, creates one engine handle for one network, starts the HTTP pools, and waits for SIGINT or SIGTERM. "One engine handle per process": a second network is a second daemon on another port.

  • macros cli clap's derive. #[derive(Parser)] generates the argument parser from the struct. Each field becomes a flag (data_dir → --data-dir), its /// doc comment becomes the help text, and its type decides the parsing: Option<PathBuf> is an optional flag, bool a switch, Vec<PathBuf> a repeatable one, Option<SocketAddr> is parsed with SocketAddr's FromStr. value_parser = [...] restricts the value to a list. Compare picocli's annotations, except that the code is generated at compile time.
  • cli Args::parse() in main exits the process with a usage message on a bad command line, so run only ever sees valid flag syntax. Cross-flag rules are declared too: --checkpoint-root and --checkpoint-slot each requires the other, and --import-log-index requires --log-index-config.

Startup: check everything first

run returns Result<(), String>. Before any flag is used it calls ffi::engine_init() and compares the result with myotis_engine::ABI_VERSION; the engine is linked statically, so a mismatch means a broken build. It then turns on EIP-1459 DNS discovery (the daemon, like the JVM daemon, may use the system resolver), resolves the network name, and reads the chain id and the default port from the engine's network catalog JSON.

  • iterators-closures error-handling collect::<Result<Vec<_>, _>>()? turns an iterator of Results into one Result: all Ok gives the vector, the first Err stops the iteration and is returned. Java streams have no direct equivalent; you would collect and then check.
  • enums-patterns error-handling .as_deref().map(seeds::load).transpose()?: as_deref turns &Option<String> into Option<&str> without moving the string out of args; map gives Option<Result<Vec<String>, String>>; transpose flips it to Result<Option<…>, …>, so ? can return the error and leave None when the flag is absent.
  • error-handling The server is bound right after this (line 203), before the engine starts, "so a taken port fails in milliseconds". The same idea runs through the whole function: a typo must not cost a started engine handle.
  • enums-patterns Matching on a tuple and on sentinels. match (&args.checkpoint_root, args.checkpoint_slot) takes the two flags apart together; the arm (None, None) if bound.is_some() adds a guard. On the handle, -3 if checkpoint.is_some() and a second -3 arm give the same sentinel two messages, and h if h < 1 binds any other negative value. The engine's negative handles are the C ABI's in-band errors (Stop 16); here they become readable messages.
  • error-handling bound.expect("guarded") cannot fail because the guard just checked is_some(); expect documents that reasoning in the panic message.
  • ownership smart-pointers StopOnDrop(handle) is a drop guard (below): from this line on, every return Err(…) and every ? drops guard, which stops the handle and lets it persist its sync state.

The rest of run (lines 257–304) applies the trust overrides, pushes the boot enodes before start_handle (the engine stashes them and dials once its EL pool is up), starts a thread that pumps the engine's log ring to stderr every 500 ms, starts a thread that retries the log-index config every 2 s until the EL reader accepts it, and builds the router with chained builder calls (Router::new(…).with_ready_wait(…).with_access_log(…), each taking self by value and returning it).

  • concurrency Shutdown. tiny_http's unblock() wakes one thread waiting in recv(), so it is called once per intake thread (http::spawn returns that count). Read workers still inside an engine call are not waited for: when run returns, main returns and the process exits, ending every thread.
  • smart-pointers ownership drop(guard) runs StopOnDrop::drop now rather than at the closing brace, so the handle is stopped before the final log flush. struct StopOnDrop(i64) is a tuple struct; self.0 is its field.
  • cli error-handling In main (lines 129–140), an error prints the engine's remaining log lines and then the message, and calls std::process::exit(1). exit does not run destructors of values still alive, but by then run has returned and its guard has already stopped the handle.
  • modules-cargo wait_for_stop_signal exists twice, under #[cfg(unix)] (signal-hook's blocking iterator) and #[cfg(windows)] (a flag polled every 100 ms). Only one is compiled for any target, so both can have the same name.

The seam between the router and the engine. The Engine trait lists what the router asks: strings in, the engine's JSON strings out. FfiEngine implements it over one engine handle; the tests implement it with a recorded fake, so the whole router can be tested without a running light client. Readiness reads the status JSON and decides whether a read should wait.

  • traits-generics concurrency trait Engine: Send + Sync declares supertraits: any implementation must be safe to move to another thread (Send) and to use from several threads at once through a shared reference (Sync). The router is shared through an Arc by the intake threads, the read workers and the body readers, so it needs both, and it can only have them if its engine does. In Java terms every method of the interface must be thread-safe, but here the compiler checks it.
  • borrowing Every method takes &self and &str arguments: the router lends its strings and keeps them. #[allow(clippy::too_many_arguments)] silences one lint for one method.

domain The JVM host's readyForReads, ported. Ready means SYNCED, a verified head, and at least one pooled peer that can actually serve at it (snapServingPeers, not snapPeers: a pool of still-syncing peers can keep the latter positive for hours, #465). Two states say "ready" for a different reason: a running handle with no EL reader, or one parked in STALE_ANCHOR. Waiting cannot change either, so the read goes ahead and the engine's own refusal is the answer. Readiness::parse (lines 81–100) uses unwrap_or_default() on the JSON parse, so garbage reads as "not running", never as ready.

ownership bytes-strings The impl Engine for FfiEngine (lines 121–217) is one line per method, for example ffi::request_account_json(self.handle, address.into(), block.into()). The ffi functions take String by value (the UniFFI convention), so each .into() allocates an owned copy of the borrowed &str. That copy is the price of reusing the JVM-facing surface; it is negligible next to a network read.

The HTTP side: a tiny_http server, four intake threads that accept and classify every request, and --workers read threads that serve the bodies naming a gated method. It also enforces geth's browser protections (the Host allowlist and the JSON Content-Type rule), the body limits, and a receive deadline for large bodies, so that no client can hold an intake thread.

  • domain DNS rebinding. A web page can make its own domain resolve to 127.0.0.1 and then send requests to the node from the operator's browser. The browser still sends the page's domain in the Host header, so an allowlist of local names refuses it with 403. A missing Host header passes, as in geth, because every browser sends one. The Content-Type rule (json_content_type, lines 99–109) closes the other door: the cross-origin POSTs a page may send without a CORS preflight are forms and text/plain, and those are refused with 415.
  • enums-patterns bytes-strings match (self, host) matches on a tuple, and (VHosts::Any, _) | (_, None) => true joins two patterns with |. In host_name, &h[..=i] slices up to and including the ] of an IPv6 literal; rsplit_once(':') splits at the last colon. Both return borrowed slices, and only to_ascii_lowercase allocates.

Two pools

  • concurrency smart-pointers A bounded channel with many consumers. mpsc::sync_channel(n) is a channel with room for n messages, like a ArrayBlockingQueue. Its Receiver can't be cloned or shared (it is not Sync), so the workers share it as Arc<Mutex<Receiver>>: one worker at a time holds the lock while it waits in recv(), and the guard is dropped once a request arrives, before the request is served. It is the same design as the thread pool in the final project of the Rust book.
  • ownership concurrency let (rx, router) = (rx.clone(), router.clone()); clones the two Arcs (a reference-count increment, not a copy of the data) before the move closure, so each thread owns its own handles and the originals stay usable for the next iteration. The same pattern feeds the intake threads.
  • enums-patterns let Ok((req, body)) = next else { return }; ends the worker when the channel is closed. std::thread::spawn(move || loop { … }) is a closure whose whole body is a loop expression.

concurrency Never read from a client's socket on intake. tiny_http has already buffered a small body (up to 1 KiB with a Content-Length and no Expect; body_in_memory, lines 226–236). Any other body may trickle in for as long as the client likes, so it is received on a thread of its own. fetch_add returns the value before the increment, so at most MAX_BODY_READS (32) bodies are being received at once; past that the request is answered 503. The decrement comes after respond, which also drops and drains the request.

  • enums-patterns match req.method() with guards: tiny_http::Method::Get if req.url() == "/" matches only when both hold, and the arms are tried in order, so the Content-Type refusal arm comes before the general Post arm.
  • ownership concurrency try_send gives the value back. Sending moves (req, body) into the channel. When the channel is full, the error TrySendError::Full((req, body)) returns ownership of both, so the request can still be answered with 503 and an error per request in the body. Nothing is dropped unanswered, and the compiler would not let you use req after a successful send.
  • domain Body::parse parses the JSON once; body.blocking() decides which pool answers it, and the router later serves the same parse (handle_parsed(body)), so the body is never parsed twice.

traits-generics A Read decorator. impl<R: Read> Read for Deadline<R> wraps any reader, like a Java FilterInputStream, and fails with TimedOut once the deadline has passed. Implementing the one required method read is enough: read_to_string is a provided method of the trait, built on top of it. In read_body (lines 321–349) it wraps req.as_reader().take(MAX_BODY_BYTES + 1); reading one byte more than the limit is how a body that is too large is detected (413). As the doc comment says, the check runs only before each read, so a client that stops sending entirely still holds its body thread, but never an intake thread.

testing The seven tests (lines 402–704) include four that start a real server on 127.0.0.1:0 (the OS picks a free port) and speak raw HTTP over a TcpStream: a health check answers while the only read worker is held; foreign hosts get 403 and non-JSON posts 415; a full queue gets 503 with one error per request that has an id; and six clients stalled mid-body do not block GET /, then get 408.

The JSON-RPC router: a port of the strict (no-proxy) path of the Kotlin RpcRouter in jsonrpc-server, with the engine-JSON reading of the Rust-engine adapters (IosRpcBackend, RustVerifiedReads) folded in. A request is answered from the engine's verified surface or refused. It handles envelopes and batches, the readiness hold, the method table, every parameter, and the mapping from engine JSON to results and error codes.

The method table and the error codes

  • enums-patterns match is an expression. Some(match method { … }) wraps whatever the arms produce, and the last arm _ => return None leaves the function early instead. Arms join string patterns with |. One function answers two questions: "is this method served?" (Some) and "how many positional arguments may it take?".
  • domain Too many arguments is an error, not a detail. dispatch refuses a request with more params than this, and a params that is neither absent, null nor an array. An extra argument the server dropped would answer a question the client did not ask. The doc and the comment on line 113 disagree slightly: eth_createAccessList takes a third argument (state overrides) that geth does not take, so there a request geth would refuse is served with the override applied.

gated(method) (lines 59–63) is "served and not in NON_BLOCKING". The seven non-blocking methods are eth_chainId, net_version, web3_clientVersion, eth_accounts, net_listening, eth_syncing and myotis_status: config and the status snapshot. Everything else may be held for readiness.

The project rule behind -32602

The repository's CLAUDE.md (section "Trust") says a parameter that can change the answer must be "APPLIED or REFUSED — never accepted and silently ignored", and that a refusal uses the permanent -32602, because -32000 is documented as retryable and a client would spin on it. The rule came from eth_call once dropping a state override (#314). In this file you can see it everywhere: too many arguments, params that are not an array, blockOverrides (never applied, so present means refused, with a message that says "rejected, not ignored"), an unknown state-override field, safe and earliest, bare-digit block numbers, a non-boolean fullTransactions, both data and input set and different, blob fields, a chainId that is not this chain's, and a missing eth_feeHistory newest block. The opposite class, "not now", stays -32000: a block a little ahead of the head, a hash the node cannot place yet, a node that is not ready.

The readiness hold

  • interior-mutability Cell: mutation through a shared reference, single thread only. Handlers receive g: &Gate, a shared borrow, yet the gate must record that it was passed. Cell<bool> allows that without a lock: passed.replace(true) stores true and returns the old value, spent.get() and spent.set(true) copy the value in and out. Cell is not Sync, so the compiler would refuse to share a Gate between threads. It never needs to be: a Budget and its gates live on the stack of the one worker serving the body.
  • lifetimes Gate<'b> holds &'b Budget. A struct that stores a reference must name its lifetime, and the compiler then guarantees that the gate cannot outlive the budget. handle_parsed creates one Budget per HTTP body; handle_one creates one Gate per request, borrowing it. So a batch shares one wait of at most --ready-wait, and each request waits at most once however many times its handler calls engine_ready (the pin check, the window check and the read each do).
  • borrowing engine_ready returns Result<&E, Fail>: on success a borrow of self.engine, with its lifetime tied to &self by elision. The handlers write self.engine_ready(g)?.get_code(…), so the engine can only be reached through the gate. The gate is taken lazily, at the first engine read, so a request refused on its parameters never waits.
  • concurrency The wait is a plain poll: thread::sleep(READY_POLL.min(deadline - now)), re-reading the status every 250 ms. When the budget runs out, the read goes ahead anyway, so the error that comes back carries the engine's own reason. Later gated elements of the same batch then fail fast with -32000.

Dispatch

  • borrowing Borrowing an empty default. params must be a &Vec<Value> borrowed from the request. For an absent params there is nothing to borrow, so the function first creates a local empty vector and borrows that. The local lives until the function returns, so the reference is valid in every arm.
  • error-handling A pipeline of ?. Each step either returns its value or ends the handler with a Fail: parse the address, parse the selector, resolve a block hash to a number, refuse a pin behind the window, then read and check the account. The sel variable is shadowed: let sel = self.resolve_hash(sel, …)? moves the old Selector into the call and binds the returned one to the same name.
  • domain Only pending consults the overlay. The engine remembers this node's own unmined broadcasts. pending_nonce_overlay returns max(mined, ours + 1) or -1 for none; u64::try_from(o).unwrap_or(mined) turns the -1 back into the mined nonce. A proof of exclusion (exists: false) is a verified balance of 0.

eth_call: two engine paths

domain error-handling The engine has a plain call (from, to, data, value) and a transaction-object call that applies gas, fees, type, access and authorization lists. parse_tx sets tx.extended when the object carries anything the plain call would drop (lines 1822–1838: an explicit type, gas, any fee field, a non-empty access list, an authorization list, or a nonce on a contract creation), and then only the transaction-object call may answer. This is #314 solved structurally. parse_tx(obj).or_else(|why| invalid(…))? converts the parser's String error into a Fail. overrides.as_deref().unwrap_or("") turns Option<String> into a &str without moving the string.

Block pins

  • domain Behind, inside, ahead. The node holds state only near its verified head. A pin more than 64 blocks behind is refused for good (-32602): no wait will make that state appear. A pin up to 16 ahead is served from head state. Further ahead is -32000, because the head may yet reach it.
  • domain ReportedHeads. A wallet pins its reads to the number it was just handed by eth_blockNumber. If this node itself reported a head at or below the pin within the last 15 minutes, the pin came from this node, so it is declined retryably instead of being called invalid, even after the head moved on. The struct (lines 156–192) is a Mutex<VecDeque<(u64, Instant)>>, pruned by age and capped at 512 entries.
  • enums-patterns let Some(n) = sel.number else { return Ok(()) };: tags have no number and pass. head.saturating_sub(64) stops at 0 instead of underflowing, which would panic in a debug build (and abort the daemon if overflow checks were on in release). n + 64 in in_window cannot overflow for a caller's number: parse_selector refuses numbers above i64::MAX (a resolved hash's number comes from a verified header).

domain A 32-byte block hash goes through resolve_hash (lines 971–1044) first: the engine names the canonical block with that hash, header only, and the router then serves the request exactly as that number, through the same window. An engine null (a hash it cannot place: not reached yet, too old, or on a fork) is a retryable -32000 naming the hash, since the node cannot tell "not yet" from "never". The resolver also checks that the engine returned the hash it was asked for and refuses block 0. eth_getProof is the exception: it hands the hash straight to the engine, which pins the proof to that block's root in one read, so no reorg can slip in between resolving and reading.

Reading the engine's JSON

  • error-handling domain Fail closed. The engine signals errors in-band: {"error": …} is retryable, {"error": …, "code": -32602} permanent. Only an object with exactly those keys counts as an envelope. Anything that does not parse, or that is not an object, is Fail::Unavailable(None), never a result. verified (lines 1188–1197) adds the state-read rule: no verifyMethod string, no answer. parse_account (lines 1117–1137) refuses any shape drift with -32000, so a malformed engine reply can never become a "verified" balance of 0.
  • bytes-strings err.as_str().map(str::to_owned).unwrap_or_else(|| err.to_string()): a string error is copied as is; any other JSON value is serialised. str::to_owned is a function path used as a closure.
  • iterators-closures o.get("error").is_none_or(Value::is_null) is true when the key is absent or null; it reads like the Kotlin o["error"]?.isNull ?: true.

tri_state serves the reads that have three outcomes: a found object, the literal null (a verified "not seen", which is a valid result), or an error envelope. call_outcome maps the EVM's status: ok → the return data or the gas, revert → geth's code 3 with the payload as data, infeasible → geth's -32000 in geth's words. A reasonless infeasible or a malformed hex field is shape drift: retryable, never a confident answer.

bytes-strings error-handling Decoding attacker-controlled bytes. A revert payload comes from a contract, so its offsets and lengths are hostile. d.get(at..at.checked_add(32)?)? returns None instead of panicking when the range is out of bounds, and checked_add returns None on overflow. That matters because a panic aborts the whole daemon (panic = "abort"); the test revert_reason_decoding_is_bounded feeds it an offset of u64::MAX. Error(string) starts with the selector 08c379a0, Panic(uint256) with 4e487b71. The decoded text is reduced to printable ASCII, so it can neither forge log lines nor spoof a UI. Inside the closure word, ? works because the closure itself returns Option.

Parameters: applied or refused

  • enums-patterns Three states, never two. OverrideParam is Absent, Valid(String) or Malformed(String). With an Option, "malformed" would have to collapse into "absent", which is exactly the silent drop the project rule forbids. An override with no actual changes (only null or empty entries) is Absent, so the plain call can serve it.
  • iterators-closures for (addr, entry) in ov iterates a &Map and yields pairs of references. changes |= !fields.is_empty(); is a boolean or-assignment. ov.clone() copies the map only once it is known to be valid.

parse_selector (lines 1476–1620) is "the ONE reading of a block selector": absent or null is latest; latest, pending and finalized pass as tags; safe and earliest are refused with an explanation; numbers must be 0x-hex, nonzero and at most i64::MAX; and methods that take a BlockNumberOrHash also accept a 32-byte hash, bare or in EIP-1898's object form ({"blockHash"} or {"blockNumber"}, not both, with an optional boolean requireCanonical). It returns a Selector whose value is what the engine is handed: the tag, a minimal 0x-number, or a lowercase hash.

bytes-strings The envelopes (lines 1858–1885) are built with format!, and the result is embedded verbatim as already-serialised JSON, because a block with full transactions can run to megabytes and need not be parsed and re-encoded. {id} formats a serde_json::Value through its Display, which is its JSON text. The error object is built as a Map, so the message is escaped. The call log (lines 1887–1951) shortens long strings at a UTF-8 character boundary (floor_char_boundary), and counts the elements of a long array result by deserialising it into Vec<IgnoredAny>, which skips each element without building it.

JSON-RPC QUANTITY and DATA encoding without a bignum dependency, ported from the Kotlin router's RpcQuantities. The engine hands balances and fees across as decimal strings, the wire wants minimal hex, and wei values are at most 256 bits, so schoolbook base conversion over digit arrays is enough.

  • ownership iterators-closures Long division by 16, repeated. Each pass divides the decimal digit array by 16, keeps the remainder as the next hex digit (least significant first), and replaces digits with the quotient. quotient.split_off(start) returns the part from the first nonzero digit as a new Vec, dropping the leading zeros; assigning it to digits drops the old vector. out.reverse() then puts the most significant digit first.
  • bytes-strings u32::from(b - b'0') assumes ASCII digits: on any other byte the u8 subtraction would underflow. Every caller checks the input first (hex_quantity_decimal, parse_wei_quantity). String::from_utf8(out) cannot fail on hex digits, so unwrap_or_default() is only a formality.

parse_hex is strict on purpose: an odd number of hex digits is refused rather than padded, because padding calldata or storage would shift it by half a byte. parse_wei_quantity caps the input at 80 characters before any conversion, so a huge string cannot make parsing expensive. It accepts 0x alone as zero (a test pins that) and, for parity with Java's BigInteger, a + sign; geth refuses both.

Bootstrapping from an operator-supplied checkpoint instead of the embedded one. explicit validates a root (32 bytes of hex) and a slot (at least 1). bound_anchor reads the marker the engine writes into a data dir created with a caller's checkpoint (sync-anchor.json on mainnet, sync-anchor-<net>.json elsewhere), so a restart without the flags resumes that anchor instead of being refused. The trust argument is in the module doc: the root picks the starting point, and the engine verifies everything after it with sync-committee signatures.

unsafe-ffi lifetimes ffi has no wrapper for create-with-checkpoint, so this calls the C ABI function by Rust path, as the Node addon does (Stop 18). The // SAFETY: comment is the convention for every unsafe block: it states why the call is sound. Here the three CStrings are bound to n, d and r, so they outlive the call, and the engine copies them before returning. CString::new fails on an interior NUL byte, which becomes the engine's own sentinel -1. Note that bound_anchor mirrors the engine's private file name and its keys checkpointRoot/checkpointSlot (host.rs lines 562–620); if the engine ever renamed them, a restart would get the engine's -3 refusal and the daemon's message for it.

--boot-enodes: EL peers the operator knows to be serving snap, handed to the engine through myotis_set_boot_enodes (#465) so a cold start does not wait for discovery. load reads @FILE or takes the argument itself. parse is a pure iterator chain: lines(), cut each at #, flat_map over commas, trim, drop empties, then map(str::to_string) to own the results. It also drops a leading UTF-8 byte-order mark, which trim would not remove because it is not whitespace. The only local check is "not empty": the engine judges every URL, applies the list or refuses it as a whole, and names every bad entry at once.

unsafe-ffi error-handling push serialises the list with serde (which escapes a NUL byte as \u0000, so CString::new cannot fail) and calls the C ABI function in an unsafe block with a SAFETY comment. The engine reports a refusal only as false plus a WARN line in its log ring, so push drains the ring and quotes the lines that contain "boot enodes refused". main.rs flushes the ring just before calling it, so the lines drained are the push's own. If a RUST_LOG filter hides WARN, the message says so instead of quoting nothing.

testing Eight tests: seven that need no engine (comma lists, files with comments, BOM, empty lists, 65 entries passed through unjudged, the refusal quote, a temp file read through load), and one that creates a real engine handle in a temp dir, never starts it, and checks that the engine accepts two good URLs and refuses a duplicate, a garbage entry and a NUL byte by entry number.

Thirty router tests. The engine replies are the shapes pinned by the engine's own golden tests in eljson.rs, so a reshaped engine fails here too. Because this file is mod tests inside rpc, it sees rpc.rs's private items: parse_account, decode_revert_reason, Router's fields.
