myotis-net, part 1: libp2p, req/resp and discovery

From here on, everything is async. This stop covers the consensus-layer side of the crate that does all of Myotis's I/O: the libp2p host that speaks the eth2 req/resp protocols, discv5 discovery, the on-disk peer cache shared with the Java engine, and the new byte counters. The central idea is an actor: one tokio task owns all network state, and everyone else talks to it through channels. The byte-level framing (varints, snappy, Status SSZ, protocol IDs) moved to myotis-wire; it is covered in stop 5.

The crate: what myotis-net is for

myotis-net is the I/O crate of the workspace. Everything that touches a socket, a clock, the file system or the tokio runtime lives here, and the verification crates below it stay "sans-I/O": they take bytes and slot numbers and return verdicts. This stop and the six after it all read this one crate. It has two halves. The consensus layer (CL), in the crate root, finds beacon nodes over discv5, talks to them over libp2p and runs the light-client sync loop (stop 10). The execution layer (EL), under src/el/, speaks devp2p to execution clients (stops 11 to 14).

The manifest makes the layering explicit. Path dependencies point one way only: down to the sans-I/O crates.

Then come the external dependencies, pinned with =. A plain "0.56.0" in Cargo means "0.56.0 or any semver-compatible later version"; "=0.56.0" means exactly that version. The lockfile pins anyway; the = documents that interop with live peers depends on the exact wire behaviour of these releases.

The rest of the list, in short: libp2p-mplex (the second TCP stream multiplexer, more below), discv5 (sigp's discovery), alloy-rlp and hickory-resolver (both used by the EL discovery code), snap, tracing, futures, async-trait, and socket2 plus getrandom for the EL's UDP socket.

The crate has two features:

  • tor is off by default. It turns on three optional dependencies (dep:arti-client and friends), and the manifest picks Arti's TLS backend per target with two [target.'cfg(…)'.dependencies] tables: native-tls off Android, rustls on Android, where the NDK has no OpenSSL. Every #[cfg(feature = "tor")] in the crate sits under src/el/. None of the five files in this stop changes with it.
  • fixture-recorder is test tooling. It is switched on by a small Cargo trick: the crate lists itself as a dev-dependency with the feature on, so tests and examples see it while the shipped library never does.
JVM lens

A Cargo feature is closer to a Gradle source set switched by a build flag than to a runtime flag. Code under #[cfg(feature = "tor")] does not exist in a build without it: no class to load, no dead branch, no dependency on the classpath.

The crate root and its rules: all consensus-layer I/O lives here, the dependency on myotis_consensus runs one way only, every clock read happens in this crate, and logging goes through tracing. Below the doc comment are four narrow libp2p re-exports, the module list, and a re-export of the sync loop's public types. traffic is new since September, as is cl_fork_watch, the consensus-layer fork detector that this stop's files feed (it is read with the sync loop).

modules-cargo Why re-export four libp2p items instead of the whole crate? roost needs exactly these to build a HostConfig. If it took them from its own libp2p dependency, a version mismatch would make them different types, because two versions of a crate never share types. The narrow list keeps the rest of libp2p out of this crate's public API. pub mod codec;, protocols and status are now four-line shims, each a single pub use myotis_wire::eth2::…::*;, so older crate::codec::… paths keep compiling. The real code is in stop 5.

Stale or inaccurate comments

The module doc (lines 1–22) is out of date in three ways. Its module list omits cl_fork_watch, clcache, el and traffic, and it still lists codec, protocols and status as if their code lived here. It describes reqresp as "TCP + noise + yamux", but the host now also speaks mplex and QUIC. And "no global mutable state" (line 21) is no longer true: traffic.rs has a static DISCV5: Mutex<…>, and el::tor, el::dnsdisco and el::request have static switches and semaphores. The ReqRespClient doc in reqresp.rs repeats the claim ("no globals anywhere in this crate").

The libp2p host. It runs TCP (with Noise and either yamux or mplex) and QUIC side by side, with a secp256k1 identity, Identify, a gossipsub with no subscriptions, and one request_response behaviour per eth2 protocol. A single tokio task, the swarm task, owns all network state. Callers hold a cloneable ReqRespClient that sends commands over a channel and awaits one-shot replies. For outbound requests the host only moves raw bytes; sync.rs parses them. For inbound requests it answers status, ping, metadata, goodbye and three "by root" protocols itself, and delegates light-client requests to an optional LcResponder, which is how roost reuses this host as a server.

The caller's side

  • concurrency smart-pointers #[derive(Clone)] ReqRespClient is cheap to clone: an mpsc::Sender (itself a handle) plus three Arcs (the agent map, the TCP-first set and a DNS memo). Every clone talks to the same task.
  • async ownership let (reply, rx) = oneshot::channel(); then reply is moved into the command, so the task now owns the right to answer. self.tx.send(…).await suspends while the 256-slot inbox is full, like BlockingQueue.put but without blocking a thread.
  • error-handling rx.await yields Result<Result<Vec<u8>, RequestError>, RecvError>. .map_err(|_| RequestError::Shutdown)? unwraps the outer layer, and the inner Result is the function's return value as it is.
  • async interior-mutability DNS is resolved here, in async context, because the swarm task's dial path is synchronous and Android lacks /etc/resolv.conf. Inside resolve_dial_addrs the memo is a std mutex that is only locked after lookup_host(…).await has returned. A std guard is not Send, so holding one across an .await would make this future unusable in tokio::spawn.

The address walk: QUIC first, TCP as the fallback

The consensus p2p spec now makes QUIC the primary transport and TCP the fallback, so a discovered peer can come with two addresses (sync::Peer::dial_addrs orders them QUIC first). request_raw_at tries them one at a time, and moves on only when the dial failed. A request that reached a connection and then failed is the peer's answer.

  • ownership iterators-closures addrs.into_iter() consumes the Vec: each addr is moved into request_raw_once, so no address is copied. wire is needed by every attempt, so each call gets wire.clone() and the original stays here. The mut addrs parameter means "I own this vector and may reorder it", which dial_order does in place through &mut addrs.
  • enums-patterns outcome == Err(RequestError::DialFailure) compares a whole Result. That works because RequestError derives PartialEq, and Result<T, E> is PartialEq when both T and E are.
  • domain A peer is put on TcpFirst only when QUIC failed and TCP then reached it. A blip that fails every dial (no network) does not demote a healthy QUIC peer for good.
  • iterators-closures traits-generics addrs.sort_by_key(is_quic) passes a function item where a closure is expected. The key is a bool, and false < true, so TCP addresses (key false) move to the front. sort_by_key is a stable sort, so the order within each transport stays the caller's.
  • interior-mutability error-handling TcpFirst is an Arc<std::sync::RwLock<HashSet<PeerId>>>, shared by the client (which writes on a QUIC dial failure) and the swarm task (which writes on a QUIC timeout or a Nimbus agent). A std lock is fine because no critical section awaits. .unwrap_or_else(|e| e.into_inner()) handles poisoning: if a thread panicked while holding the lock, lock()/read() return Err(PoisonError), and into_inner() takes the guard anyway. For a dial-order hint that is the right call; Java has no equivalent because its locks don't track panics.
  • bytes-strings agent.get(..6) returns Option<&str>: None if the string is shorter than six bytes or byte 6 is not a character boundary. Slicing with &agent[..6] would panic in both cases. The agent string is chosen by the remote peer, so it must never be able to panic this host.
  • borrowing In prefer_tcp, let mut set = set.write()…; shadows the parameter: the first set is the &TcpFirst, the new one is the write guard. The guard drops at the closing brace, after the && expression is evaluated.

ownership enums-patterns Clone because you might need it again. request_in_order takes addrs and wire by value. To be able to retry, the first call gets addrs.clone() and wire.clone(), and the retry consumes the originals. The match arm Err(RequestError::Timeout | RequestError::ConnectionClosed) if … is an or-pattern nested inside Err, followed by a guard. The retry happens only when the swarm demoted the peer while this request was out: the request was lost to a connection this node closed (see demote_stalled_quic below), not refused by the peer.

The owner's side

  • ownership concurrency tokio::spawn(run_swarm(swarm, rx, …)) moves the Swarm and the receiver into the task. SwarmCtx's plain HashMaps need no locks because only this task can reach them. The Java analogue is a Netty EventLoop fed from a BlockingQueue<Command>. The two exceptions, agents and tcp_first, are created here as Arc::default() and cloned: one copy goes into the task, one into the client.
  • async tokio::select! waits for whichever is ready first, the next command or the next swarm event (the event = swarm.select_next_some() arm at line 1532, after the remaining command arms), and drops the other future. Both are cancellation-safe, so nothing is lost. Because the futures are dropped before the handler body runs, the handler may take &mut swarm. The handlers never .await, which keeps the loop responsive.
  • ownership enums-patterns ctx.pending.drain() hands each stored Pending back by value. if let Pending::External(reply) = p takes the sender out, and let _ = reply.send(…) ignores a caller who has already gone away. rx.recv() returns None once every client clone is dropped, so the task also ends when nobody can reach it.
  • enums-patterns enum Pending works like a sealed interface. An outcome completes either an external caller's oneshot or one of the two automatic Status exchanges.

The request-id collision fix

A real bug, and its fix in the types

libp2p numbers outbound requests per behaviour, starting at 1, and this host has thirteen request/response behaviours. When pending was keyed by the id alone, a new peer's auto-Status and a bootstrap request to another peer could share id 1. The second insert evicted the first, so one caller saw "service shut down", and a bootstrap caller could receive Status bytes. Keying by (&'static str, OutboundRequestId), with send_tracked as the only inserter, makes a mismatched key impossible: the protocol that picks the behaviour is the protocol in the key. The fix landed in aa123758; the tests in pending_request_tests mint ids the way the behaviours do and assert that they collide. The inbound budget map in_flight is keyed the same way for the same reason.

  • lifetimes borrowing behaviour_for<'a>(swarm: &'a mut Swarm<…>, …) -> Option<&'a mut RR> returns a mutable borrow into the swarm, tied to the input by 'a. In send_tracked that borrow (rr) is last used on the send_request_with_addresses line, so the next line may use ctx freely. Some(match … { …, _ => return None }) shows return inside an expression.
  • ownership on_outcome is either moved into the map or consumed on the error path, never copied. A reply sender therefore has exactly one owner at every moment.

enums-patterns Some(Pending::AutoStatusV2(peer_id) | Pending::AutoStatusV1(peer_id)) if !ctx.connected.contains(&peer_id) is an or-pattern that binds the same name in both alternatives, plus a guard. Arms are tried in order, so this "stale outcome" arm catches both kinds before the specific arms below it. A v1-only peer answers v2 with UnsupportedProtocol, and the host falls back to v1. Any other failure still settles the peer, so its parked requests are released rather than starved.

A stalled QUIC connection is closed, not just avoided

domain concurrency libp2p's request-response hands a request to any established connection to the peer and cannot steer it by transport. So when a request times out on a QUIC connection (the doc comment above the function records the stall measured against Nimbus), the only cure is to close that connection; the next request dials afresh, TCP first. quic_conns.remove returns whether the id was there, which makes the function idempotent: other requests timing out on the same connection in the same poll do nothing. The Identify handler applies the same rule up front to any peer whose agent is Nimbus.

Reading a response until the peer goes quiet

  • traits-generics async T: AsyncRead + Unpin + Send: any async byte stream that can be polled through &mut (Unpin) and moved between threads (Send). The whole function compiles to a state machine; its 16 KiB chunk buffer lives inside the future, not on a thread stack.
  • async tokio::time::timeout_at(wake_at, io.read(&mut chunk)): if the timer wins, the unfinished read future is dropped, which is cancellation, and no data is lost because a pending read hasn't consumed anything. Before the first byte there is no timer at all. The behaviour-level request timeout (10 s, or 60 s for updates) is the deadline then, which keeps slow, rate-limited servers usable.
  • domain budget is set only for updates_by_range (55 s, under the 60 s behaviour timeout). When it runs out with data buffered, the read completes with the whole chunks that arrived instead of letting the behaviour timeout discard them and charge the peer a failure.
  • error-handling An error after data arrived keeps the buffered response instead of discarding it. The codec in myotis-wire validates it later.

The request side has a newer twin, drain_capped. The three "by root" protocols (blocks, data-column sidecars, payload envelopes) are inbound only and always answered with zero chunks, so their request body is never read: futures::io::copy(io.take(cap + 1), &mut sink()) reads it to EOF and throws it away, up to 256 KiB, without buffering. A light client serves these at all because Nimbus asks every new peer for blocks (and later columns and envelopes) by root, and ends its peer loop, disconnecting, when the protocol cannot be negotiated. The answer is zero chunks rather than ResourceUnavailable because, per the comment in respond_inbound, Nimbus treats an error chunk as a failed request too (the protocol docs are in myotis-wire's protocols.rs).

The behaviour, gossipsub and the Lighthouse ban

  • macros #[derive(NetworkBehaviour)] generates the combined behaviour impl plus a BehaviourEvent enum with one variant per field (BehaviourEvent::StatusV2, …::Gossipsub, …). handle_behaviour_event matches on exactly those variants.
  • domain The gossipsub with no subscriptions is still there, and still only so that /meshsub/ negotiates. Lighthouse reports a peer whose gossipsub upgrade fails as PeerAction::Fatal: the peer id is banned for 12 h, and the whole IP once more than five of its peer ids are banned. That was #422. The test meshsub_negotiates_without_any_subscription plays Lighthouse (a subscribed swarm) against this host and fails on GossipsubNotSupported. If you test from a machine that ran a pre-gossipsub build, the bans can outlive the fix by 12 hours, and a banned host sees healthy nodes as "dial failed" (the repo's CLAUDE.md records this caveat for the cold-start checks).
  • domain metadata_v3 is new: post-Fulu peers ask for v3, and Nimbus drops a peer that cannot answer. updates is advertised outbound-only for a wallet (advertising a protocol you cannot serve gets you sent Goodbye) and Full for a serving host.

TCP with two muxers, QUIC beside it, and every byte counted

  • domain Why mplex. The spec says a TCP client MUST support mplex and MAY support yamux, with yamux preferred where both exist. Nimbus and Lodestar speak only mplex on TCP. A yamux-only host (this one, until recently) completed Noise with every Nimbus node and then died on the muxer proposal, which made Nimbus nodes look dead. SelectUpgrade::new(yamux, mplex) offers both, and its argument order is the preference order. The test pair a_yamux_only_host_cannot_connect_to_an_mplex_only_peer / the_host_connects_to_an_mplex_only_peer_like_nimbus pins both sides.
  • iterators-closures smart-pointers A move closure that clones on every call. .map(move |stream, _| …) moves tcp_meter (an Arc) into the closure. The closure runs once per connection, so it cannot give its captured Arc away; it calls Arc::clone(&tcp_meter) each time, and each CountingStream owns one strong reference.
  • traits-generics The TCP stack and the QUIC stack produce different output types. StreamMuxerBox::new(c) erases each muxer to one boxed type, and or_transport combines the two into a transport that tries TCP or QUIC by address; its output is an Either, flattened by into_inner(). The return type Result<_, Box<dyn Error + Send + Sync>> lets ? convert the Noise config error. QUIC brings its own TLS 1.3 and its own streams, so neither Noise nor a muxer applies there.

The two if dns branches after this closure build the same swarm with and without .with_dns(). They are separate chains because each builder step consumes the builder and changes its type, so a failed DNS step cannot hand the builder back. start_host_with tries with DNS first and falls back with a warning; Android has no /etc/resolv.conf.

The responder: synchronous by design

  • traits-generics concurrency HostConfig holds Option<Arc<dyn LcResponder>>: a shared, thread-safe trait object, like an injected Java interface. Send + Sync as supertraits make every implementation safe to call from the swarm task. The methods are plain fn, not async fn, because respond_inbound runs inline in the event loop; an I/O fetch there would stall every connection. A miss returns None, answered as ResourceUnavailable.
  • domain Two responder details changed. Ping now answers with our metadata sequence number instead of echoing the caller's, so peers re-fetch our real metadata. A Goodbye is answered and then the peer is disconnected, so a public responder does not collect dead connections.
  • domain error-handling A serving host also caps response bytes queued but not yet written at 64 MiB across all connections (MAX_IN_FLIGHT_RESPONSE_BYTES). In on_rr_event, a response that would overflow is swapped for ResourceUnavailable; both terminal events, ResponseSent and InboundFailure, release the bytes. Missing either would leak budget until the responder refused everything.

Shared status

interior-mutability smart-pointers LocalStatus (lines 812–829) is shared between the sync loop (writer) and the swarm task (reader) through an Arc, so it needs a Mutex. *self.inner.lock().expect(…) = s; assigns through the guard, and the guard lives only for that statement. get returns a clone(), so the caller never holds the lock.

JVM lens

SwarmCtx needs no lock and LocalStatus does, for the same reason a Java object confined to one Netty event loop needs no synchronisation while a field shared with another thread does. The difference is that Rust checks the confinement. Moving the SwarmCtx into the task makes it unreachable from anywhere else, and anything the task shares (LocalStatus, AgentMap, TcpFirst) has to be an Arc around a lock, or it will not compile.

discv5 discovery for the consensus layer, in two modes. Client mode (spawn) runs two tasks: a lookup loop (FINDNODE every 15 s, or every 2 s while the sync loop hunts for light-client servers) and a consumer of every ENR heard in NODES responses. smart-pointers async A tokio task is not tied to its handle. Dropping a JoinHandle only detaches the task. So Drop aborts it explicitly. That drops the task's Arc<Discv5>, the last clone goes away, and discv5's own Drop shuts the service and its UDP socket down. In client mode, sync.rs wraps the handle in a DiscoveryGuard that does the same.

domain Design notes from the file: "hearsay" ENRs (heard in NODES responses) are used on purpose; this found the first sepolia peer in 4 s instead of 2 min 12 s, and they are trusted only after a successful Noise handshake. add_enr alone is passive and fails on a bucket full of dead entries, so the re-seed also pings. The CL fork watch gets its evidence from the routing table once per round, not from hearsay, because a relayed record is self-declared and keys are free.

In memory: a plain struct where ranges only widen, three failures evict a peer, and changes only set dirty, so flush writes once per sync round. The only change since September is the Java twin's name in line 2.

  • borrowing let before = self.served.get(addr).copied();. Without .copied(), before would be an Option<&(u64, u64)> still borrowing self.served, and the &mut self call on the next line would not compile. Copying the pair out ends the borrow.
  • bytes-strings traits-generics HashSet::insert and remove return whether something changed, like Java's Set.add, and changed |= accumulates the result. self.served.get(addr) accepts a &str for a String key, because String: Borrow<str>. Vec::contains has no such flexibility, which is why ensure and mark_failure write self.peers.contains(&addr.to_string()) and allocate a String just to compare.
  • concurrency borrowing No synchronisation at all. The mutators take &mut self, and run_sync owns the cache as a local variable, so the compiler guarantees a single writer. It's a non-thread-safe Java object confined to one thread, except the confinement is proven. run_sync builds it with .map(ClPeerCache::load).unwrap_or_else(ClPeerCache::disabled), passing both associated functions as values.

error-handling An atomic write via temp file plus rename. and_then chains two fallible steps without ?. The error is deliberately swallowed, because the file is only a performance cache. There is no file lock, so across processes (for example the Java engine) the last writer wins. let Some(path) = &self.path else { return }; binds a reference into self.

Stale or inaccurate comments

The test ordering_prefers_proven_then_bootstrap (lines 420–421) says the widest range leads because it is "the generous multi-chunk server", which is exactly what the peers() doc (lines 107–109) says width does not show.

New since September. Byte counters per network stack, split into an execution-layer and a consensus-layer pair, so a host running several networks can show each one's data usage (the engine's usage.rs turns the totals into a ledger). A TrafficMeter lives in ChainConfig and is handed to every socket the stack opens. For this stop's half: libp2p TCP is counted on the raw socket, below Noise and the muxer; QUIC is counted per substream above QUIC, because libp2p does not expose its socket; and discv5, which only counts process-wide, has its growth shared out among the meters whose discovery is running.

concurrency interior-mutability add_rx takes &self, not &mut self, and still changes the count: AtomicU64 is interior mutability without a lock, like Java's AtomicLong. That is what lets many connections share one meter through an Arc (which only ever hands out &T). Relaxed ordering guarantees each counter's own updates are not lost, and nothing more, which is all a statistic needs.

discv5: one global counter, shared out with weak references

  • concurrency interior-mutability static DISCV5: Mutex<Discv5Ledger> = Mutex::new(…) is a global initialised at compile time. That is allowed because Mutex::new and Vec::new are const fn. A static must be Sync, and the Mutex is what makes the ledger so. This is the crate's answer to an external global: the discv5 crate's own metrics are process-wide.
  • smart-pointers Weak is Java's WeakReference, with explicit counting. The ledger keeps Weak<TrafficMeter>, so being registered does not keep a meter alive. retain(|w| w.strong_count() > 0) prunes dead entries, and filter_map(Weak::upgrade) turns each live one into a temporary Arc for the duration of the update. The live vector drops those Arcs at the end of the function.
  • bytes-strings saturating_sub clamps at 0. A plain - that underflows panics in debug and test builds, where overflow checks are on, and wraps silently in release. The split is even, with the remainder to the first meter; the test discv5_growth_is_shared_by_the_live_meters_only checks the arithmetic, including a dropped meter and nobody live.
  • error-handling DISCV5.lock().unwrap_or_else(|e| e.into_inner()) again takes the guard even if a panicking thread poisoned the lock. A wrong byte count is better than a panic in a status read.

smart-pointers ownership Registration as a value. Discv5Share::join registers the meter and returns a token; dropping the token unregisters it. It is the RAII shape of Java's try-with-resources, except no try block is needed: the owner (the lookup task) simply holds the token, and when the task ends or is aborted, Rust drops it. Arc::downgrade(meter) is called twice, once for the ledger and once for the token, and w.ptr_eq(&self.meter) finds the token's own entry by pointer identity, like == on Java references. swap_remove is O(1) because order does not matter. Both paths flush first, so bytes from before the change go to the meters that were live then.

libp2p: wrapping a poll-based stream

  • async traits-generics What poll_read is. Under every .await on a byte stream there is a poll_read that returns at once with Poll::Ready(result) or Poll::Pending (after registering the waker in cx). A wrapper implements the same trait and forwards each call; here it adds the byte count when the inner call is Ready(Ok(n)). It is the decorator pattern, as with a Java FilterInputStream.
  • async smart-pointers Pin<&mut Self> and Unpin. Poll methods take the receiver pinned, a promise that the value will not move in memory, which self-referential futures need. To call the inner stream's poll_read, the wrapper needs a Pin<&mut S>. Pin::new(&mut self.inner) builds one, and it is only allowed because the impl requires S: Unpin ("safe to move even when pinned"). With that bound no unsafe pin projection is needed.
  • traits-generics layer: fn(&TrafficMeter) -> &ByteCounter is a plain function pointer (no closure, no allocation) that picks which counter to use. The elided lifetimes mean "the returned reference borrows from the argument". (self.layer)(&self.meter) needs the parentheses so Rust calls the field instead of looking for a method named layer. Line 295 defines cl, which build_swarm passes.

traits-generics smart-pointers CountingMuxer implements libp2p's StreamMuxer with an associated type: type Substream = CountingStream<M::Substream>, so every substream it hands out is a counting one. Poll<Result<T, E>>::map_ok transforms a ready success and passes Pending and errors through. The Arc::clone(&self.meter) comes first because the closure needs its own handle while self.inner is borrowed mutably through the pin. It costs one atomic increment per poll, including polls that return Pending.

Not counted

The module doc lists what the meters miss: IP/TCP/UDP headers, QUIC's own packet overhead and TLS handshake, EIP-1459 DNS lookups, and Tor. With several networks running, discv5's share is an even split, not a measurement.
