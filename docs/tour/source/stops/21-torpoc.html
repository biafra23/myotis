tor-poc: the same stack over Tor

A proof of concept for docs/privacy-and-tor.md, run by hand against live mainnet. It boots an embedded Arti Tor client and runs the unmodified RLPx + eth + snap stack from myotis-net over a Tor stream. Each wallet address gets its own circuit and a fresh throwaway node key, followed by one proof-verified account read. The production change it needed is the most instructive idea in this stop: making the connection types generic over the byte stream.

The production change traits-generics async

The clearnet code was written against tokio::net::TcpStream. To run it over Arti's DataStream, the two connection types became generic over the stream, with a default type parameter so that every existing clearnet caller compiles unchanged. The code lives in myotis-net/src/el/rlpx/transport.rs (Stop 11 covers it in full):

impl<S: AsyncReadExt + AsyncWriteExt + Unpin> reads as "for any tokio byte stream that may be moved between polls". The extension traits are implemented for every AsyncRead/AsyncWrite type, and Arti's DataStream implements those when its tokio feature is enabled. dial stays in a separate impl RlpxConnection<TcpStream> block (line 65), because only TCP can be dialled that way. Since the September tour the struct also carries traffic: Option<Arc<TrafficMeter>>, the data-usage counter; handshake_over passes None to the new handshake_metered, so tor-poc counts nothing.

JVM lens

It is like a protocol class written against InputStream/OutputStream that you hand a Tor socket's streams, with one difference. Java erases generics to one implementation that dispatches at run time; Rust monomorphises, compiling a specialised copy of the handshake for S = DataStream next to the TcpStream one, with no virtual calls. The default parameter (S = TcpStream) is something Java generics cannot express.

Generic code is not automatically behaviour-neutral. A TcpStream sends each write at once; a DataStream buffers until it is flushed. The handshake therefore flushes before it waits for the peer's answer:

async error-handling write_all and flush come from AsyncWriteExt, the bound on S. Each returns a future of io::Result<()>; .await drives it, .map_err(…) turns the io::Error into the function's String error, and ? returns early. On TCP the flush is a no-op. The tor-poc README records what happened without it: the peer never saw the auth message, and every Tor attempt ended with "early eof" while reading the ack.

It boots Arti, measures a clearnet baseline over the same stack (so a later Tor failure can be blamed on the Tor path), probes peers over Tor, and then performs per-address isolated, proof-verified snap reads. It is not production code: there is no quarantined peer pool, and the state root is the peer's claimed head, not a beacon-anchored one. It is fully sequential, with no tokio::spawn anywhere. #[tokio::main] is still required, because Arti uses the current runtime.

The core flow

  • traits-generics async Inference picks the type. stream is an Arti DataStream, so handshake_over(stream, …) is instantiated with S = DataStream, and conn is a RlpxConnection<DataStream>. No type is written anywhere.
  • ownership smart-pointers Ownership down the layers. stream moves into the RLPx connection, and conn moves into the eth session. Each layer owns the one below, like wrapping Java streams, except that the old variable becomes unusable. Arc::clone(&key) hands one reference-counted handle to handshake_over, and the original key stays usable for key.public_key_bytes(), which auto-derefs through the Arc. peer.pubkey, a [u8; 64], is copied.
  • error-handling async Two error layers. timeout(…) wraps the handshake, so the result is Result<Result<…, String>, Elapsed>. The first map_err(…)? handles the timeout, and the second handles the handshake's String error. On timeout, the inner future and the stream it owns are dropped, which closes the circuit.
  • iterators-closures borrowing An FnMut closure. since updates its captured mark, so calling it needs &mut since, hence let mut since. While since is still going to be called, mark is mutably borrowed by it and cannot be used elsewhere. Instant is Copy, so mark = t0 copies.
  • traits-generics A conversion into a trait object. prefs.set_isolation(isolation) is declared as fn set_isolation<T: Into<Box<dyn Isolation>>>(…), so the Copy IsolationToken is converted into a boxed trait object inside Arti. One token per address means one circuit per address.
  • domain The fourth argument. EthSession::handshake(conn, &…, eth_cfg, None): the None is served_range, the block range a serving node would advertise. tor-poc is outbound-only and serves nothing.

traits-generics borrowing EthSession<arti_client::DataStream> names the generic type explicitly in a return position. head_number<S: …> repeats the impl's bounds so it can call EthSession<S>'s methods, and takes &mut because requests change the session's state (the request id and the frame codec). .map_err(|e| anyhow!("{e}")) turns myotis-net's String errors into anyhow::Error, because String does not implement std::error::Error.

Choosing a peer: an explicit lifetime

  • lifetimes borrowing Why 'a. The function returns a reference but takes several reference parameters (tor, peers, eth_cfg), so the elision rules cannot guess which one the result borrows from. 'a says: from peers. The caller must then keep the slice's owner alive while it uses the result.
  • enums-patterns error-handling Nested results in one match. Ok(Ok(mut session)) / Ok(Err(e)) / Err(_) peels the nested timeout result; the mut inside the pattern makes the binding mutable. best.map_or(true, |(_, h)| head > h) means "no best yet, or better than the best". best is an Option<(&Peer, u64)>, which is Copy, so map_or consumes a copy and best stays usable.
  • ownership async Where the session goes. session is owned by the match arm. When the arm ends, it is dropped, and with it the RLPx connection and the Tor stream. The function returns only the &Peer; query_over_tor later opens a new circuit to it.

borrowing ownership &[&Peer] is not &[Peer]. ordered is a Vec<&Peer>, but pick_working_peer wants a slice of owned Peers. Peer is not Clone, so ordered_owned rebuilds them field by field (name.clone(), plus copies of the Copy fields), and the &Peer that comes back borrows from ordered_owned. That is the 'a above in action. live.clone() copies only the vector of references, not the peers.
