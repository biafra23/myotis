myotis-evm, part 2: simulation, tracing and fixtures

Stop 7 showed the one verified EVM run behind eth_call. This stop covers what has been built on top of that run since September: the full JSON-RPC transaction object (TxRequest, with EIP-7702 authorization lists), the two tracers of debug_traceCall, and eth_simulateV1, which runs whole blocks of calls on top of a verified block. It ends with the test machinery that replays a real mainnet RAILGUN shield from a recorded world: every account, slot and bytecode the EVM read, saved as JSON and served back by an oracle that refuses anything it was not given. The Rust lessons are interior mutability on one thread (RefCell recorders behind shared references), enums that carry data, and test-only code that never reaches the shipped library.

One run, several recorders

None of these files existed in the September tour. They share one design idea. revm lets you attach an inspector to a run: an object whose hooks revm calls before every opcode (step), when a call or create frame opens and closes, when a log is emitted, and on SELFDESTRUCT. executor.rs (stop 7) has exactly one inspector type, RequestInspector. It holds a set of optional recorders, and each hook forwards to whichever ones are present. The tracer of debug_traceCall and the log recorder of eth_simulateV1 are two of those recorders.

Every field is a shared reference, &'a. The inspector owns nothing; the request's code owns each recorder on its stack and lends it to the inspector for the run. But recorders must change as the run goes on, and a shared reference does not allow mutation. So each recorder keeps its state in a RefCell and mutates it through &self. That is the pattern you will see in trace.rs and simulate.rs.

Why RefCell and not MutexA RefCell<T> checks borrows at run time: borrow_mut() hands out a RefMut guard, and a second borrow_mut() while the first guard lives panics. It costs a counter, not a lock, and it is not Sync, so a type holding one cannot be shared between threads. That fits: one EVM run executes on one blocking thread from start to end (the reader in myotis-net wraps each simulate and trace_call call in its blocking helper). If anyone tried to move a &TraceRecorder to another thread, compilation would fail. The oracle, by contrast, is shared across threads behind Arc<dyn SnapStateOracle>, whose trait requires Send + Sync; that is why RecordingOracle later in this stop uses a Mutex.
Java/Kotlin viewAn inspector is a listener interface with default no-op methods, like an EventListener in OkHttp. The difference is ownership: in Java the listener would keep references to its collaborators forever. Here the borrow checker proves that every recorder outlives the run that borrows it.

One more piece from stop 7 matters here: the prefetch loop (converge_runs). It runs the EVM several times, first in a discovery mode where missing state reads as a placeholder zero, then for real. A recorder therefore sees several runs. Each one is reset (or created fresh) at the start of every run, so what it holds when the loop settles describes the run whose answer is returned, never a discovery pass.

TxRequest is the JSON-RPC transaction object (geth's TransactionArgs) in the form the executor applies it. It exists because of #509: a type-4 eth_estimateGas whose authorizationList was silently dropped ran against an account with no code, answered about 59k gas for a transaction that needs several hundred thousand, and the wallet's real transaction ran out of gas on chain. The module doc states the rule this file enforces: every field that changes the answer is applied, or the request is refused by TxRequest::validate. Each field's meaning follows geth, so a wallet gets the same answer from Myotis as from a public node.

  • enums-patterns An enum that makes a bad state unrepresentable. geth refuses gasPrice together with the EIP-1559 fields, so Fees holds one fee model or none. Compare a Java class with three nullable fields, where "both set" would be a state every reader has to check for. Each variant carries its own data, like a Kotlin sealed class with data-class subclasses.
  • enums-patterns traits-generics #[derive(Default)] on an enum needs one variant marked #[default]. All fields are u128, so the enum can also derive Copy: it is copied bit for bit, like a primitive.
  • enums-patterns ownership match *self matches on the value behind the reference. That is allowed only because Fees is Copy: the bound gas_price is a copied u128. For a non-Copy type you would write match self and get references to the fields instead. DynamicFee { max_fee_per_gas, .. } ignores the other field with ...

The struct itself (lines 105–130) is plain data: from, to: Option<[u8; 20]> (None is contract creation), data, value, and then a row of Options, one per optional JSON field. TxRequest::call builds the plain four-field subset that older entry points carry, with every other field absent. The transaction type is a u8 with five constants, not an enum. A plausible reason, which the code does not state: the type comes from the request and may be any byte (a test feeds it 0x7e), and validate must be able to hold it in order to refuse it with a message. tx_type() returns the explicit type, or derives one in revm's order: an authorization list makes 4, EIP-1559 fees make 2, a non-empty access list makes 1, anything else 0.

  • enums-patterns borrowing Matching a tuple with guards. (&self.authorization_list, ty) builds a temporary tuple of a reference and a u8. Matching through the reference means list binds as &Vec<Authorization>: nothing is moved out of self, which a &self method could not do anyway. Arms are tried top to bottom, and an if guard can reject an arm whose pattern matched. The last arm, _ => {}, makes the match exhaustive.
  • domain enums-patterns Three kinds of "nothing". For both lists, None means "the field was absent" and Some(vec![]) means "an empty list was sent". They are treated differently: an empty access list is accepted because it changes nothing, but an empty authorization list is refused, as EIP-7702 requires.
  • error-handling validate returns Result<(), String>: success carries nothing, failure a message. The executor turns that string into a permanent refusal. The remaining checks (lines 225–233) refuse a type-4 creation and a nonce of u64::MAX (EIP-2681).
  • testing The inline #[cfg(test)] mod tests (lines 238–349) pins each contradiction by the text of its error, with unwrap_err().contains(…).

debug_traceCall's two tracers, as geth defines them: callTracer (the tree of call frames, with gas, input, output, errors and optionally logs) and prestateTracer (every account and slot the run touched, as it stood before the run). The tracing runs over the same verified run and prefetch loop as eth_call. Only the options listed in the module doc are served; the host refuses every other one, and diffMode is not served. The executor's trace_call (stop 7's file) builds a TraceRecorder, runs the loop with it, and then assembles the answer: the call tree, or the prestate read back from the run's database.

  • enums-patterns Options live inside their variant. onlyTopCall only exists for the call tracer, so it is a field of Tracer::Call, not a loose flag beside an enum. The recorder asks questions like matches!(self.tracer, Tracer::Call { only_top_call: true, .. }): a pattern with a literal inside it, evaluated to a bool.
  • smart-pointers enums-patterns Why Box<CallFrame>. An enum value is as large as its largest variant. A CallFrame is a big struct (several Vecs and Options), while a BTreeMap is a small handle to heap data. Boxing the frame moves it to the heap and keeps Trace small; Clippy's large_enum_variant lint suggests exactly this. Java never faces the question, because every object is behind a reference already.

The recorder is TraceRecorder { tracer: Tracer, state: RefCell<State> } (lines 161–164). State holds a stack of open frames, the finished root, the depth, a log counter, and the prestate's Touched sets. reset writes *self.state.borrow_mut() = State::default(): assigning through the RefMut drops the old state and puts a fresh one in its place. In step, a prestate run peeks at the stack before SLOAD/SSTORE, the EXT* opcodes, BALANCE, SELFDESTRUCT and the four call opcodes to learn which accounts and slots will be touched.

  • iterators-closures ownership A lazy argument. input: impl FnOnce() -> Vec<u8> is a closure that produces the calldata. The executor passes || inputs.input.bytes(context).to_vec(), so the copy is made only on line 267, when the frame is actually recorded. A prestate run, and the inner frames under onlyTopCall, return early and never call it. FnOnce is the weakest closure bound: the closure may be called at most once, which is all this needs. In Kotlin you would pass a () -> ByteArray lambda for the same reason.
  • interior-mutability borrowing let mut st = self.state.borrow_mut(); holds the RefMut guard until the function returns, early return included. The borrow is released when st goes out of scope.
  • ownership enums-patterns Building a tree without parent pointers. Open frames live in st.stack, a Vec. When a frame ends, pop() moves it out of the stack by value. let Some(mut frame) = … else { return }; is a let-else: bind on the matching pattern, otherwise run the else block, which must leave the function. The finished frame is then moved into its parent's calls vector, or becomes the root. Each frame has exactly one owner at every moment, so no Rc or parent reference is needed. A Java version would typically keep a mutable parent pointer in every node.
  • borrowing st.stack.last_mut() is a mutable borrow of the last element, used once for push. The match arms show why it is Option: an empty stack means the frame was the top one.
  • domain A failed frame resets log_count to the mark taken when it began, because the EVM discards a reverted frame's logs and their indexes with it. After the run, call_tree also clears the logs of every failed frame and of everything under it (clear_failed_logs, a short recursion over &mut frame.calls).

error-handling bytes-strings unpack_revert decodes a revert's Error(string) the way geth does. The payload comes from contract code, so every offset in it is untrusted. Each step uses a tool that returns None instead of panicking: body.get(range) rather than body[range] (slice indexing panics when out of bounds), checked_add rather than + (which panics on overflow in debug builds), and usize::try_from(…).ok(). The ? operator works on Option too: inside a function returning Option, x? returns None early. String::from_utf8_lossy replaces invalid bytes rather than failing, and into_owned turns its Cow into a String. The rest of the file maps revm's InstructionResult to geth's error strings (error_string), names Panic(uint256) codes, and lists the accounts geth's prestate tracer looks up before the run (tx_start_accounts, which recovers each EIP-7702 authority from its signature).

eth_simulateV1 (#716), following geth's internal/ethapi/simulate.go. A request lists blocks; each block has blockOverrides (number, time, gas limit, fee recipient, base fee, withdrawals …), stateOverrides and a list of calls. The simulation starts from a verified block N, whose state every read proves against N's state root. It then builds N+1, N+2, … that exist only inside this request: each call's state changes carry over to the next call and the next block. The answer gives each block's header fields and each call's return data, logs, gas and error, in geth's words and error codes. The module doc (lines 1–56) is also a precise list of what this node cannot compute and therefore refuses: a simulated block's state root and hash (they need trie nodes no proof carries), the blob base fee, requestsHash, Amsterdam blocks, withdrawals on Gnosis, and state overrides of precompile addresses.

Settling the chain before anything runs

The request types are plain structs of Options that derive Default: BlockOverrides has one Option per geth field, so "not overridden" is None. sanitize_chain fills in what the caller left out, as geth does.

  • ownership borrowing Borrowed input, owned output. The function receives &[SimBlock], a borrowed slice, and must return completed blocks. It cannot change the caller's blocks, so it clones each one (block.clone()) and edits the copy. The new block shadows the loop variable of the same name; shadowing is common in Rust and creates a new binding rather than reassigning.
  • borrowing let overrides = &mut block.block_overrides; borrows one field of the local block mutably. The borrow is last used on line 379, so by line 391 it has ended and out.push(block) may move the whole block into the vector. The compiler tracks the end of a borrow by its last use (non-lexical lifetimes), not by the closing brace.
  • enums-patterns *overrides.number.get_or_insert(prev + 1): get_or_insert stores the value if the Option is None and returns &mut to its content either way; the * copies the U256 out (it is Copy). The match overrides.time has a guarded arm, Some(time) if time <= prev_time, whose body is a return. A return expression has type ! ("never"), which fits any arm type, so the match still evaluates to a u64.
  • methods BlockOverrides { number: …, time: …, ..BlockOverrides::default() } is struct update syntax: name some fields, take the rest from another value. It replaces a builder in many Rust codebases. A gap between block numbers is filled with empty blocks 12 seconds apart, as geth does.

plan_blocks then picks each block's fork rules with spec_for (stop 7) and refuses, before any state is read: a difficulty override, an Amsterdam block, a base fee above 264−1, a state override of a precompile's address, and withdrawals on Gnosis.

Where simulated writes go

  • lifetimes A struct that borrows. SimDb<'a> holds two references: to the verified OracleDatabase and to the recorder's refusal cell. The lifetime parameter says "a SimDb cannot outlive what it points to". In impl DatabaseRef for SimDb<'_>, '_ means "some lifetime I don't need to name".
  • traits-generics revm's DatabaseRef is a read-only database trait whose methods take &self. type Error = OracleError; is an associated type: each implementation picks its error type once, instead of the trait being generic over it. Three methods delegate to the base; only block_hash_ref adds behaviour.
  • interior-mutability block_hash_ref takes &self but must record why it refused. It does so through the shared &RefCell<Option<String>>, which the recorder also holds. get_or_insert_with(|| format!(…)) keeps the first refusal, and the closure (and its format! allocation) runs only when the cell is still empty.
  • domain type SimCache<'a> = CacheDB<SimDb<'a>>. revm's CacheDB keeps its own maps of accounts and storage over a read-only database: reads fall through to SimDb once, and every write stays in the CacheDB. That is how "state carries from call to call" while nothing is ever written into a cache another request reads. The cache lives for one pass of the prefetch loop and is then dropped.

The recorder

SimRecorder (lines 537–541) has a trace_transfers flag and two cells: refusal: RefCell<Option<String>> and state: RefCell<SimState>. SimState holds a stack of per-frame log vectors (geth's simulate tracer drops a failed frame's own logs), the next log index in the block, each open frame's last opcode and stack height (for geth's error wording), and the set of EIP-2935 history slots that hold a simulated block's unknown hash.

  • interior-mutability Ending a borrow early. drop(st) releases the RefMut on state before self.refuse(…) runs. refuse borrows the other cell, refusal, so today the two borrows would not collide. The explicit drop keeps the state borrow from overlapping anything refuse might do later. With RefCell, an overlap would compile and then panic at run time with BorrowMutError, so short borrow scopes are the habit to keep.
  • domain Refusing a read in flight. Returning true tells RequestInspector::step to end the frame with InstructionResult::Stop; every frame above it stops at its next step, because the first check sees the refusal. Two reads are refused this way: BLOBBASEFEE without a blobBaseFee override, and an SLOAD of a poisoned EIP-2935 slot. The third, BLOCKHASH of a simulated block, is refused by SimDb above.
  • error-handling if let Ok(slot) = interp.stack.peek(0) ignores a stack too short to peek at: the opcode will then fail on its own.

The frame hooks mirror geth's tracer. call and create push an empty log vector for the new frame, and record an ether transfer as an ERC-7528 log under traceTransfers (a CREATE's address is only known when it ends, so its log's third topic is patched then). end pops the frame's logs; if the frame failed, it clears them and gives their indexes back, otherwise it appends them to the parent's vector. When no parent is left, the logs are the finished call's.

Any module of the same crate may write impl EvmExecutor; field access still follows visibility, which is why oracle and runs are pub(crate) in the struct. It feels like a Kotlin extension function, but these are real methods with access to crate-visible fields.
  • error-handling The function is a pipeline of ?: cancellation, limits, sanitizing, planning, the fork of the base block, and each call checked as a transaction object (check_tx, stop 7), all before a single state read.
  • iterators-closures borrowing The last statement hands converge_runs a closure that borrows db, base, opts, blocks and plans from this stack frame. converge_runs takes impl FnMut(Option<&CodeNeeded>) -> Result<T, EvmError> and calls it once per pass. So for a simulation, a "run" of the prefetch loop is the whole simulation, every block and every call.

One call

Run::call (lines 1093–1228) applies geth's checks in geth's order: the block gas limit, the shared budget (SIMULATE_GAS_BUDGET, the same 30M-gas ceiling (VIEW_CALL_GAS) one eth_call has, playing the role of geth's RPC gas cap), nonces and fee caps under validation, init code size, and geth's buyGas balance check. Then it runs the call.

  • borrowing Reborrowing a &mut. cache is a &mut SimCache parameter. with_db is generic over its argument, and passing cache itself would move the mutable reference into the builder (a &mut is not Copy), leaving cache unusable afterwards. &mut *cache creates a new, shorter mutable borrow instead. The EVM is built inside a block, so it is dropped at the } on line 1186; the borrow ends there and credit(cache, …) on line 1200 may use the cache again. When the parameter type is a concrete &mut T, as in credit, the compiler inserts this reborrow for you.
  • methods ownership A consuming builder. Context::mainnet().with_db(…).with_block(…).with_cfg(…) takes each value by ownership and returns a new type each time. The builder keeps what it is given, so the shared block_env and cfg are cloned for every call.
  • concurrency self.executor.runs.fetch_add(1, Relaxed) counts EVM runs through a shared reference with an atomic. Relaxed ordering is enough for a statistic that no other memory access depends on.
  • error-handling The order of the checks after the run matters: cancellation first, then a refusal the recorder raised, and only then revm's own result, so a refused read is reported as a refusal rather than as whatever revm made of the stopped frame.

The rest of call matches revm's ExecutionResult. Success { output, logs: receipt_logs, .. } renames a field while destructuring it. A revert becomes SimCallError with code 3, geth's decoded reason (unpack_revert from trace.rs) and the raw payload; a halt uses the top frame's last opcode for geth's wording, and adds geth's note when the gas was capped. block_transaction (lines 1255–1278) builds the unsigned transaction geth puts in the block, and hashes its encoding from encode.rs.

  • ownership Why zero is a closure. Line 34 defines let zero = || encode_u64(0);. Each vec![…] takes ownership of its elements, and the zero signature fields v, r, s appear three times. One Vec<u8> cannot be moved into three places, so each zero() call makes a fresh one. The other fields appear in several arms, but only one arm runs, so each is moved at most once and needs no clone.
  • enums-patterns let fields = match tx.tx_type { TYPE_LEGACY => { return …; } … }: matching a u8 against const names works because constants may be used as patterns. The legacy arm returns from the whole function, because a legacy transaction has no type byte in front.
  • iterators-closures tx.authorization_list.iter().flatten() (and the same for the access list on line 36) iterates an Option<Vec<T>>: iter() on an Option yields zero or one item, and flatten turns that one Vec into its elements. None becomes an empty list with no special case.
  • modules-cargo pub(super) makes these functions visible to the parent simulate module and nowhere else.

Recorded worlds: keeping test tooling out of the library

The remaining files are test tooling. They solve one problem: how do you test the EVM against real mainnet state (a RAILGUN shield touches WETH, the RAILGUN proxy, its implementation, a RelayAdapt7702 delegate and more) without a network in the test? The answer is to record once and replay many times. A recorder runs the transaction through the live engine's verified read path and keeps every account, slot and bytecode the EVM read. The replay serves exactly that world and fails any read outside it.

None of this may ship in the engine library that goes into the Android and iOS apps. Three pieces of Cargo configuration keep it out.

  • modules-cargo testing cfg(test) is per crate. It is set only while compiling this crate's own tests. myotis-net's example cannot see a cfg(test) item of myotis-evm, so the fixture module is also compiled under feature = "fixture". The feature turns on serde_json through "dep:serde_json": an optional dependency that exists only when the feature is on. Gradle's testFixtures plays a similar role.
  • modules-cargo A crate that depends on itself. myotis-net lists itself as a dev-dependency, with its fixture-recorder feature on. Dev-dependencies apply only to tests, examples and benchmarks, so cargo test and every example build myotis-net with the feature, and the library the engine links does not. The feature in turn enables myotis-evm/fixture and the #[cfg(feature = "fixture-recorder")] method ElReader::head_evm_oracle the recorder needs. The example has no [[example]] entry: Cargo discovers every file in examples/ on its own.

The root of the recorded-world module. Its doc gives the whole design in a paragraph: a RecordingOracle keeps every answer, an EvmFixture holds the world with its block and request and round-trips through JSON, and EvmFixture::oracle serves only that world. It declares the three submodules (older mod.rs layout: the parent's code is in fixture/mod.rs), re-exports what callers need, and defines the bisection both the recorder and the replay use, plus a hex helper.

  • enums-patterns name @ pattern. Ok(result @ ExecutionResult::Success { .. }) checks that the value is a Success and binds the whole value to result, not just its fields. The second arm nests or-patterns: Ok(_) | Err(EvmError::IntrinsicGasTooLow { .. } | EvmError::FloorDataGasTooLow { .. }) means "any other outcome of a run, or one of these two errors".
  • error-handling Result<Option<ExecutionResult>, String> has three outcomes: "runs at this gas" (Ok(Some)), "does not run at this gas" (Ok(None), a revert, a halt or too little gas), and "this is not an answer" (Err, for example a read the recording never made). Treating the third as a "no" would let a bisection silently converge on a wrong limit.
  • ownership let mut limited = tx.clone();: the caller's request is borrowed, so the function clones it to set gas. overrides.clone() is needed because run_tx takes its StateOverrides by value.

lowest_limit_that_runs bisects between 0 and the executor's budget with a closure runs = |gas| runs_at(…).map(|r| r.is_some()), propagating the Err case with ?. One shared bisection means the replay makes exactly the runs the recording made, so it reads exactly the recorded state. run_tx itself is in executor.rs, also behind cfg(any(test, feature = "fixture")): it runs once at a given limit and returns revm's raw result, skipping the call path's checks.

RecordingOracle wraps any Arc<dyn SnapStateOracle>, answers every read from it, and keeps a copy of each answer in a RecordedWorld: accounts (with None for a proven absence), storage by account and slot, and bytecode by hash. It adds no verification of its own; it only observes what the inner oracle verified. Its doc points out two traps. It does not forward prefetch_batch, because a prefetch writes straight into the executor's caches and would bypass the recorder (the trait's default, a no-op, applies instead). And it must be used over empty caches, because a value already cached is never read again.

  • borrowing lifetimes Returning a borrow of yourself. bind(&mut self, …) -> Result<&mut RecordedWorld, OracleError> hands back a mutable reference into self. Lifetime elision ties the output's lifetime to &mut self, so the caller can write into the world exactly as long as it holds the recording. The check comes first: get_or_insert fixes the state root on the first read, and a read at any other root is an error, since a world mixed from two roots is a state no block ever had.
  • enums-patterns slot.map(|s| s.to_be_bytes::<32>()) converts Option<U256> into Option<[u8; 32]> for the error. ::<32> is the "turbofish", naming a generic parameter (here a const generic, the byte count) at the call site.
  • concurrency interior-mutability Why a Mutex here. SnapStateOracle requires Send + Sync, because oracles are shared between threads behind Arc. A RefCell field would make RecordingOracle non-Sync and the impl would not compile. So the recording sits in a Mutex<Recording>, reached through a small lock() helper (lines 75–79) that recovers from a poisoned lock with unwrap_or_else(|poisoned| poisoned.into_inner()): the maps stay consistent because each insert is a single call.
  • concurrency borrowing Not holding the lock across the slow part. The inner fetch (a network round trip in production) happens before the lock is taken. self.lock().bind(…)?.accounts.insert(…) is one statement: the MutexGuard is a temporary that lives until the ;, so the lock covers the bind and the insert and is released right after. If bind fails, ? returns early and the guard is dropped on the way out.
  • ownership account.clone(): the answer goes into the map and back to the caller, so one of the two needs its own copy. A U256 is Copy, so value needs no clone. Bytecode is content-addressed, so it is stored without binding to the state root.
  • domain fetch_block_hash (lines 92–99) is forwarded but not recorded: a world holds state, not headers. A replay of a run that needed the header chain for BLOCKHASH fails there instead of answering from nothing.

EvmFixture: a recorded world as a deterministic JSON file (sorted keys, lowercase hex, so a re-recording diffs cleanly), and ReplayOracle, which serves it. The fixture holds the block context, the request exactly as a wallet sends it, the sender's synthetic balance as a stateOverride, free-form meta and measured sections, and the world. The reader is strict: an unknown key, a bytecode that does not hash to its key, or a request field the reader cannot apply is an error, never skipped.

Stale or inaccurate commentsThe layout above lists the block fields without parentHash, but to_json writes it (line 105) and from_json accepts it (line 152), as an optional field for files recorded before BLOCKHASH was served. The order shown is a schema, not the file's order: the file's keys are sorted (the committed fixture begins with "accounts"), because serde_json's Map is a sorted map unless its preserve_order feature is on.
  • enums-patterns A guard on the root. Some(account) if state_root == &self.world.state_root => Ok(account.clone()) serves a recorded account only at the recorded root. Everything else, including an unrecorded address, falls to _ and becomes StateUnavailable. The doc explains why "absent" would be the wrong default: a missing entry is not evidence of absence, and treating it as absence describes a world no block had.
  • ownership account is &Option<OracleAccount> borrowed from the map, and the trait returns an owned value, so it is cloned. The EMPTY_CODE_HASH shortcut serves empty code for every codeless account without recording it.
  • error-handling .ok_or(OracleError::BytecodeUnavailable { … }) builds the error value even on success. ok_or_else(|| …) would build it only on failure; for a small enum the difference does not matter.
  • error-handling iterators-closures transpose. field("gas").map(|v| quantity_u64(v, k)) gives an Option<Result<u64, String>>: maybe absent, and if present maybe malformed. .transpose() flips it into Result<Option<u64>, String>, so a single ? propagates the parse error and leaves an Option.   • enums-patterns The fee model is chosen by matching a tuple of three Options. The first arm refuses gasPrice together with either EIP-1559 field; the order of the arms makes the last one, (None, cap, tip), mean "at least one 1559 field". data and input are both accepted, and must agree when both are present.
  • iterators-closures borrowing The closures field, optional_u64 and optional_u128 borrow obj from the enclosing function. optional_u128 spells out its return type, Result<Option<u128>, String>, which documents the transpose it ends with.

traits-generics lifetimes fixed<const N: usize> is generic over a number: one function serves 20-byte addresses and 32-byte hashes. Vec<u8>::try_into::<[u8; N]>() succeeds only if the length is exactly N. The type expected at the call site picks N (a struct field of type [u8; 32], say), or a turbofish names it, as in fixed::<32>(k, "a storage key") on line 429. Next to it, fn object<'a>(value: &'a Value, …) -> Result<&'a Map<…>, String> (line 480) names its lifetime explicitly: with two reference parameters (value and what), elision could not tell which one the result borrows from.

The first and so far only fixture's domain code: a RAILGUN "shield ETH" through a fresh EIP-7702 account, built byte for byte the way the RAILGUN wallet SDK builds it (the transaction #509 reported, with throwaway keys). The sender sends value to a fresh "ephemeral" account in a type-4 transaction whose one authorization delegates that account to the RelayAdapt7702 contract. Running the delegate's code, the account calls itself to wrap the ETH into WETH and shield it into RAILGUN, authorized by the ephemeral key's EIP-712 signature. The file also defines the variants a replay checks, measure (everything the tests assert), and record_shield, the recording procedure with its self-check.

  • domain Two signatures by one key. The EIP-712 signature (lines 133–139) authorizes the execute payload inside the contract. The EIP-7702 authorization (authorize, signed over keccak(0x05 ‖ rlp([chain_id, delegate, nonce])) via revm's signature_hash) installs the delegation. signature[64] += 27 turns the recovery id into the 27/28 form the contract's ECDSA recovery expects.
  • error-handling .map_err(|e| e.to_string())? converts the key's error type into this module's String errors, then propagates it. Test tooling can afford string errors; the library's own errors are typed enums.
  • ownership TxRequest::call(…) returns an owned request; let mut request then sets the two extra fields. ShieldTx { request, ephemeral, payload_hash } uses field-init shorthand and moves the request into the result.

ownership borrowing Field order in a struct literal is evaluation order. retry_from_delegated(&shield) borrows shield, and the last field, shield, moves it. Fields are evaluated in the order written, so the borrow ends before the move. Write shield first and the compiler reports "borrow of moved value". The struct's declared field order does not matter here; only the order in the literal does.

measure (lines 491–555) runs the shield and its variants: the shield's estimate, a run at it, the lowest limit that runs; the estimate without the authorization list (#509's wrong answer); the broadcaster's requireSuccess = false multicall, which swallows a failed call; and the retry from an account a failed first attempt left delegated. It defines four local closures (run, runs, estimate, lowest) that capture exec, block and accounts by reference and add a label to every error. ShieldEvents::of reads the outcome from the logs: WETH's Deposit, RAILGUN's Shield, and the ephemeral account's CallError.

  • testing A recording that checks itself. record_shield first runs measure through a RecordingOracle over fresh, empty in-memory caches, reads the coinbase too, and checks that the sender and the ephemeral account were read and are absent on chain. Then it builds the fixture and, as shown, runs measure again over a new executor whose only state is fixture.oracle(). Any difference between the two ShieldMeasurements fails the recording. A fixture that would not replay is never written.
  • traits-generics replayed != live works because ShieldMeasurements derives PartialEq; {replayed:?} needs Debug. Both are derived on almost every data type in this crate for exactly these two uses.
  • smart-pointers Arc::new(fixture.oracle()) creates an Arc<ReplayOracle>, which coerces to the Arc<dyn SnapStateOracle> that EvmExecutor::new expects. Earlier in the function, Arc::clone(&recording) as Arc<dyn SnapStateOracle> does the same explicitly while keeping a typed handle, so the function can still call recording.recorded().
  • enums-patterns smart-pointers A recursive enum. Tuple(Vec<Abi>) contains more Abi values. That is fine because a Vec stores its elements on the heap: the enum's own size stays fixed. A variant Tuple(Abi) without indirection would be rejected as a type of infinite size, and you would need Box<Abi>.
  • iterators-closures items.iter().any(Abi::is_dynamic) passes a method as a function value: Abi::is_dynamic has type fn(&Abi) -> bool, exactly what any wants for an iterator of &Abi.
  • domain The free function encode below (lines 696–710) does Solidity's head–tail ABI encoding: static items go into the head in place, dynamic ones leave a 32-byte offset in the head and their bytes in the tail. A golden test compares the result byte for byte with an independent Python encoder (relay_adapt_7702_golden.json, loaded with include_str!).

macros methods const fn h20 turns a 40-digit hex string into an address at compile time, so pub const MAINNET_WETH: [u8; 20] = h20("c02a…") costs nothing at run time. A const fn may only do what the compiler can evaluate: hence a while loop with an index instead of a for loop (which would call the iterator trait's methods, not allowed there), and a nested const fn nibble. A panic! or failed assert! during constant evaluation is a compile error, so a typo in an address constant stops the build.

The replay tests for the committed fixture, rust/testdata/evm/relayadapt7702-shield.json. They run measure against the recorded world alone, compare with what the recorder measured live, and assert #509's acceptance: the estimate is a limit the whole shield runs under, the old estimate without the authorization list is not, a swallowed failure cannot lower the estimate, and the retry completes. Two tests count reads to prove the prefetch waves of #532 fetch everything (stop 7), and one compares debug_traceCall's call tree, frame by frame and gas included, with a full node's trace of the same request.

  • modules-cargo testing How this file is found. executor.rs declares an inline mod tests { … }, and inside it mod relay_adapt_7702_shield; without a body. For a module declared inside an inline module, Cargo looks in a directory named after the path: src/executor/tests/relay_adapt_7702_shield.rs. Again no #[path] is needed. The file's use super::*; then sees everything tests sees, which includes executor.rs's private items and its imports (Arc, NoopStateProofCache, with_estimate_buffer, assert_frame_matches), because glob imports pass imported names along too.
  • macros concat!(env!("CARGO_MANIFEST_DIR"), "/../…") builds the path at compile time: env! reads an environment variable while compiling (Cargo sets CARGO_MANIFEST_DIR to the crate's directory) and concat! joins string literals into one &'static str. The test works from any working directory.
  • concurrency lifetimes testing Compute once, share between tests. cargo test runs tests on several threads at once. static REPLAY: OnceLock<Replay> runs the expensive replay (a few seconds of bisections) the first time any test asks, and every other caller waits for that result. get_or_init returns a &'static Replay: a static lives for the whole program, so references into it may too. In Kotlin this is val replay by lazy { … } at top level.
  • error-handling testing unwrap_or_else(|e| panic!("{path}: {e}")) panics with the path in the message, which a plain unwrap() would not show. testing smart-pointers concurrency WaveServing (lines 114–162) wraps the replay oracle, counts single reads and waves in AtomicUsize fields (atomics, because the trait's methods take &self and the type must be Sync), and with fill: true really writes a wave's results into the caches, as the network oracle does. wave_world keeps an Arc<WaveServing> for the test while the executor holds the same object as Arc<dyn SnapStateOracle>. The test shows the two sides of #532: with filling waves, no read is made one at a time; without them the same world is read one by one more than 50 times. The answer is the same either way.

The recorder: cargo run --release -p myotis-net --example record_shield_fixture. It syncs the mainnet light client from the embedded checkpoint (up to 25 minutes), starts the EL reader with a peer cache, waits until there is a snap peer and a verified head it can serve, and then records the shield with fresh random keys. A failed attempt (a peer vanishes, the head moves past what peers serve) is retried at a fresh head with fresh keys, up to five times within a 30-minute budget. On its first run it seeds its own peer cache with a copy of the newest one an installed Myotis keeps, because finding snap peers on mainnet from scratch is slow. Finally it writes the fixture to rust/testdata/evm/ and prints the world's size. The keys come from OS randomness and are never written anywhere.

  • enums-patterns Destructuring in the parameter list. type Head = ([u8; 32], BlockContext, Arc<dyn SnapStateOracle>) names the triple head_evm_oracle returns. async fn record((block_hash, block, oracle): Head, …) takes it apart right in the signature; any irrefutable pattern may stand where a parameter name would.
  • async ownership concurrency Leaving the async world. record_shield blocks: the oracle's reads wait on network I/O by blocking the thread (stop 7). Calling it directly inside an async task would stall a tokio worker thread. tokio::task::spawn_blocking(move || …) runs it on tokio's blocking pool. move transfers ownership of oracle, block, the key, params and meta into the closure, because the closure must be 'static: the thread may outlive this stack frame. The &ephemeral_key and &params inside are borrows of the closure's own moved copies.
  • error-handling async .await yields Result<Result<EvmFixture, String>, JoinError>: the outer error means the thread panicked. .map_err(…)? handles the outer layer and the function returns the inner Result as it is.
  • bytes-strings The note fields are derived from one random value: keccak256(&[&note[..], label].concat()) concatenates two byte slices into a new Vec. npk[0] &= 0x0f forces the note key below the SNARK scalar field, which shield_base_token checks.

error-handling cli fn fail(message: &str) -> ! never returns: std::process::exit has type !. That is what lets main write unwrap_or_else(|e| fail(…)) where a value is expected, and use fail(…) as a match arm next to arms that produce an address. The rest of main uses tokio::time deadlines and a 5-second poll of sync.status(), and stops the reader and the light client before writing the file. The testdata README describes the same procedure, and how to re-run the replay tests, including the Java engine's twin test, after a re-recording.
