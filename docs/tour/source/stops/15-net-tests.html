myotis-net, part 7: integration tests and probes

The black-box test layer, with three very different kinds of code. Six offline files run in every build: five conformance replays that feed bytes generated by the Java engine through one Rust layer and must reproduce Java's answer sheet exactly, and one allocation test that throws 10 MiB hostile frames at every eth and snap decoder. Fourteen live files talk to real networks and never run unless someone asks; four of their tests are the release gates from your CLAUDE.md. Last comes snap_probe, a diagnostic binary that crawls other EVM chains for snap servers. Tests are also where Rust's ownership rules show up in their simplest form.

What runs where testing modules-cargo

Gradle's cargoTest task is cargo test --workspace, and check depends on it. It self-skips on a machine without cargo. Your CLAUDE.md counts a failing ./gradlew check as a PR-time failure, and its PR workflows (Build and Test in ci.yml among them) run on pull requests into any base branch. The workflow files are not in the snapshot, so take that part from CLAUDE.md. On every ./gradlew check or build with cargo:

  • the five conformance replays (one test each) and the twelve tests of el_hostile_frames run;
  • the seventeen live tests in fourteen live_* files are compiled and reported as ignored;
  • examples/snap_probe.rs is compiled (the crate's own dev-dependency on itself even turns on the fixture-recorder feature so that another example compiles), but never run.

Release step 3 in CLAUDE.md runs three commands, either by dispatching the cold-start regression workflow (preferred, because a runner is a clean host) or locally. They cover four test functions: 3a runs the whole live_pins_alive binary, which holds two tests (pins, then bootnodes, one at a time because of --test-threads=1); 3b and 3c each run one test of live_cold_start by name. The other live files are developer diagnostics with no schedule.

A panic in a spawned task does not fail the test

Tokio catches a panic inside a tokio::spawned task, and the task's JoinHandle.await returns Err(JoinError). If the test ignores that Err, the failure is gone. This holds even under --release, whose workspace profile says panic = "abort": Cargo ignores the panic setting for test targets, because the test harness needs unwinding. In production the same panic would abort the whole process.

Offline: one corpus, two engines

testing domain Each Java twin has two modes. With -Dmyotis.el.writeExpected=true it generates vector files plus an expected.txt answer sheet into rust/testdata/el/<layer>/. Without the flag it replays them. The Rust test replays the same bytes and must reproduce the same expected.txt, key by key. That byte-level contract is what lets the Rust engine replace the Java one. Corpora are read at run time from a path built on env!("CARGO_MANIFEST_DIR") (the crate directory, filled in by the compiler), so a corpus refresh does not force a rebuild.

Replays the discv4 corpus. Rust must encode signed Ping/Pong/FindNode packets byte-identical to Java (possible because both sign deterministically, with RFC 6979 low-s ECDSA, from a fixed key and expiry), accept and reject the same packets, and decode Neighbors with the same skip-versus-stop leniency.

  • testing The replay shape shared by all five files. If the corpus is missing, print and return. That is a pass, mirroring Java's assumeTrue, except that Rust has no “skipped” status. Next, parse expected.txt into a BTreeMap and compute every verdict into actual. Then check each expected key, and finally assert_eq!(expected, actual), which also catches extra keys.
  • ownership iterators-closures for (base, raw) in vectors(…) destructures owned (String, Vec<u8>) pairs. decode_neighbors(&raw) only borrows. .collect::<Vec<_>>() (the “turbofish”) names the collection and lets _ infer the element type. ids is then moved into the map.
  • enums-patterns match actual.get(k) { Some(got) => …, None => panic!(…) }: get returns Option<&String>, so a missing key has to be handled explicitly.

Pins three things across languages: ECIES decryption of the two canonical EIP-8 auth messages, session-secret derivation that must reproduce the spec's published AES and MAC secrets, and frame encoding and decoding under fixed secrets. Only the uncompressed Hello frame is byte-compared, because the Java and Rust snappy encoders produce different (equally valid) bytes; the compressed one is only decoded.

  • borrowing &frame[..16], &frame[16..32]: borrowed windows into one buffer, nothing copied. dec: &mut FrameCodec: frame decryption is stateful (the CTR keystream position and a running MAC), so each decode advances it, and frames must go through one exclusive borrow in wire order.
  • enums-patterns match is an expression: one arm yields l, the other returns from the whole function. Ok(d) if … is a guarded arm.
  • bytes-strings frame.len() - 16 would panic on underflow in a debug build for a frame shorter than 16 bytes. That is fine for committed vectors, but not a pattern for untrusted input.
  • modules-cargo The test imports myotis_net::el::rlpx::frame::FrameCodec, but the code lives in myotis-wire now (#505). el/rlpx/frame.rs is a one-line pub use myotis_wire::rlpx::frame::*;, a re-export that keeps the old path working. Java has no equivalent; the nearest is a type alias per class.

Covers eth/68 and eth/69 Status encode and decode, BlockHeaders decode (each header's keccak hash and number), and eth/69 “bloomless” receipts rebuilt into canonical bytes with the bloom recomputed.

enums-patterns domain Status.latest_block is an Option<u64>: it is None for eth/67 and eth/68, whose Status has no such field. unwrap() is safe only because this message was decoded as eth/69. A light client advertises only [head-32, head], which is why the test writes 21_000_000 - 32. Underscores are just digit separators.

  • domain error-handling Decoders know what was asked. Since #454, decode_block_headers(bytes, requested) and decode_receipts69(bytes, requested) keep at most requested + 1 items (one extra, so over-serving is visible) and only check the rest. The replay passes usize::MAX for “keep everything”. The helper uses saturating_add(1), so usize::MAX + 1 stays usize::MAX instead of overflowing.
  • borrowing smart-pointers block.canonical(count) rebuilds the 256-byte bloom only when the receipt count equals a transaction count the caller trusts, so a peer cannot make the engine expand more receipts than the block holds. It returns Cow<'_, RawList> (“clone on write”): Cow::Borrowed for eth/66–68 receipts that are already canonical, Cow::Owned for an eth/69 expansion. The '_ ties the borrowed case to block. With no body in a test vector, the count is the vector's own block.len().

Checks the byte encodings of the snap requests. The “strong pin” is that Rust decodes Java's AccountRange and StorageRanges and runs the real verify-on-fetch path, including the MPT proof check against the committed roots, and gets the same account fields and slot value.

  • enums-patterns domain AccountOutcome::Present(acct) binds the proof-verified leaf. Absent is a verified exclusion proof, a cryptographic answer rather than an error.
  • error-handling Earlier in the file, expected["account.stateRoot"] indexes a BTreeMap, which panics on a missing key. Here the answer sheet is also an input: it provides the roots.

Checks that verify_header_chain gives the same true/false as Java (the twin lives in :node-core) for a valid chain and four forgeries: a broken parent link, a made-up child above the anchor, a forged anchor, and a wrong first state root. It also pins the exact verifyMethod and failReason token strings that operator tooling greps for; peerBlockAheadOfAnchor is new since September.

  • domain Anchored at the top. The trust anchor is the newest header's hash. A parent hash commits a header to its parent, never to its children, so trust flows only downwards from the anchor. The old walk anchored on the oldest header, which let a peer append a made-up child; vector 003-chain-made-up-child pins the fix. The key in expected.txt was renamed from beaconBlockHash to anchorBlockHash with it.
  • ownership iterators-closures into_iter() consumes headers, so the closure receives each VerifiedHeader by value and can move its non-Copy header field into the new struct. The unused parts (raw_rlp) are freed. With .iter() you would get references and need vh.header.clone(). _id marks a binding that is deliberately unused.

The regression test for #454. A peer sent frames that were 10 MiB lists of one-byte elements (492 KB as snappy on the wire), and decoding one into an owned RLP tree cost 547 MB of heap. Every decoder a peer can reach must now stay flat on such a frame: the handshake and read-loop paths (request id, Hello, Status, gossip, control messages) and the responses to our own requests (headers, bodies, receipts for eth/66–70, block access lists, snap ranges and codes). The file counts allocations with its own global allocator, which is why it is a separate test binary: a #[global_allocator] applies to the whole binary.

  • concurrency interior-mutability Per-thread counters. The test harness runs tests in parallel on several threads. thread_local! gives each thread its own copy of every counter, so one test never sees another's allocations. Like Java's ThreadLocal, but declared statically. Cell<usize> allows set through a shared reference with no locking, which is safe because a thread-local is never shared.
  • unsafe-ffi const { Cell::new(0) } initialises the slot at compile time. A lazily initialised thread-local could itself allocate on first use, inside the allocator, and recurse. try_with instead of with returns an error rather than panicking when the thread's locals are already being torn down, which can happen during the last allocations of a thread.
  • unsafe-ffi traits-generics An unsafe trait. GlobalAlloc is declared unsafe trait: implementing it is a promise the compiler cannot check (return properly aligned memory, never unwind). So the impl is unsafe impl, and the // SAFETY: comment says why the promise holds: every call is forwarded unchanged to System, the platform allocator. The methods are unsafe fn because callers must keep promises too (pass the same layout to dealloc).
  • macros #[global_allocator] static COUNTING: Counting = Counting; replaces the allocator for every Box, Vec and String in this binary. Counting is a unit struct: a type with no fields, whose only value is written Counting. The JVM has no equivalent; the nearest is an agent that instruments allocation.
  • traits-generics iterators-closures counted<T>(f: impl FnOnce() -> T) takes any closure that runs once and returns any type, and hands back the counts plus the result. ALLOCATIONS.with(Cell::get) passes a method path as the closure, the way Kotlin writes Cell::get.

domain testing The test frames are built before counted runs, so only the decoder's own allocations are measured. Two budgets appear in the file. assert_flat allows at most 16 allocations and 64 KiB: the decoder walked the frame without building anything. assert_one_buffer allows one buffer about the size of the input: the decoder kept the peer's elements as they arrived in a RawList, not one heap allocation each. Here eth/69 receipts are kept compactly, and asking for the wrong transaction count is refused before a single 256-byte bloom is rebuilt.

testing The last two tests use peak rather than counted. The LIVE counter goes up on alloc and down on dealloc, and PEAK keeps its high mark, so a decoder that allocates and frees as it walks is allowed; only memory held at once counts. Fifty thousand valid headers arrive for a request of three, and the decoder keeps four (one past the request) while holding less than 64 KiB at any moment.

Live EL tests: finding peers

Two tests against a network's real discv4 bootnodes, read from the engine's own ElConfig (mainnet by default; NET=sepolia|gnosis|chiado; anything else panics). The first passes when it learns at least one node beyond the seed list within 60 s, stopping early at five. The second is a census: one discovery service per bootnode, each with its own key, for 30 s; at least MIN_SEEDING (2) bootnodes must hand out neighbours. Its per-bootnode lines are what you read when re-syncing the list from geth (release question 2).

  • enums-patterns Guarded arms in order. Ok(Some(peer)) if is_bootnode(…) runs first, then if is_self(…), then the plain Ok(Some(peer)). The first arm whose pattern and guard match wins, so a bootnode's own bond event and a bootnode echoing our own record are logged but not counted. Before this change, five answering seeds could pass the test without a single FindNode.
  • ownership discovered.insert(peer.node_id.clone()) keys on distinct node ids, so a re-bond is not a second find. The clone is not strictly needed: Rust allows moving one field out of a local struct and still reading the others (a “partial move”), as long as the type has no Drop impl. The census below does move: others.insert(entry.node_id).
  • borrowing let discovered = discovered.len(); shadows the set with a usize for the rest of that block. The set is still alive, just unnamed until the block ends.

bytes-strings traits-generics A table entry stores its IP as raw bytes. <[u8; 4]>::try_from(&entry.ip[..]) converts a slice into a fixed array; the angle brackets are needed to name a method on the array type. .ok().map(IpAddr::from) drops the error and passes a constructor as a function. to_canonical() turns an IPv4-mapped IPv6 address back into IPv4 before comparing.

  • async ownership tokio::spawn(census_one(i, *addr)) needs no Arc clones: the future owns i and a copy of the SocketAddr (both Copy), and census_one creates its own key inside. Compare this with live_eth below.
  • error-handling testing probe.await.expect("census task") turns a panicked task's JoinError into a panic on the test thread, so here a failure inside a task does fail the test.
  • bytes-strings usize::from(row.neighbours > 0) converts a bool to 0 or 1 through the standard From impl.

Live EL tests: climbing the stack

Takes discovered mainnet peers, RLPx-dials them (ECIES handshake to an encrypted framed channel), sends our Hello, and succeeds when one peer answers with a valid Hello within 90 s. Dials are sequential, and each is bounded by the 10 s handshake timeout inside dial.

iterators-closures domain New since September: the tried set starts out holding the bootnodes. bootnodes.iter().copied().collect() turns &SocketAddr items into owned copies. A bonded bootnode arrives as an event whose UDP port stands in for a TCP port, and the EF NodeOps bootnodes are discovery-only, so dialling one would waste a 10 s timeout out of 90. That is also why bootnodes is cloned into the config above: the test keeps its own copy.

bytes-strings error-handling Checked narrowing. TableEntry.tcp_port is a u32, and port as u16 would silently truncate, as a Java (short) cast does, so the range is checked first. u32::from(u16::MAX) is a lossless widening. SocketAddr::from((ip, port)) uses a From impl on a tuple.

Runs discovery, RLPx and the eth handshake (Hello, version negotiation, Status, the network and genesis gate) against up to 200 mainnet peers concurrently. For READY peers it fetches 128 headers downwards from block 21,000,000 and checks the parent links. Many attempts are needed because peers are often full, and discv4 also returns same-genesis forks such as PulseChain.

  • async ownership smart-pointers Why the clones. tokio::spawn needs a future that owns everything it touches ('static) and is Send, because the task may run on any worker thread and outlive this loop iteration. So each iteration shadows key and cfg with fresh Arc clones, and async move moves them in. addr and peer_pubkey are Copy, so they are copied. Inside the future, &cfg borrows the future's own Arc.
  • concurrency The limit of 32 is only a throttle: the loop pauses 100 ms per new candidate while 32 tasks are unfinished. A Semaphore would enforce a hard cap, as snap_probe does.
  • enums-patterns if let Ok(outcome) = h.await keeps only tasks that finished normally. A panicked task is skipped without a trace in the counts.
This assert cannot fail the test

assert!(ok, …) runs inside a spawned task. If a peer serves a broken chain, the task panics, h.await returns Err(JoinError), and the if let Ok(outcome) above silently skips it. The only traces are a panic message in the output and a missing count. Header verification here is opportunistic by design (the test asserts only Status exchanges), but the assert! reads as if it were stronger.

iterators-closures borrowing headers.windows(2) yields overlapping two-element sub-slices, and (&w[0], &w[1]) borrows both.

Uses the same concurrent dial pattern. This proves proof checking, but not beacon anchoring: the root is the peer's own. A valid exclusion proof (Absent) counts as verified.

The whole EL read pipeline behind one call. It starts ElReader from ElConfig::mainnet() with a fresh, never-synced ExecAnchor (both shared through Arc::clone) and calls get_account at the head in a loop. With no beacon anchor, a served query must say beaconNotSynced. The only unconditional requirement is that the reader starts; the real headerChain verdict is left to the daemon integration check in your CLAUDE.md.

  • domain enums-patterns ReadAnchor::Head is new: a read now says which beacon block it is anchored to, the optimistic head (latest) or the finalized block (finalized). The finalized read is never silently downgraded to the head.

Diagnostics against the project's own Sepolia node

Dials the project's dedicated Sepolia node directly, with no discovery, and issues the exact request shapes the log-index backfill walker uses: a 1,024-header reverse window (which must start at the head and chain by parent hash) and bodies plus receipts for a 64-block chunk (whose prefix must have matching receipt and transaction counts). The fork id now comes from the engine's pins (forkid::SEPOLIA_FORK_ID_HASH and SEPOLIA_FORK_NEXT); the session folds in the next fork once its timestamp passes, so the handshake keeps working across Sepolia's Amsterdam activation.

ownership Copy before move. let best_hash = session.peer_status.best_hash; copies a [u8; 32] (arrays of Copy types are Copy) before ManagedPeer::spawn(session, …) consumes the session. head.first() returns a reference into the Vec; cur_n and cur_hash are copies out of it.

  • enums-patterns let [upper, lower] = pair else { break }; is a slice pattern. A slice's length is known only at run time, so the pattern can fail, and the else is required even though windows(2) always yields two elements. wrapping_sub(1) cannot panic at block 0.
  • async borrowing Concurrency without tasks. futures::future::join polls both requests inside the current task and returns both results. Both futures borrow peer and chunk at once, which is legal because ManagedPeer methods take &self and shared borrows may overlap. Nothing is spawned, so there is no 'static requirement and no Arc. Compare this with live_eth.
  • domain A response cut short by the peer's byte budget is the expected honest shape, so the rest of the test checks a consistent prefix, not exact lengths. It compares only counts; the real walker verifies the transaction and receipt roots.

“MEASUREMENT ONLY”: an A/B timing of the backfill chunk pipeline (#298) against the dedicated node. It fetches the same 8 × 64-block chunks sequentially and through buffered(4), in a full-serve region and in a spam region where responses are truncated, alternating the order over two rounds. Nothing is verified. It uses the same engine fork-id pins as the file above.

  • async iterators-closures stream::iter turns an iterator of futures into a stream. buffered(DEPTH) keeps up to 4 of them in flight and yields results in the original order. The four fetches are polled concurrently inside one task, not on four threads.
  • borrowing Each async move captures hashes and peer, which are shared references. References are Copy, so every future still borrows chunks and the peer. That is fine because nothing is spawned.
  • async Cancellation by drop. break stops polling, and the in-flight fetches are dropped with fetches when the function returns. That is exactly the case ManagedPeer's pending guard exists for.
  • traits-generics futures::StreamExt::next(&mut fetches) calls the trait method in fully qualified form instead of importing the trait.

Live CL tests and the release gates

End to end for the light client (Stop 10): start SyncHandle with ChainConfig::mainnet(), poll every 5 s until SYNCED (at most 15 minutes, measured: servers give about one update per 10 s per peer), then check that finality has moved past the embedded checkpoint. Unchanged since September.

“Are this build's configured CL peers and bootnodes actually alive?” A silently rotted pin list is what #422 turned out to be. Stale or inaccurate comments

The header (lines 10–14) says a sick pin “costs up to its retries (3 x PIN_TIMEOUT)”. The bootstrap loop retries only after a ResourceUnavailable answer, so a pin that times out costs one PIN_TIMEOUT. A pin that bootstraps and then stalls on updates can cost far more: two update asks of up to two attempts each, every attempt up to 20 s plus 11 s waits. The total for “a couple of dozen pins is minutes” is right; the per-pin bound is not.

“The two cold-start regressions issue #422 asked us to keep.” Each test starts what a host starts on a fresh install: the CL light-client sync with no snapshot and no CL peer cache, and now also the EL reader on its execution anchor with no EL peer cache. Why the EL reader runs too

From Gloas (EIP-7732), a light-client header proves only the execution block hash. SYNCED then waits until the EL peer pool has fetched the finalized execution header by that hash (feed_exec_anchor in sync.rs). Run CL-only, the dead-pins test could never pass on Sepolia after its Gloas fork; it bootstrapped, followed finality, and stayed CATCHING_UP. So the test starts the EL half the way a host does, and the pass condition stays SYNCED, the state a host shows. Before Gloas the EL reader plays no part in SYNCED.

A probe binary: snap servers on other chains

A one-shot census of snap/1 service on three foreign EVM chains: Polygon PoS (Bor), Scroll and Mantle. It crawls discv4 from Bor's and Scroll's published bootnodes plus the Ethereum mainnet DHT (Mantle publishes no EL bootnodes, and its op-geth uses mainnet's), RLPx-dials every node it learns, reads Hello and Status, and, for a peer of a target chain, mirrors the peer's own Status back so that no per-chain fork-id table is needed. It then fetches the head header by hash and asks one GetAccountRange at that header's state root. A non-empty proof that verifies (present or absent) counts as “serves snap”. As the header says, this proves nothing about whether that head is canonical: no anchor is involved. Run with CRAWL_SECS=300 cargo run --release -p myotis-net --example snap_probe.

  • concurrency smart-pointers A hard cap. Semaphore::new(96) allows 96 probes at once. Compare the soft throttle in live_eth.
  • ownership _permit is not _. A binding named _permit lives to the end of the block, holding the permit for the whole probe. let _ = … would drop the permit immediately and remove the cap. Java's try (permit) { … } spells out the same scope.
  • iterators-closures borrowing spawn_dial is a closure that borrows key, reports and sem (it clones the Arcs inside), so it is an Fn closure that can be called many times.   • interior-mutability async reports is Arc<Mutex<Vec<PeerReport>>> with tokio's async mutex, built by Arc::default(). At the end, let reports = reports.lock().await; shadows the Arc with the lock guard. The guard borrows the Arc, which is still alive, just no longer nameable.
