myotis-engine: the boundary

This is where Kotlin, Swift, JavaScript and other Rust binaries meet the engine. Four host routes lead through two thin export files into one big file, host.rs. It owns the process's only engine tokio runtime and a registry of chain handles, and exposes every contract operation as a plain blocking function: strings and integers in, a JSON string, a bool or a negative sentinel out. Exceptions and panics never cross the boundary. The C half of the boundary is the one place in the codebase where raw pointers are handed to foreign code.

Four routes, two doors

Every host ends up in host.rs, but there are two doors into it. ffi.rs is the UniFFI surface: ordinary Rust functions marked #[uniffi::export]. capi.rs is a hand-written C ABI. Which door a host takes depends on what it can link against.

  • JVM (the Android app, the desktop app, the daemon, and the engine library eth.myotis:myotis-engine that a separate wallet consumes): RustEngineNative in :myotis-engine-rust calls the UniFFI-generated Kotlin in myotis_engine.kt, which calls libmyotis_engine through JNA. That reaches ffi.rs. Stop 17 (UniFFI end to end) takes this route apart; here it is a black box.
  • iOS: :myotis-engine-ios runs Kotlin/Native cinterop over the hand-kept header rust/include/myotis_engine.h. Its RustEngine.kt calls the myotis_* functions in capi.rs, statically linked from libmyotis_engine.a.
  • Node and Electron: myotis-node (napi-rs, Stop 18) links this crate as an rlib and calls the capi functions by Rust path.
  • The standalone daemon myotis-rpcd (Stop 19) is new since September. It also links the rlib, but calls the ffi functions by Rust path, as plain Rust functions. It uses capi only for the two functions UniFFI does not export: myotis_set_boot_enodes and myotis_create_with_checkpoint.

A #[uniffi::export] function stays an ordinary pub fn; the macro only adds a C-callable twin beside it. That is why myotis-rpcd and the example binary at the end of this stop can call ffi::create_handle(String, String) directly, with no FFI in between.

No HTTP server in this crate

The engine answers function calls, not HTTP. The JVM apps' loopback JSON-RPC listener is a port, LoopbackRpc, in :myotis-engine-rust; the :myotis-engines selector fills it with KtorLoopbackRpc. An in-process consumer of the engine library (Myotis.newEngine()) gets no listener at all and calls reads() directly. myotis-rpcd brings its own JSON-RPC server, in Rust. All three end in the functions on this page.

The NULL-to inconsistency in myotis_eth_call_json that the old tour flagged was fixed in ABI 29.

Declares the modules, expands UniFFI's crate-level scaffolding, and defines ABI_VERSION (now 55), the number every host checks at startup. Most of the file's 406 lines are that constant's doc comment: one entry per version since v2, a changelog of every surface change. The crate is built as a cdylib (loaded by JNA), as an rlib (linked by myotis-node and myotis-rpcd), and, via Gradle, as an iOS staticlib. It is the library crate that builds and owns a tokio runtime for its hosts.

  • modules-cargo Visibility at the module line. Each mod x; pulls x.rs into the module tree, and that line decides its visibility. pub mod capi and pub mod ffi are reachable from other crates; mod host, mod eljson and mod usage are visible only inside this one, like a package whose classes are all package-private. So myotis-rpcd can call myotis_engine::ffi::status_json but not myotis_engine::host::status_json.
  • macros unsafe-ffi uniffi::setup_scaffolding!() expands into whole items at the crate root: a tag type, checksum functions and #[no_mangle] glue that the generated Kotlin calls. #[uniffi::export] in ffi.rs refers back to that tag. The details are in Stop 17.
  • domain Bump on every shape change. The last two entries show the house rule: an additive function still bumps the version, "so a host that serves eth_simulateV1 is never paired with an engine that lacks it". On the JVM the number is a backup check, because UniFFI's per-function checksums fail first when a stale library is loaded. For the iOS C ABI it is the main check: RustEngine.EXPECTED_ABI_VERSION is read from the header's MYOTIS_ABI_VERSION, and a test in capi.rs pins the header to this constant.
  • modules-cargo pub use re-exports an item from a dependency under this crate's name. MAX_PROOF_STORAGE_KEYS is re-exported so myotis-rpcd can refuse an oversized eth_getProof before it reaches the engine, without depending on myotis-net itself. bls_dst is re-exported only to keep the consensus crate in the build graph.

The built-in network list: a const array of four records (mainnet, gnosis, sepolia, chiado), serialized to the same camelCase JSON as io.myotis.api.NetworkInfo, plus alias resolution (xdai and gbc → gnosis). The golden file rust/testdata/networks_catalog.json is compared byte for byte here and parsed by the Java side's NetworksJsonGoldenTest. A new test pins has_ens to the EVM crate's name-tree table, so a network cannot offer names its engine refuses. Gnosis now has names (Genome's .gno); Chiado has none.

  • macros traits-generics #[derive(Serialize)] generates the JSON writer at compile time: Jackson without reflection. rename_all = "camelCase" maps display_name to displayName.
  • lifetimes ownership Every field is Copy. A &'static str is a pointer and a length into the binary's read-only data. So the whole struct is Copy and can live in a const with no heap allocation. A String field would own heap memory and make both impossible.
  • borrowing lifetimes enums-patterns In canonical_network_name, the lowercase String is a temporary, borrowed only while the match runs. Every arm returns a literal, so the result can be 'static and never points into the temporary. | separates alternative patterns. Input is deliberately not trimmed, so both engines reject exactly the same inputs.

A process-wide ring of the last 4,096 tracing lines, which hosts drain on a timer into their own logs (Android's Logs tab and logcat, slf4j on desktop). Before it existed, Rust logs were invisible on Android. Pulling instead of pushing means no callbacks into the host, no Android dependencies, bounded memory, and no panics. The file is unchanged since September.

  • interior-mutability concurrency A lazy, mutable global. Every static must be safe to share between threads. OnceLock creates the value exactly once (its new() is a const fn, so no startup code runs), and the Mutex allows changes through the shared &'static reference. In Java terms, it's a static final holder whose contents can only be touched under synchronized, and the compiler enforces that.
  • error-handling let Ok(mut ring) = ring().lock() else { return String::new(); }; means a poisoned lock degrades to "no lines" instead of an unwrap() panic, which in this workspace (panic = "abort") would kill the host app.
  • traits-generics bytes-strings impl Write for RingWriter is how tracing writes into the ring. RingWriter has no fields, so it takes no memory. String::from_utf8_lossy returns a Cow: borrowed when the bytes are valid UTF-8, allocated only when something has to be replaced. trimmed.to_string() then makes the owned copy the ring keeps.
  • domain write reports success even when it drops a line, and anything logged before init() is lost.

New since September: data usage per handle (ABI 50, docs/data-usage.md). Each handle's ChainConfig carries a TrafficMeter from myotis_net::traffic, a set of byte counters that only grow. A UsageLedger turns those totals into per-day figures: every tick adds the growth since the previous tick to the current local day, and to the day's metered figures too when the host last said the network is metered. Today's figures are kept in data-usage[-net].json beside the sync snapshot, in a format the Java engine's ledger writes byte for byte, so the figures survive both a restart and an engine switch.

  • concurrency interior-mutability An atomic global with no lock. The metering is one byte for the whole process (it describes the device's network, not a chain), so a static AtomicU8 holds it. Atomics are Sync, so a plain static works with no OnceLock or Mutex, and AtomicU8::new is a const fn. Ordering::Relaxed is enough because the value guards no other memory; Java's getOpaque/setOpaque on an AtomicInteger is the nearest analogue.
  • enums-patterns Metering::Unknown as u8 works because the enum has explicit discriminants (= 0, = 1, = 2) and no data. The way back, from_code, is a match returning Option, because an integer can hold values no variant has. #[default] on a variant tells #[derive(Default)] which one to use.
  • concurrency Read the counter under the lock. The comment explains a race Java code would have too: the minute ticker and a status read may tick at the same moment. If each read meter.snapshot() before taking the lock, the later one could store an older seen and count bytes twice. Taking the snapshot inside the critical section orders them.
  • error-handling interior-mutability lock().unwrap_or_else(|e| e.into_inner()) is the other way to treat a poisoned mutex: take the guard anyway. PoisonError::into_inner returns it. That is safe here because the state is a few counters that cannot be left half-updated in a way that matters; ringlog chooses to give up instead.
  • ownership borrowing st is a MutexGuard<LedgerState>; through it, st.today.rx = … writes into the locked state. DayTotals is Copy, so today: st.today in the returned snapshot copies four integers, while st.day.clone() must copy the String explicitly. The guard is dropped at the closing brace, after the return value is built.
  • iterators-closures st.last_write.is_none_or(|t| t.elapsed() >= WRITE_EVERY): true for "never written" or "written long enough ago". saturating_sub / saturating_add stop at 0 and u64::MAX instead of wrapping; a counter that moved backwards would otherwise wrap to a huge number.

unsafe-ffi One call into libc. Rust's standard library has no time zones, so local_day asks the C library with localtime_r. std::mem::zeroed() is unsafe because an all-zero bit pattern is not a valid value for every type (a reference or a NonZeroU32 would be undefined behavior); for the plain C struct libc::tm it is fine, which is what the SAFETY: comment states. localtime_r itself is unsafe because it is a foreign function taking raw pointers; &t and &mut tm coerce to them. #[cfg(unix)] removes the block entirely on other targets, where the UTC fallback below (Howard Hinnant's date algorithm) is the only path.

ownership In open_on (lines 119–138), the struct literal names state first and meter last. Fields are evaluated in the order written, so meter.snapshot() borrows meter before the next field moves it into the struct. Swapping the two lines would not compile: "borrow of moved value".

Behind every FFI entry point sits one engine for the whole process. It owns a multi-threaded tokio runtime and a registry of chain handles, and each contract operation (lifecycle, status, settings, verified reads, the EVM calls, ENS, transactions, the eth_getLogs index, address activity) is a blocking function. The file enforces the trust-anchor rules for data directories used by create_with_checkpoint (#441), applies or refuses every block selector, and parses all untrusted input without panicking. 87 of its tests sit in eight test modules; none starts networking.

The singleton and the state machine

  • enums-patterns ChainEntry is a sealed class with data: Created(config), Running(config, sync, reader?), Paused(config, frozen status, read stats). The map entry is the only owner of the SyncHandle. The config, the reader and the read stats are behind Arc, so a caller can copy a pointer out and work without holding the lock.
  • smart-pointers Paused gained an Arc<ReadStats> since September: the reader is dropped on pause, but its read counters must outlive it. Holding a second Arc to the same counters is all it takes; whoever drops the last Arc frees them.

concurrency domain One lock per concern. EngineState now has nine per-handle side maps beside handles (served window, seed pins, log-index runtime bits, activity watch, fee-history cache, the two fork watches, the EL carry, the usage ledger). Each is its own Mutex<HashMap<i64, …>>, so a status read touching the ledger never waits on a seed-pin push. The cost is discipline: every map must be cleared in stop, and the comments repeat "Dies with the handle" for that reason. Besides the usage map, the excerpt shows the two coarse locks: create_lock serializes every create, and tearing_down keeps a stopping handle's directory "in use" until its loop has finished writing.

  • interior-mutability smart-pointers static ENGINE: OnceLock<Option<EngineState>>: get_or_init runs its closure once, even when several threads race. None means the runtime couldn't be built, so every entry point returns its failure value rather than panicking. Statics are never dropped, so the runtime lives until the process exits. .as_ref() turns &Option<T> into Option<&T>, and because the Option lives in a static, that reference is &'static.
  • concurrency Handle ids come from an AtomicI64 starting at 1, so a valid id can't be confused with −1, and ids are never reused. Locks are taken in the order create_lock → handles → tearing_down.

Create: a named guard

  • interior-mutability ownership A named guard. let Ok(_serial) = engine.create_lock.lock() else { … }; binds the guard, so the lock is held until the function returns, which serializes every create end to end. The pattern _ would bind nothing, and the guard would be dropped, releasing the lock, at the end of the statement. (_serial only suppresses the unused-variable warning.) Mutex<()> guards no data; it is purely a critical section.
  • error-handling resolve_config and bind_persistence return Result<_, i64> whose error is the sentinel to hand back, so Err(sentinel) => return sentinel passes it straight through. &mut config lends the config so bind_persistence can set its snapshot and peer-cache paths.
  • domain Fail closed. A directory that carries a caller-supplied anchor marker belongs to that anchor. A plain create on it returns −3, because resuming it from the embedded checkpoint would silently swap trust anchors.

enums-patterns error-handling matches!(expr, pattern if guard) is a match that yields true or false. Here only a definite NotFound counts as absent. symlink_metadata looks at the directory entry itself, so a dangling symlink is "present" (an issue reported from freedom-browser#353). Any other error, such as a permission problem, also counts as present. Uncertainty refuses.

Start and resume: the lock scope

  • borrowing concurrency A block as a lock scope. The guard map lives only inside let (config, read_stats) = { … };. It is dropped at the }, so only two cheap Arc copies leave the locked region, and the slow start runs without the lock. Holding the map lock across block_on would stall every other FFI call and risk deadlock.
  • smart-pointers ownership Two kinds of clone. Arc::clone(c) increments a reference count. (*config).clone() dereferences the Arc and deep-copies the whole ChainConfig, because SyncHandle::start takes it by value. The copy still shares its inner Arcs (the WsPolicy, the traffic meter), which is how a settings call later reaches the running loop.
  • async SyncHandle::start is not async, but it calls tokio::spawn, which only works inside a runtime. block_on(async { … }) is there purely to be inside the runtime while it runs. It is not an async move block, so it captures by reference where it can: config is only borrowed. cl_watch is still taken by value, because the block assigns it into cfg.
  • enums-patterns match (from, map.get(&handle)) matches a tuple, so one match covers "the expected variant for this transition". _ => return false covers an unknown id or the wrong state.

async error-handling The EL reader starts in a second block_on (lines 776–797). Its async block ends in ? and .await: an async block has its own return type, here a Result, so ? inside it returns from the block, not from spin_up. A reader that fails to start is not fatal: the chain runs on the consensus layer alone, and status reports elReaderAvailable: false.

  • concurrency domain Publish only if nothing changed. After the lock-free start, the entry is re-checked. If a concurrent stop removed it, or a racing start already published Running, the freshly built stack is shut down rather than orphaned. (… Created(_)) | (… Paused(..)) is a single arm with two alternative patterns; .. ignores the remaining fields.
  • ownership smart-pointers map.insert(handle, ChainEntry::Running(config, sync, reader)) moves sync and reader into the map. That is why pins_reader = reader.clone() is taken first: one more Arc (inside the Option) for the seed-pin replay after the publish. drop(map) releases the lock explicitly before that slow call.
  • domain Lines 798–841, above this excerpt, replay what the host set while the handle was not running: the served-block window, the log-index runtime bits and the activity watch list. A pause drops the reader that held them, and no host re-pushes on resume, so the engine stashes each push per handle and re-applies it on every spin-up.

Pause: moving a value out of a map

  • ownership enums-patterns SyncHandle::stop(self) consumes the handle, so pause must own it. map.get would only lend it, so the code removes the entry, which moves the value out, and puts back anything that isn't Running. The tuple (sync, reader) is the block's value, carried out past the lock.
  • async ownership block_on(async move { … }): the teardown block owns sync and reader, because it consumes them. Inside it, if let Some(reader) = &reader only borrows (to cancel requests), and the later if let Some(reader) = reader moves the Arc out to call stop. Compare the borrowing async { … } blocks in the read path below.
  • domain The frozen status keeps the warm store facts but zeroes the live-connection counts. Paused is published before the teardown finishes, which is why the doc forbids concurrent lifecycle calls on one handle; the Java RustChainHandle serializes them with synchronized. The ledger tick with true forces today's figures to disk with the rest of the warm state.

A background task started from a foreign thread

  • concurrency Once inside a function. A static declared inside a function body is still one global; only its name is local. std::sync::Once::call_once runs the closure the first time and never again, which is how register can call start_usage_ticker on every create and get exactly one ticker.
  • async lifetimes Why &'static EngineState. rt.spawn needs a future that is 'static: it may run after the caller's stack frame is gone. The async move block captures engine, a reference. That is allowed only because the reference itself is 'static (it points into static ENGINE). With an ordinary &EngineState parameter this would not compile. Runtime::spawn can be called from any thread; unlike tokio::spawn, it does not need to be inside the runtime.
  • smart-pointers concurrency tick_all_ledgers clones the Arcs out under the lock and ticks them after the guard is gone. The temporary guard in match engine.usage.lock() { … } lives until the end of the match, so by the for loop it is already dropped.

A verified read, start to finish

  • async borrowing The standard bridge. (1) Parse the input, with no panics, including the block selector. (2) snapshot_reader clones the Arc<ElReader> under the lock and releases it. (3) read_anchor applies or refuses the selector against the current head. (4) engine.rt.block_on(reader.request(async { … })) blocks this thread until the future finishes; request wraps it in the 90-second request budget with cancellation. (5) Turn the Result into JSON. The async block may borrow reader and address, because block_on doesn't return before the future completes. Unlike spawn, it needs no 'static.
  • error-handling engine.handles.lock().map_err(|_| "engine lock poisoned")?: poison becomes an error value, and ? returns it. The helper's error type is &'static str, so each state has a precise message ("handle is paused", "handle not started").
  • async concurrency Never on a runtime thread. Calling block_on from one of the runtime's own worker threads makes tokio panic, which aborts the host. Every caller of this file runs on a foreign thread: a JVM, iOS, Node or rpcd thread.
  • domain Three kinds of answer: the result JSON (a failed verification is reported inside it, as failReason), {"error": …} (bad input, a stopped chain, or no peers), and the literal "null" for an item verified not to exist. A fourth arrived with ABI 27: {"error": …, "code": -32602}, a permanent refusal of the request itself.

Block selectors: apply or refuse

  • enums-patterns let BlockSelector::Number(block) = block else { return Ok(()); }; is let-else on an enum: if the value is a Number, bind its payload and continue; otherwise run the else block, which must leave the function. It reads like Kotlin's val n = (x as? Number)?.n ?: return. The new block shadows the old one, a common Rust idiom.
  • domain error-handling Three refusals, two codes. CallBlockRefusal::to_json (just above) turns Behind into the permanent −32602, because the head never moves back that far, and Ahead and NoHead into the retryable {"error"}, because they clear as the node syncs. Calling a lagging node's answer "permanent" would tell a client to stop asking. A number inside the window still runs against head state; that is the documented near-head trade-off.
  • bytes-strings saturating_sub and saturating_add keep head - 64 from wrapping below zero near genesis and head + 16 from wrapping at the top.
  • domain error-handling Apply or refuse. The eth_call state-override parser treats an unknown key as an error, not a skip, because a silently ignored override answers a different question (#314, the rule in your CLAUDE.md). call_target above it applies the same rule to to: empty means contract creation, and anything malformed is refused rather than turned into a creation.
  • error-handling traits-generics ? converts the error. The function returns Result<_, String>, but val.as_str().ok_or("override 'code' must be a hex string")? produces an error of type &str. ? calls From::from on the error before returning, and String implements From<&str>, so the literal is copied into an owned String only on that failure path. ok_or_else(|| format!(…)) is used where the message needs formatting, so the work happens only when needed.
  • borrowing iterators-closures for (addr_str, entry) in map iterates a borrowed serde_json::Map, so both are references into the parsed JSON; nothing is copied until parsed.insert builds U256 values.

interior-mutability enums-patterns A live setting reaches a running loop through c.ws_policy.bound_override_periods.store(…), an atomic behind the shared Arc<WsPolicy>. It works in all three states, and one arm lists them with |. In Some(ChainEntry::Created(c)) | Some(ChainEntry::Running(c, _, _)) | …, every alternative must bind the same names with the same types, here c: &Arc<ChainConfig>. It's the same mechanism as the consent flag in live_cold_start (Stop 15).

A write: judged before it is sent

  • domain The order of the checks is the point. Bytes that are no transaction (#360) are refused before the engine is even asked whether it is up, so a paused node gives the same permanent −32602 as a running one. A transaction signed for another chain (#665) is refused next, from the handle's config, which exists in every state. Only then does the code need a running reader. check_raw_transaction_json below runs the first gate alone, with no handle, so hosts can call it before their readiness wait.
  • enums-patterns error-handling Nested results. reader.request expects a future returning Result<T, String>, and send_raw_transaction returns Result<hash, SendError>. Wrapping it in Ok(…) makes T that whole inner result, so the match sees Result<Result<…, SendError>, String>. One match then separates all five cases, and Ok(Err(SendError::Unavailable(e))) | Err(e) joins the two retryable ones, since both bind e: String.
  • modules-cargo use myotis_net::el::reader::SendError; in the middle of a function body is legal; the import is scoped to that block.

Hex parsing without panics

traits-generics bytes-strings error-handling Const generics. parse_hex_fixed::<32> returns a stack array [u8; 32]; N is a compile-time number, something Java generics can't express. The length check and all(is_ascii_hexdigit) run first, so every later slice is two ASCII bytes. hex.get(a..b)? still returns None where &hex[a..b] could panic (on a range that is out of bounds or splits a multi-byte character), and .ok()? turns a parse error into None. Elsewhere, slot as u64 in get_storage_proof_json deliberately keeps the bit pattern of a negative Java long (a slot index ≥ 2⁶³).

Entering the runtime without blocking

  • async rt.enter(). reader.set_activity_watch is a plain function, but it may tokio::spawn the follower task, and that needs a "current runtime". let _guard = engine.rt.enter(); sets this thread's current runtime until the guard is dropped at the end of the function. It is cheaper than block_on(async { … }) when there is nothing to await. Note the name: _guard, not _, for the same reason as _serial above.
  • concurrency A lock held on purpose. The activity_watch stash lock is taken first and held across the reader call, so pushes are applied and stashed in one order, and a resume (which takes the same lock to re-apply the list) sees all of a push or none. snapshot_reader takes the handles lock briefly inside it; spin_up and stop never hold both, so the nesting cannot deadlock.
  • iterators-closures engine.handles.lock().is_ok_and(|map| map.contains_key(&handle)): is_ok_and consumes the Result, so the closure receives the guard itself by value, and the guard is dropped when the closure returns.

interior-mutability Why Option<HashMap>. A static initializer must be a constant expression. Mutex::new is a const fn, but HashMap::new is not (it seeds a random hasher), so the map starts as None and get_or_insert_with creates it on first use, under the lock. OnceLock would work too; this form keeps one lock for both the creation and every later update. This debounce keeps a polling wallet's repeated refused eth_getLogs filter to one log line per minute.

Stale or inaccurate comments in host.rs
  • The module doc (lines 2–5, 25–26) still calls the callers "the JNI natives (lib.rs)" and "the JNI shim". The JNI layer is gone: the callers are ffi.rs (UniFFI) and capi.rs. Many function docs still begin with the deleted nativeXxx names; lib.rs explains that history, this file does not.
  • status_object (lines 3819–3820) says its key ordering is part of the golden contract, but it builds a serde_json::Map, and this build compiles serde_json without preserve_order (checked with cargo tree -e features on the snapshot). Keys come out in alphabetical order. The tests compare parsed values, and Java reads keys by name, so nothing breaks; only the comment is wrong. eljson::invalid_params_json gets this right and says so.
  • The doc for get_transaction_receipt_json (lines 3011–3016) sits directly above pending_nonce_overlay's doc, so rustdoc attaches both to pending_nonce_overlay, and the receipt function has none.

  • unsafe-ffi macros How a Kotlin call arrives, in one paragraph. RustEngineNative calls the generated createHandle in myotis_engine.kt, which encodes each string into a buffer and calls a JNA native. The wrapper that #[uniffi::export] generated turns the buffers back into owned Strings and calls create_handle. On load, the generated Kotlin compares a checksum per function (today 44197 for create_handle; it was 39066 in September), so a stale .so fails loudly instead of crashing on a changed signature.   • ownership borrowing Owned in, borrowed onward. UniFFI hands over owned Strings (copied out of Kotlin memory), and &network lends them to host, whose functions take &str.   • unsafe-ffi Raw pointers. *const c_char carries no ownership and no lifetime, and may be null, so every use is guarded by is_null(). CStr::from_ptr scans for the terminating NUL and borrows the caller's memory. .into_owned() copies it, so the result no longer depends on how long the C side keeps its buffer. CStr / CString relate like &str / String.
  • unsafe-ffi ownership Handing ownership to C. CString::new(s) takes the String's buffer by move, so the text is not copied (the buffer may grow by one byte for the NUL). It fails on an interior NUL byte, which into_c turns into a null pointer instead of a panic. into_raw() gives up Rust's ownership: no Rust code will free it unless it comes back.
  • unsafe-ffi #[no_mangle] extern "C" keeps the symbol name exactly myotis_init and uses the C calling convention. Functions that take only integers are plain extern "C"; functions that dereference caller pointers are unsafe extern "C" with a # Safety section, because the compiler can't check the caller's promise.
  • error-handling No panics. There's no catch_unwind. The workspace builds with panic = "abort", and since Rust 1.81 a panic unwinding out of an extern "C" function aborts anyway. So every failure path returns null, false or −1.
