myotis-net, part 3: execution-layer peers

From an empty routing table to a verified snap peer that serves many requests at once: discv4 discovery with its ENR fork-id filter, EIP-1459 DNS node lists, the tokio side of RLPx and the eth handshake, the managed-peer actor, the peer cache, and the Tor reserve and transport. The pure wire codecs now live in myotis-wire (stop 5); this stop is the I/O that drives them. It is where generics over AsyncRead, hand-written cancellation safety, and “split one value into two independently owned halves” come together.

The path of one peer

Candidates reach the peer pool (stop 12) from four sources. discv4 walks the UDP DHT and, since #539, asks each node for its ENR first, so enrfilter can drop nodes of other chains before any TCP dial. dnsdisco walks a network's signed DNS node list on hosts that allow DNS. peercache replays peers that served snap before a restart. torreserve holds a share of those proven peers aside for Tor only.

The pool dials a candidate with RlpxConnection::dial: TCP, then the EIP-8 auth/ack handshake and a stateful frame codec (the codecs are myotis-wire's, stop 5). EthSession::handshake exchanges Hello and Status and checks network id and genesis. The pool turns a snap-capable session into a ManagedPeer, and the reader, the EVM and the log index then send concurrent requests through it. Nothing a peer says is trusted until myotis-wire's snap/fetch.rs verifies it against a trusted root. The Tor path (tor.rs) runs the same RLPx and eth code over an Arti stream to a node from the reserve.

Declares the execution-layer submodules, twins of the Java com.jaeckel.ethp2p.networking package. Two children are private (mod feecache; and mod tasks;), and torreserve is pub(crate): visible inside the crate, invisible to the engine and the hosts. #[cfg(feature = "tor")] pub mod tor; exists only in Tor builds: a compile-time switch, not a runtime if. modules-cargo Rust visibility is per module, not per package as in Java. pub(crate) is roughly Java's package-private stretched to the whole crate. Code outside the crate that names el::torreserve does not compile, while el::pool can use it freely.

Owns the peer pool's background tasks. It offers a graceful shutdown (abort, then await), a hard one (abort only), and silently refuses new spawns after shutdown. spawn also drops handles of finished tasks (retain(|task| !task.is_finished())), so the list does not grow for the life of the pool. The primer shows the whole file; the notes below add the part that concerns the pool.

  • interior-mutability concurrency The “stopped” flag and the handles share one lock. A concurrent spawn therefore either lands before take (and is aborted) or sees the flag (and drops its future unrun). It's Java's shutdownNow() + awaitTermination().
  • async interior-mutability The std guard lives only inside the synchronous take(), so stop() never holds it across .await. A held std guard would make the future non-Send.
  • smart-pointers ownership A reference cycle. The pool's loops own Arc<PoolInner>, and PoolInner owns this Tasks. While the loops run, the count never reaches zero, so Tasks::drop can't fire on its own. PeerPool::drop calls abort() explicitly to break the cycle.

Execution-layer peer discovery over UDP: discv4, a Kademlia DHT. Like the Java reference it is client-only: it pings, sends FindNode, reads Neighbors and answers Ping with Pong, but never answers FindNode. Since #539 it departs from the Java twin twice: it pings back a node that pings it while no pong from that node is on file, and it answers ENRRequest (EIP-868) from bonded nodes. Both exist so that the fork-id filter (enrfilter.rs) can read a node's ENR before the pool dials it. The packet codec moved to myotis-wire and is re-exported here (pub use myotis_wire::discv4::*;, line 32). The table and the rate limiter are pure (time is a parameter); only Discv4Service owns a socket.

The table

borrowing let bucket = &mut self.buckets[idx]; borrows one element of the vector mutably; until its last use, nothing else may touch self.buckets. The closure in retain reads entry.node_id, a different value, so the two borrows don't conflict. bucket.push(entry) then moves the entry into the bucket: the caller passed it by value and no longer has it. A full bucket drops its oldest entry, the same simplification the Java table makes (no ping-before-evict).

Start, stop and drop

  • ownership async Actor-style ownership. Everything the loop needs is packed into ServiceLoop and moved into the task (tokio::spawn(loop_state.run(stop_rx))). The socket, the pending maps and the ENR exchange need no locks, because only that task can reach them. Two things are shared: the routing table, as Arc<std::sync::Mutex<KademliaTable>> (the pool reads it), and the tallies, as Arc<EnrCounts> of atomics.
  • ownership cfg is taken by value, and its fields are moved out one by one: cfg.fork_filter in the match, cfg.bootnodes and cfg.pool_below_target into the struct literal. Moving fields out of a struct is allowed when the struct has no Drop impl; afterwards cfg as a whole can no longer be used.
  • error-handling The ? inside the Some(filter) => arm returns from start itself when our own ENR can't be signed; a match arm is not a function boundary.
  • interior-mutability async lifetimes In stop(), the guard created in the if let condition lives through the body (this crate is edition 2021), which means across task.await. That's only allowed with an async mutex, and the lock also guarantees the task is joined exactly once, even if two callers stop concurrently through &self.
  • concurrency A watch channel works as an awaitable stop flag. Drop sends true but can't wait, so the task detaches and winds down on its own; the socket closes when the task ends.

The loop

  • async borrowing One select! over five cancel-safe sources: stop, the 15 s refresh tick, the 1 s ENR sweep, probe requests, and recv_from. When one branch wins, the losing futures and their borrows (of self.socket, buf, self.probe_rx) are dropped before its handler runs. That is why a handler may call &mut self methods.
  • enums-patterns async Some(addr) = self.probe_rx.recv(): when all senders are gone, recv() yields None, the pattern fails, and select! disables that branch. There is no busy loop at shutdown.
  • ownership borrowing for bootnode in self.bootnodes.clone() iterates a clone, so the loop doesn't hold &self.bootnodes while calling the &mut self method send_ping.
  • bytes-strings ownership buf is allocated once and reused. parse(&buf[..n]) borrows only the received bytes and returns an owned Parsed (its data is a Vec<u8>), so the next recv_from can overwrite the buffer.
  • async MissedTickBehavior::Skip: after a laptop sleep, the interval fires once instead of replaying every missed tick as a burst of FindNodes.

The ENR exchange

Every sighted node (its Ping, its Pong, or an entry in someone's Neighbors) goes through consider. With no filter configured it is handed over at once. Otherwise the exchange looks up an earlier verdict by node id. With none on file, the node becomes a PendingEnr: if it holds our pong, an ENRRequest goes out now; if not, we ping first and ask once it answers. The ENRResponse is decoded and its identity checked against the packet's signer (decode_enr). ForkFilter::verdict then sorts the node: Foreign nodes are counted and removed from the table, Compatible and Unknown ones are emitted. Every second, sweep_enr hands over nodes that did not answer within 3 s: the filter fails open, and the eth Status check at the handshake stays the authority. While the pool is at its target it dials nothing, so second-hand Neighbors entries skip the exchange and are handed over unjudged.

A second thread runs through the code: the TCP port. A Neighbors entry is hearsay from a relayer. A Ping's FROM endpoint is the node's own signed claim, and its ENR is its own signed record. The exchange keeps the node's own word per address family (Judgement::tcp_port: [Option<u32>; 2]) and lets hearsay replace only a port that was itself hearsay or a guess. Port 0 means “takes no TCP connections on this family”, and the pool never dials it.

  • borrowing Copy out, then mutate. enr is a &mut into self.enr. The first match turns the borrowed lookup enr.verdicts.get(...) into Seen, an enum that holds no references (Judged carries a copied Option<u32>). The borrow of the map ends there, and the second match is free to call enr.verdicts.get_mut or remove.
  • borrowing Non-lexical lifetimes. self.forget(...) and self.emit(...) need all of self, while enr still borrows part of it. This compiles because a borrow lasts until its last use, not to the end of its scope: in each arm, enr is used for the last time before self is touched. In the let … else at the top, the else branch has no enr at all, so it may call self.emit directly.
  • ownership let mut entry = entry; moves the parameter into a new, mutable binding. Parameters are immutable unless declared mut, and rebinding is the idiom for “mutable from here on”.

borrowing ownership Two more variants of the same discipline sit nearby. handle_enr_response (lines 1117–1211) first borrows the pending entry (let Some(pending) = enr.pending.get(&sender)) only to check the request hash, and later shadows it with the owned value let Some(mut pending) = enr.pending.remove(&sender). sweep_enr (lines 1215–1262) collects the expired keys into a Vec before removing them, because a map can't be mutated while it is being iterated, and collects the nodes to emit into another Vec, because self.emit needs &mut self while enr is still in use.

concurrency interior-mutability The std guard (table) is released at the end of the if let body, before anything else happens. The event is then offered with try_send. Blocking on a full channel would freeze every branch of the single-task loop, including stop. Dropping an event is harmless, because the table already holds the entry.

domain An ENRRequest is answered only from a node whose pong we verified, keyed by address and checked against the signing key (is_bonded), and only within the Ping rate limit. Otherwise a spoofed source address could make us send a signed record to a victim, an amplification attack; geth applies the same checkBond rule. Expired requests are ignored so a captured one can't be replayed.

The EIP-2124 fork-id pre-filter (#539). discv4 is one DHT for every Ethereum network, so a Neighbors reply mixes mainnet, testnets, Gnosis and others; before this file the pool learned a node's chain only after a full TCP, ECIES, Hello and Status exchange. A node's ENR carries its fork id in the eth entry, [[fork-hash, fork-next]]. ForkFilter accepts the pinned hash and its successor, and treats a hash that could be our chain one fork ahead of this build (a plausible activation time, on the beacon epoch grid) as Unknown rather than Foreign, so a stale build can still reach upgraded peers and learn of the fork. The file also decodes remote ENRs and signs our own minimal one. dnsdisco.rs uses the same filter for its leaves.

  • enums-patterns Match arms are tried in order, and guards make that order part of the logic: a hash in accepted is Compatible before the plausibility guard is even evaluated. The last arm, Some(_), catches every parsed hash that passed neither guard.
  • iterators-closures .map(...).any(...) is lazy: any stops at the first true, so at most one activation time is computed per accepted hash. Like Java streams, nothing runs until the terminal operation pulls.
  • domain forkid::activation_of finds the one timestamp T that turns our hash into the observed one. Another chain's hash lands on an epoch boundary inside the window only by chance, which the module doc puts at about one in 25,000 per baseline.

borrowing bytes-strings domain Enr::decode(&mut &raw[..]) passes a mutable reference to a slice: alloy_rlp's decoder advances the slice past what it consumed, like a read cursor. The slice is a view into raw; no bytes are copied until <[u8]>::to_vec copies the eth entry out. The signer check matters: without it, a node could answer with someone else's validly signed record.

EIP-1459 DNS node lists for the EL pool (#539, part 3). A network publishes its node list as a Merkle tree of DNS TXT records under a domain: a signed root (enrtree-root:v1 e=… l=… seq=… sig=…), branch records listing child labels, and leaves that are signed ENRs. Each label is the base32 of the first 16 bytes of the keccak of its record, so a resolver can withhold records but can't add any. The walk is bounded (lookups, depth, deadline) and its order random. DnsSeeder walks once when first asked, then again every 4 minutes while the pool stays below target; it keeps up to 600 candidates, hands them to the dialer in batches of 10, and nudges up to 32 UDP endpoints into discv4. DNS discovery runs only where the host switched it on, and never under Tor: the query itself tells the local resolver which network this node is on.

An async trait you can put behind dyn

  • traits-generics async The walk takes resolver: &dyn TxtLookup, so production and tests can pass different resolvers at run time. A trait with an async fn can't be used as dyn, because each implementation's future is a different, unnamed type. The fix is to return one concrete type for all of them: Pin<Box<dyn Future<…> + Send + 'a>>, a heap-allocated future behind a pointer. It's like a Java interface method returning CompletableFuture<List<String>>.
  • lifetimes 'a ties the future to both borrows: it may use self and name until it completes, so neither may be dropped first. Box::pin(async move { … }) moves those two references (not the resolver) into the future.
  • iterators-closures bytes-strings TXT strings are at most 255 bytes, so a long ENR arrives in segments. The inner collect::<String>() concatenates one record's segments; String::from_utf8_lossy returns a Cow that borrows when the bytes are valid UTF-8 and allocates only when it must replace bad bytes.

The walk

iterators-closures domain An explicit stack replaces recursion, which an async fn could not do without boxing. visited is the loop protection: a label resolved once is never fetched again, so a label listed by two branches costs one lookup. A label that fails the depth check is not marked visited, so a shorter path can still reach it. find(|r| label_of(r).eq_ignore_ascii_case(&label)) picks the one record that hashes to its own name, which is the tree's integrity check. Just after the excerpt (lines 498–503), branch children are shuffled before being pushed, so a tree larger than one walk's budget is seen in a different part each time.

Claiming a walk

  • lifetimes borrowing Borrowing from one of two owners. resolver borrows either the caller's Arc (the Fixed arm) or a freshly built SystemResolver. let system; is declared before the match, and assigned inside the arm, so the value lives until the function returns. Declared inside the arm, it would be dropped at the arm's end while resolver still pointed at it, and the code would not compile.
  • smart-pointers traits-generics r.as_ref() turns &Arc<dyn TxtLookup> into &dyn TxtLookup without touching the reference count.
  • async ownership Cancellation by drop. begin_walk_if_due sets walking; WalkClaim's Drop clears it. Because walk_once binds the guard (let _claim = WalkClaim(self);), the flag is cleared whether the walk returns, its future is dropped by the pool stopping, or it unwinds. Rust has no finally; a value's destructor is the equivalent, and it also runs on cancellation, which Java's finally has no notion of.
  • ownership The name matters. let _claim = … keeps the guard until the end of the scope. let _ = … would drop it immediately, releasing the claim before the walk even started.
  • lifetimes WalkClaim<'a>(&'a DnsSeeder) borrows the seeder, so the compiler proves the guard can't outlive it. impl Drop for WalkClaim<'_> uses the anonymous lifetime: “for any lifetime”.

ownership interior-mutability Elsewhere in the seeder: merge calls std::mem::take(&mut st.pool) to move the vector out of the mutex guard (leaving an empty one), passes it by value to the pure merge_candidates, and stores the result back. take_batch indexes st.pool[(start + i) % len] without .clone(), because an Enode is (SocketAddr, [u8; 64]), which is Copy. forbidden = || !(self.policy)() needs the parentheses: policy is a boxed closure stored in a field, and self.policy() would look for a method of that name.

Index of eth/66–71: messages is a re-export shim of myotis-wire's eth codecs (stop 5), and session is the handshake and one-request-at-a-time correlation, twin of the Java EthHandler.

An eth session on one RlpxConnection<S>. handshake (capped at 30 s) sends our Hello, reads the peer's, picks the highest common eth version (66–71) and snap version (1 or 2), sends our Status in that version's format with the fork id in effect now, reads the peer's Status while answering Pings, and rejects the peer unless network id and genesis match. Afterwards it serves requests one at a time: headers, bodies, proof-verified snap reads, header-chain verdicts, and a transaction push confirmed by a Ping/Pong round trip. into_parts hands the connection to the concurrent ManagedPeer; the Tor path keeps using the session directly.

Gotcha: a timeout in the middle of a frame

await_response (lines 293–316) wraps recv_answering_ping in timeout(remaining, …). A timeout can cancel read_exact in the middle of a frame, and tokio documents read_exact as not cancel-safe. EthSession has no torn-state marker, so after such a timeout the session is out of step with the stream and must not be reused. The Tor read builds a new session for each candidate attempt and drops it when the attempt ends (reader.rs, around line 6410).

Index of snap/1 and snap/2: messages and fetch are re-export shims of myotis-wire's snap codecs and verification (stop 5). snap shares the eth peer's RLPx connection, and the two protocols are told apart by message code; the first snap code is 0x21, 0x22 or 0x24 depending on the eth version. The request methods are on EthSession and ManagedPeer.

The managed-peer actor. A handshaken session is split into a reader, owned by a background task, and a writer shared behind a lock. Many requests can be in flight at once, each matched to its response by (reqId, code) through a map of oneshot channels. Besides delivering responses, the read loop answers Ping, serves GetBlockHeaders from the pool's shared window, answers other Get* requests with empty responses, records the peer's announced head (eth/69 BlockRangeUpdate), reports gossip sightings of our own transactions, and fails every waiter on disconnect, recording why. Much of the file defends against async cancellation. The writer and its torn marker

  • async Cancellation safety by hand. torn is set before the write's .await. If the caller's future is dropped mid-write (write_all is not cancel-safe), nothing after the .await runs, the flag stays set, and the next lock holder refuses the stream instead of writing after a partial frame with an already-advanced MAC.
  • async error-handling New since September: w.torn = result.is_err();. A send that completed with an error leaves the stream just as corrupt as a cancelled one, so the marker stays set for it too, and a request already queued on the lock can't write after it.
  • interior-mutability async The guard w is a tokio::sync::MutexGuard, held across writer.send(…).await. That is the point of an async mutex: one frame at a time on the wire. A std guard held across an .await would block the executor thread and make the future non-Send.
  • enums-patterns inner: Option<RlpxWriter>: close() takes the writer out, which drops it and closes the write half; later sends see None and fail with “peer writer closed”.

A task-local mark for hedged reads

  • async macros tokio::task_local! declares a value that is visible only to code polled inside a scope. REQUEST_SENT.scope(sent, fut) wraps fut so that anything it calls, however deep, can reach the value without it being passed as a parameter. Java's ThreadLocal is the closest analogue, but it would be wrong here: a tokio task can move between threads at every .await, and several tasks share a thread.
  • smart-pointers interior-mutability The caller keeps one Arc clone, the scoped future gets the other. std::sync::OnceLock accepts only the first set, so the mark records the first request frame an attempt wrote. try_with returns an error outside a scope, which let _ = ignores: mark_request_sent() is a no-op for requests that are not part of a hedged read.
  • domain Why it exists: every request first waits for the shared writer, which a large served response or a stuck write can hold for up to 30 s. The hedged race in reader.rs and evm.rs judges a slow peer from the moment its request actually left, not from when the attempt was created.

The guard that cleans up a cancelled request

  • ownership async PendingGuard lives on the stack of the request future. If that future is dropped at any .await, the guard is dropped with it, and its Drop removes the orphaned map entry. Every path that completes normally sets armed = false first, because there the entry is already gone.
  • async smart-pointers Drop::drop is synchronous and can't .await the async mutex, so it spawns a tiny task that can. It clones the Arc and copies the id into an async move block, because the spawned task must own everything it uses ('static). Handle::try_current() fails during runtime shutdown, when the whole map is being dropped anyway.

concurrency deliver (lines 128–143) is the other side: the read loop removes the entry only if it expects this code, sends the payload through the oneshot, and stamps last_response only when the send succeeded. A late answer to a cancelled request can beat its guard's spawned removal, and a frame nobody receives must not count as proof that the peer is responsive.

Splitting and spawning

One request

  • concurrency interior-mutability Check and insert under one lock. fail_all sets closed while holding the same pending lock. So a request either inserts before the drain (and receives its Err) or sees closed and bails. It can never hang on a dead connection.
  • async smart-pointers No .await lies between the insert and arming PendingGuard: the block's guard is dropped at its }, and the next statement arms the guard. If the future is dropped at any later .await, the guard removes the entry.
  • iterators-closures encode: impl FnOnce(u64) -> Vec<u8> builds the body once the id is known: a LongFunction<byte[]> that runs exactly once. Callers pass closures that borrow their own arguments, such as |id| messages::encode_get_block_bodies(id, hashes).

error-handling async The rest of request (lines 560–597) has three outcomes after timeout(REQUEST_TIMEOUT, rx): Ok(Ok(result)) means the response arrived; Ok(Err(_)) means the sender was dropped because a disconnect drained the map; Err(_) means we gave up, so the stale entry is removed. It's Java's future.get(15, SECONDS), with each outcome spelled out. A timeout_streak atomic makes only the first timeout of a silent streak a WARN line naming the peer.

The read loop

read_loop (line 1111) takes mut reader: RlpxReader by value: the task owns the reader outright. It loops on reader.recv().await and classifies each frame: transaction gossip, BlockRangeUpdate (only on eth/69 and later, where code 0x21 is free; on eth/68 it is the snap base), Ping, Disconnect, served headers, empty answers, and finally responses.

interior-mutability async The sent-transaction watch is a std mutex (SharedSentTxWatch). Each guard lives inside its own block expression (let (watching, unseen) = { let mut w = watch.lock().unwrap(); … };) and dies at the block's }, so the hash decoding between the two blocks runs unlocked, and no guard spans an .await. Otherwise the future wouldn't be Send, and tokio::spawn(read_loop(…)) wouldn't compile.

  • enums-patterns iterators-closures request_id.and_then(|id| empty_answer(code, &snap_codes, id, eth_version)) chains two Options: no request id, or not a Get* code, both end in None. The answer echoes the request's id, so the asking peer can match it.
  • ownership deliver(…, frame.payload) moves the payload Vec out of the frame and on through the oneshot to the waiting request. The bytes are never copied between socket and caller.
  • concurrency The lines after the loop are a backstop: every break already went through fail_all, but any future exit path still leaves the peer marked closed, with a reason.

Closing, from either side

interior-mutability concurrency The reason is written before the flag, so a caller that sees closed and then asks why always finds an answer. set_close_reason keeps the first reason: a write failure that follows the remote's Disconnect must not overwrite it (#539). map.drain() moves every Pending out of the map, and entry.tx.send(…) consumes each sender; let _ = ignores a requester who already gave up.

interior-mutability smart-pointers In close, the std guard created in let task = … .take(); dies at the ;, before task.await. In Drop, get_mut() needs no locking at all: &mut self already proves exclusive access, and the mutex just hands out its contents. close() stores with Ordering::Release while the rest of the file uses SeqCst. That is valid, just inconsistent. Drop only aborts the task: when the last Arc<ManagedPeer> goes, the reader is dropped with the task and the writer with the struct.

enums-patterns domain Coverage (lines 216–231) derives PartialOrd and Ord. For an enum, the derived order is the declaration order, so Covers < Near < Unknown < Behind, and the pool sorts peers for its read ladder by that order. The judgement compares the peer's head with our anchored head as observed at the same moment (KnownHead::anchored_then), so it doesn't go stale as the observation ages; an observation older than five minutes simply counts as Unknown.

domain Two defenses in the eth requests are worth knowing. Headers a peer returns enter the pool's serve window only if they are the ones we asked for (by number range, or by hash): a hostile peer could otherwise pin the window at fabricated far-future numbers (lines 650–665). Block access lists are kept only when their keccak matches the commitment in the header, and a mismatch is reported as forged (verified_bal_entries, lines 1309–1320).

Persists execution-layer peers that reached a READY session, so a restart dials proven snap servers first. The Tor reserve: verified snap servers set aside for Tor reads and sends, persisted beside the peer cache as peers-tor[-net].cache. A node moves in from the peer cache and from then on the pool never dials it directly, so no direct session of ours can be paired with a Tor session to it. Its last direct contact is stored with it, and Tor uses it only once TOR_DIRECT_SEPARATION has passed. Three Tor dials in a row that the node refuses send it back to the peer cache. The reserve holds about a third of the verified peers, at most 24, and none while fewer than two are known. The Java engine has no Tor mode and never reads this file.

  • iterators-closures sort_by_cached_key computes each element's key exactly once, then sorts. That matters because the last key component, draw(node), is meant to be random per call. sort_by_key calls the key function on every comparison; a random key would then contradict itself between comparisons, and since Rust 1.81 the sort may even panic when it detects an inconsistent order. Here the draw just shuffles peers of equal rank.
  • borrowing ownership Vec<(&[u8; 64], &Reserved)> holds borrows into self.entries; sorting them moves only pointers. as_peer builds owned CachedElPeers at the end, so the returned vector borrows nothing. BTreeMap<[u8; 64], Reserved> works because fixed-size arrays implement Ord.
