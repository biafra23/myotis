myotis-consensus: the light client as a state machine

SSZ decoding, hash_tree_root, Merkle branches, fork versions, sync-committee signatures, and the store that ties them together. The store is a small state machine: it holds one committee, then two, then rotates. Every update passes a fixed sequence of gates before it may move it. Since the last edition the crate has learned the Gloas fork, where a light-client header stops carrying the execution payload. Like myotis-core, the crate performs no I/O and never reads a clock: myotis-net passes “what time is it” in as a slot number. Watch how Option::take, Box, clone and borrow scopes move a 24 KB committee and a 470-byte payload header around without surprises.

How the files fit

Bytes from a peer are decoded by types. Before Gloas the decoders sniff the fork layout from offsets. From Gloas on they cannot, so the caller names the format with an LcFork value from fork. LightClientProcessor in store first runs the cheap gates: the sync-committee period (which also picks the verifying committee), the next-committee adoption rule, and the wire-shape check. Only then does it call verify, which checks the BLS aggregate through myotis-bls under the fork version that fork picks for the signature slot. ssz and spec check the Merkle branches against the gindices of the right fork, and the result updates LightClientStore. snapshot persists the store in a byte format the Java engine reads too.

The crate is now no_std-capable: with default-features = false it builds on bare-metal targets with only the alloc crate. That is why every module opens with an alloc::… import line (see lib.rs).

What Gloas changes for a light client

Gloas is the consensus fork that brings enshrined proposer-builder separation (EIP-7732) and progressive SSZ containers (EIP-7688). The code shows four consequences for a light client, and each one lands in a different file.

  1. The header proves a block hash, not a payload. A Gloas beacon block body carries a signed payload bid instead of the execution payload. The payload itself is revealed separately and may be withheld. So a Gloas LightClientHeader carries only a 32-byte execution block hash, and that hash is the bid's parent_block_hash: the payload of the parent, which the chain has already imported. There is no state root, block number or timestamp in it any more. Those have to come from the execution header that this hash pins. In the code this is the new enum HeaderExecution in types.rs.
  2. Everything is fixed-size, so nothing can be sniffed. With no variable-length payload header left, every Gloas container has no offsets. The only honest way to know the format is the fork of the object's slot, which the req/resp context bytes tell the caller. The decoders gained decode_for(LcFork, bytes), and the store checks that each header has the shape of its attested slot's fork.
  3. The proof indices move and stop being derivable. The Gloas BeaconState is a progressive container. The field indices of finalized_checkpoint, current_sync_committee and next_sync_committee (20, 22, 23) are the same, but their generalized indices are not (1 << depth) + field any more. spec.rs pins them as constants, and the store selects them by the fork of the attested slot.
  4. The transition needs a padded proof. In the first epochs after the fork, a Gloas update's finalized header is still a Fulu block. It travels in the Gloas shape, and it proves its block hash at the Deneb-era gindex 812 (depth 9), padded with two leading zero nodes to the 11-node vector. ssz::verify_normalized_merkle_branch accepts the padding only if the extra nodes are all zero.

One thing does not change: the signing domain. A signature is still verified under the fork version of the epoch of max(signature_slot, 1) − 1, while the wire format follows the slot's own fork with no off-by-one. At the first Gloas slot the objects are Gloas-shaped, but a signature made at that slot still uses the Fulu domain (fork.rs pins both in one test).

Mainnet-preset constants, the Gloas gindex constants, generalized-index (gindex) helpers for the pre-Gloas branch depths, and the sync-committee period math. A gindex numbers the nodes of a binary Merkle tree: the root is 1, and the children of node g are 2g and 2g+1. So its bit length minus one is the node's depth, which is exactly what gindex_depth computes.

  • domain Why constants. The comment says it: the Gloas state is a progressive container, so the depth-derived formulas below give 553, 2070 and 2071 for the Gloas depths, not 735, 2945 and 2946. A unit test (gloas_gindices_are_constants_not_depth_derived) pins both the values and the mismatch.
  • methods pub const fn can run at compile time, so GLOAS_EXECUTION_BRANCH_LEN is computed from the gindex instead of being typed in a second time. leading_zeros is a single CPU instruction on a u64.
  • error-handling Two kinds of failure, two tools. A bad branch depth comes from data, so it returns gindex 0, which can never verify: a safe rejection. 1u64 << 64 would overflow, and with overflow checks enabled that panics.
  • bytes-strings A function body's final expression without a semicolon is its return value: checkpoint_gindex * 2 + 1. The u64 suffix fixes the literal's width before the shift. The * 2 + 1 steps one level further down into the Checkpoint container, to its field 1 (root).

error-handling domain The earlier part of this doc comment (lines 92–103) explains that 8192 slots per period is right on gnosis only by coincidence (16-slot epochs × 512 epochs), so the period length must be configuration the wallet is told. A zero period is a build-time configuration mistake, so it gets assert!, which stays on in release builds, unlike debug_assert!.

Hand-written SSZ primitives: SHA-256 pair hashing, merkleization with padding, container and list roots, Merkle-branch verification (now in two flavors), and checked little-endian readers. Hand-written because the pre-Gloas light-client wire types are fork-polymorphic, with sizes sniffed at run time, which derive-based SSZ libraries can't express.

  • borrowing layer[i] = sha256_pair(&layer[2 * i], &layer[2 * i + 1]); The two shared borrows on the right end when the call returns, before the indexed write happens. That's why an in-place reduction compiles.
  • traits-generics In sha256_pair (line 21), h.finalize().into() converts the digest into [u8; 32]. The target type is inferred from the function's return type.
  • ownership let mut value = *leaf; copies 32 bytes out of the reference, since Root = [u8; 32] is Copy, then the loop overwrites the local copy. Bit i of the index says whether the running value is the right or the left child at level i. Only the low depth bits are read, so passing the full gindex works.
  • domain The normalized check is new. It accepts a branch that is longer than the gindex's depth only when every extra leading node is zero, then verifies the rest normally. That is how a Fulu header in the Gloas shape fits its 9-level proof into an 11-node vector.
  • error-handling enums-patterns let Some(extra) = branch.len().checked_sub(depth) else { return false; }; turns “shorter than the depth” (an underflow) into a rejection. && short-circuits, so the hashing never runs on a dirty pad.
  • iterators-closures branch[..extra].iter().all(|node| *node == [0u8; 32]): a sub-slice, an iterator over references, and a closure that dereferences each one to compare the arrays by value.

error-handling bytes-strings data.get(offset..offset + 4) is None when out of range. Inside .map(…) the slice is guaranteed to be exactly 4 bytes, so try_into().unwrap() cannot fail. This is an unwrap with a proof beside it.

One header, two shapes

  • enums-patterns A sum type. In Kotlin you would write a sealed class with two subclasses; in Java a sealed interface with two records. A Rust enum variant can carry data, and a value is exactly one variant at a time. The compiler forces every match to handle both, so no code path can forget that a Gloas header has no state root.
  • smart-pointers ownership Why Box. An enum is as large as its largest variant. An ExecutionPayloadHeader is about 470 bytes inline (eight roots, two Vec handles, six u64, three Option<Root>), against 32 for the hash. Box<ExecutionPayloadHeader> moves the payload to the heap and leaves an 8-byte pointer in the enum, so a Gloas header doesn't pay for space it never uses. The Box owns its contents: dropping the header frees them, and clone() deep-copies them.
  • traits-generics impl Default for HeaderExecution is written by hand because #[derive(Default)] on an enum needs a #[default] unit variant. Box::default() builds a boxed ExecutionPayloadHeader::default(), which is what lets LightClientHeader keep its #[derive(Default)].
  • enums-patterns borrowing match &self.execution matches through a reference, so p binds as &Box<ExecutionPayloadHeader> and h as &Root. *h copies the 32 bytes out. p.as_ref() turns the &Box<T> into a plain &T.
  • enums-patterns ownership shape() writes match self.execution without &, even though self is only borrowed. That compiles because the patterns use _, which binds nothing, so nothing is moved out. Write Payload(p) there and the compiler refuses: it would have to move the Box out of borrowed data.
  • domain shape() is the shape the bytes were decoded from, not the fork of the header's slot. The two differ for exactly one case: a Fulu finalized header carried by a Gloas update.

error-handling decode_gloas just above (lines 379–396) requires len() == GLOAS_SIZE exactly, not “at least”. One byte short or one byte long is an Err: there is no tail to silently ignore. It reads the 11 branch nodes with read_roots, which collects into an Option<Vec<Root>> (lines 433–437).

A Gloas update: offsets as constants

  • modules-cargo A const inside a function is still a compile-time constant. Each offset is built from the previous one, so the layout reads top to bottom like the spec's container definition.
  • iterators-closures let truncated = || SszError(…); captures nothing, and a closure that captures nothing is Copy. That is why the same truncated can be passed by value to ok_or_else four times.
  • error-handling The slices &ssz_bytes[..H] and so on index directly, which would panic out of range. They cannot: every bound is a constant below the exact length checked on line 564.

macros domain const _: () = assert!(…); is Rust's static assert. The expression is evaluated at compile time, and a failing assert! in a const context is a build error. The fact being proven is that a Gloas object is always smaller than the smallest canonical pre-Gloas one. So if the sync loop receives an object under a fork digest it does not recognize, the size alone tells the two formats apart without misreading. The comment names the consumer, ChainConfig::lc_fork_of_chunk in myotis-net.

Signature verification in three functions: compute_domain, compute_signing_root, and verify_sync_aggregate. The last requires at least 2/3 participation using integer math, flattens the participating pubkeys, and makes a single myotis_bls call. Gloas changed nothing here: the signature still covers only the beacon header.

  • borrowing lifetimes &attested_header.hash_tree_root() borrows a temporary. Temporaries live until the end of the enclosing statement, so the reference stays valid during the call.

A network's append-only list of (activation_epoch, fork_version), that chain's slots per epoch, and now the epoch at which Gloas activates. It answers two different questions. “Which version signed an aggregate at signature_slot?” uses the epoch of max(slot, 1) − 1. “Which wire format do this slot's objects use?” uses the slot's own epoch. enums-patterns traits-generics A data-less enum that derives Copy, PartialEq and Eq behaves like a Java enum constant: it is passed by value, compared with ==, and costs one byte. There are only two variants because the pre-Gloas decoders still tell Capella through Fulu apart by sniffing; only Gloas has to be named.

  • traits-generics Invariants through privacy. The fields are private and new (lines 80–97) is the only constructor. It asserts a non-zero slot length, a non-empty list, a genesis entry at epoch 0, and strictly ascending epochs (using forks.windows(2)). That is what makes newest()'s self.forks[self.forks.len() - 1] safe.
  • error-handling The constructor panics on invalid geometry, deliberately. These values come from compile-time constants, and a Result nobody could meaningfully handle would just hide the mistake.
  • ownership borrowing new(…, forks: &[(u64, [u8; 4])]) borrows the caller's constant list and stores an owned copy (forks.to_vec()).
  • ownership methods A consuming builder. with_gloas_epoch(mut self, epoch) -> Self takes the schedule by value, changes one field, and hands it back. A caller writes ForkSchedule::new(…).with_gloas_epoch(10). The original binding is moved into the call, so no other code can hold a half-configured copy. The mut belongs to the parameter binding, not to the type.
  • enums-patterns Some(gloas) if epoch >= gloas => LcFork::Gloas is a match arm with a guard. If the guard is false the arm doesn't match and _ catches it, which also covers None: a chain with no Gloas date is pre-Gloas forever.
  • iterators-closures .any(|(activation, _)| *activation == epoch) destructures each borrowed tuple in the closure's parameter. activation is a &u64, hence the *.

  • domain signature_slot.max(1) - 1 is the spec's max(signature_slot, 1) - 1. The aggregate signs the block of the previous slot, so the first slot of a new fork's epoch still signs under the old version.

testing domain The two rules side by side: slot 640 is the first Gloas slot, its objects are Gloas-shaped, and a signature at that slot still verifies under version B (the fork before). The message on the second assert (“no date is not a far-future date”) records a design choice: a missing Gloas epoch is None, never u64::MAX.

The state and how it rotates

ownership initialize takes the header and committee by value. It needs the header twice, so it clones once (line 70) and moves the original (line 71). After line 71, header can't be used. In Java, both fields would simply alias one object. The constructor above it, Self { slots_per_period, ..Self::default() }, uses struct update syntax: every field not listed comes from Default.

  • ownership enums-patterns self.next_sync_committee.take() moves the 24 KB committee out and leaves None, exactly the state the store needs next, with no copy. It's mem::replace(&mut x, None) with a friendlier name. The old current committee is dropped when it's overwritten.
  • domain Two triggers, one effect. apply_next_when_period_changes rotates when an applied update's finalized slot crosses into a later period. force_rotate_if_past_period rotates when the caller's wall-clock estimate is past the store's period. Both need a held next committee: without one there is nothing to rotate into.

The bootstrap check

  • error-handling enums-patterns Result<(), BootstrapReject> is Rust's “success with no value, or one of three reasons”. The caller in myotis-net/src/sync.rs writes if let Err(reason) = processor.verify_bootstrap(&bootstrap) and logs the reason through its Display impl (lines 584–592).
  • enums-patterns let (depth, gindex) = match fork { … }; A match is an expression, here producing a tuple that is destructured right away. The Gloas arm uses constants; the pre-Gloas arm derives both from the branch's length.
  • domain The checkpoint pin itself (does this header's root equal the root we trust?) is the caller's job, as the doc comment says. This function proves everything else.

process_update, gate by gate

  • error-handling enums-patterns let Some(committee) = self.committee_for(sig_period) else { …; return false; }; binds the reference or leaves. The else block must diverge (return, break, panic), which the compiler checks.
  • macros tracing::debug!(store_period, sig_period, have_next = …, "…") logs structured fields. A bare name like store_period is shorthand for store_period = store_period, and ? (used further down) means “format with Debug”.

domain The adoption gate (new). An update carries the next committee of its attested state, which is the committee of period(attested) + 1. The update that slipped through before is the last block of P−1, signed at the first slot of P. It passes the committee gate, its signature verifies against our current keys, and its next committee is genuinely committee(P), with a genuine branch. Adopting it would install committee(P) as P+1's keys at the next rotation, and every P+1 update would fail BLS from then on. The comment also explains a conscious deviation: the spec's apply step wants the finalized header in the store's period too, but this client adopts from the attested state so catch-up doesn't stall at a period that never finalized.

  • borrowing lifetimes Non-lexical lifetimes. committee is a &SyncCommittee borrowed through &self. While it is alive, nothing may mutate self. Its last use is the BLS call (line 383), so the borrow ends there, and the &mut call self.store.update_next_sync_committee(…) on line 445 is allowed. Move a use of committee below line 445 and the code stops compiling. The &self calls in between (verify_finality_branch, verify_header) are shared borrows, which may overlap freely.
  • domain used_next = sig_period != store_period computes a bool just for the log line, so a reader of a failure knows which committee's keys were tried.
  • ownership update.next_sync_committee.clone() copies 24 KB because the update is only borrowed (&LightClientUpdate); its fields can't be moved out. The alternative signature, process_update(&mut self, update: LightClientUpdate), would let the store move the committee but would force every caller to give up its update.
  • domain The order matters: a held next committee is never overwritten. The execution branches are checked separately (step 6, lines 411–419) because the sync-committee signature does not cover the execution part of the header.
  • domain update_optimistic receives the signature slot, not the attested header's slot. The doc on optimistic_slot() (lines 138–146) says why: the value orders updates, and a slot to show the user is optimistic_header().beacon.slot (#658).

borrowing Option<&SyncCommittee> lends, never copies. The returned reference's lifetime is tied to &self by lifetime elision, which is exactly why the NLL point above matters.

Stale is not a win

  • enums-patterns A three-way answer instead of bool. Tuples compare field by field, so (finalized, optimistic) snapshots before and after tell whether anything moved.
  • domain The doc tells the incident: on Sepolia's Gloas fork day, every Lighthouse light-client server stopped at the fork but kept answering first, with an update that still verified. Counting that as the poll's win hid the one server (roost) that was current.

Binding the beacon header to the execution layer

  • enums-patterns borrowing Matching a tuple. match (&header.execution, slot_fork) builds a temporary tuple of a reference and a Copy enum, then matches both at once. Four combinations, four arms; one of them is a flat false. payload binds as &Box<ExecutionPayloadHeader>, and payload.hash_tree_root() works anyway because method calls auto-dereference through & and Box.
  • domain The doc bullet list is the clearest statement of the Gloas rules in the crate. Note the limit it records: Capella's own block-hash gindex (412) is not accepted, because no header this client meets is older than Deneb, and a Capella header's genuine proof simply fails here.

domain verify_execution_branch (the associated function at lines 227–229, still used by the corpus tests) is kept for callers that hold no fork schedule. It now refuses a Gloas-shaped header outright, so a call site that should have moved to verify_header fails loudly instead of guessing.

A back door around “refuses zero”The doc on LightClientStore::new says the store refuses a zero period length instead of defaulting to the mainnet preset. But the struct also derives a public Default, which sets slots_per_period to 0, and the getter slots_per_period() (lines 53–59) maps 0 to the mainnet preset. So LightClientStore::default() quietly gets mainnet geometry. Nothing in the snapshot calls default() directly; new uses it only as the base for struct update syntax.

A byte-exact codec for the verified store, shared with the Java engine: switching engines resumes from the same file instead of re-bootstrapping. Top-level integers are big-endian (Java DataOutputStream), the beacon header is embedded as SSZ, and the file is bound to its chain by the genesis validators root. Version 2 adds a one-byte shape tag per header for Gloas, and is written only when a header needs it. Any malformed, foreign or unknown-version input decodes to None, and the caller falls back to the checkpoint.

  • domain Forward compatibility by restraint. v1 is chosen whenever both headers are payload-shaped, so a store that never saw Gloas writes the same bytes as before and an older build can still resume it. v2 appears only once a Gloas-shaped header is held, which is state an older build couldn't follow anyway.
  • borrowing enums-patterns match &s.next_sync_committee matches through a reference because SyncCommittee isn't Copy; moving it out of borrowed s is illegal. Compare the Electra tail in write_execution (line 228), where e.deposit_requests_root is Copy and is matched by value.
  • macros debug_assert_eq! documents an invariant that serialize guarantees, and checks it only in debug builds.
  • iterators-closures write_branch writes exactly len nodes whatever it is given: .take(len) truncates, and for _ in branch.len()..len zero-pads. When branch.len() > len that range is empty, not an error: a Rust range whose start is past its end simply yields nothing.
  • enums-patterns Constants as patterns. SHAPE_PAYLOAD => compares against the const. That works because the name refers to a constant in scope. A lowercase name that isn't a constant would instead bind any value and match everything, which is why Rust insists on UPPER_CASE for constants. The _ => None arm refuses an unknown tag rather than guessing.
  • error-handling BeaconBlockHeader::decode(…).ok()? converts a Result into an Option and then propagates None, so a decode error becomes “not a valid snapshot” without a message.

lifetimes This is the Reader<'a> from the primer, and the stop's clearest lifetime lesson: impl<'a> names the buffer's lifetime, and fixed returns slices tied to the buffer, not to &mut self. So a returned slice may outlive the &mut borrow of the reader, and a caller could keep it while it reads on. Helper functions take r: &mut Reader<'_>, where '_ means “some lifetime I don't need to name”. self.pos.checked_add(len)? makes even a wild length from a corrupt file a clean None.

The test suite

Eight integration tests, all network-free. Two replay the committed mainnet corpus end to end, one reads the official consensus-specs Gloas vectors, and five are regression tests for real bugs or forks (#295, #423 on two paths, the adoption rule, and Gloas).
