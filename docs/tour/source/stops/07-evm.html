myotis-evm: an EVM over verified state

The Rust engine's EVM: eth_call, eth_estimateGas, eth_createAccessList, debug_traceCall and ENS resolution, executed by revm. Every piece of state revm reads, BLOCKHASH included, comes through one trait whose implementations may return only proven data. The crate still does no I/O. It is where you meet shared ownership (Arc<dyn Trait>) and interior mutability in earnest, in both of its forms: a Mutex where the type must be shareable across threads, a RefCell where it never leaves one.

The shape of a call

A host asks myotis-net's ElReader (stop 14) for an answer. The reader builds a BlockContext from the verified head and an EvmExecutor over a fresh network-backed oracle plus long-lived shared caches, and runs it on a blocking thread. Inside this crate, spec_for picks the fork rules. A per-call OracleDatabase answers each revm read from four layers in order: caller overrides → per-call view cache → cross-call proof cache → verified oracle fetch. A “prefetch convergence loop” keeps the number of slow, one-at-a-time network round-trips small.

The executor now has two families of entry points. The view-call family (call_view, call_view_from, call_view_overridden, create_view, estimate_gas) takes a target, calldata and value. The transaction-object family (call_tx, estimate_tx, create_access_list, trace_call) takes a whole TxRequest: gas, fees, nonce, access list, EIP-7702 authorizations. Every field the request names is applied, or the request is refused. TxRequest itself, the tracers and eth_simulateV1 live in the files of stop 8. This stop covers the foundation they all stand on.

EvmError is the closed set of ways an EVM request can end other than with success bytes: oracle failure, revert (with raw data), out of gas, other halt, fork too old, unsupported chain, rejected envelope, a loop that did not converge, and seventeen newer variants for transaction objects, estimates, access lists and simulations. Most of the new ones carry geth's exact wording in Display, because wallets match on those strings. Two classifier methods tell a host how to serve each one.

  • enums-patterns matches!(value, pattern) is a macro that expands to a match returning true or false. The pattern uses | to list alternatives and { .. } to ignore fields. It can reach into a nested enum: line 144 matches only the BlockHashUnsupported arm of the wrapped OracleError.
  • domain error-handling Three classes of failure. A refusal can never be answered on this build (a request no transaction could be, an Amsterdam block the fork table does not know), so hosts serve the permanent JSON-RPC code −32602. An infeasible request was understood, and the answer is that it fails within the caller's own limits (gas, funds, fee cap); hosts serve −32000 with geth's message. Everything else (a revert, state that could not be fetched) goes to the host's ordinary mapping. This is the CLAUDE.md rule “apply or refuse” turned into types.
  • error-handling traits-generics impl From<OracleError> for EvmError (lines 170–174) is what lets ? turn an oracle error into an EvmError automatically. The primer walks through this mechanism.

smart-pointers enums-patterns Two variants wrap another EvmError: FailedWithGas { gas, error: Box<EvmError> } and CallFailed { supplied_gas, error: Box<EvmError> } (lines 95 and 110). An enum's size is the size of its largest variant, so an enum that contained itself directly would need infinite size. The Box puts the inner error on the heap and leaves a pointer in the variant. kind() (lines 176–209) returns a &'static str, a string literal that lives for the whole program, so the caller gets a name it can log without owning anything. Its arm EvmError::FailedWithGas { error, .. } | EvmError::CallFailed { error, .. } => error.kind() binds the same name in both alternatives, which Rust allows only when the types agree. kind() exists so an info-level log line names the error without its values (an address, a balance; #532 review).

One call's verified block inputs: the state root (which world to read), the number and timestamp (which fork applies), the opcode inputs (base fee, coinbase, prevrandao, chain id, gas limit) and two optional fields added since September. parent_hash: Option<[u8; 32]> is what BLOCKHASH(N-1) returns and where a header walk starts; None only for a fixture recorded before the field existed. slot_number: Option<u64> is the EIP-7843 slot that Amsterdam headers carry for the new SLOTNUM opcode. Every field must come from the verified header, never from the local clock, because a local timestamp could select different fork rules than the network.

ownership ..BlockEnv::default() fills the remaining fields, like Kotlin's copy(). self.prev_randao is a Copy array, so reading it through &self copies it. self.slot_number.unwrap_or(0) reads an Option<u64>, which is also Copy, so nothing is moved out of self. The doc above the method explains why the 0 is never observable: before Amsterdam SLOTNUM is an invalid opcode, and from Amsterdam on the executor has already refused a context without a slot. OracleDatabase is how revm reads state: a DatabaseRef implementation over the oracle and the caches, pinned to one state_root and built per call. A read tries the caller's overrides, then the per-call view cache, then the cross-call proof cache, then a verified fetch (stored into both caches). For the prefetch loop it has a sentinel mode, which returns a counted, uncached zero placeholder instead of fetching, and it records every account, slot and code hash a run touched in an AccessSet. New since September: the overrides live here, and BLOCKHASH is answered from verified data.

  • smart-pointers Three Arc<dyn …> fields share the oracle and caches with the executor and with other calls. view and track are this call's own mutable state, wrapped in Mutex. A RefCell would make the type non-Sync, and revm's &self database is shared by reference.
  • ownership overrides: StateOverrides is owned by the database: the caller hands its overrides over at construction and they die with the database at the end of the call. The doc comment states the trust rule: an override is consulted ahead of every tier and never written back into any of them.
  • ownership interior-mutability std::mem::take(&mut self.track.lock().unwrap().set) (line 241) moves the access set out through the guard and leaves an empty one. In Java that is a synchronized block doing var s = set; set = new AccessSet(); return s;.
  • interior-mutability borrowing Where each guard dies. Line 248: at the ;. Why DatabaseRef and not Database

revm's Database trait takes &mut self; DatabaseRef has the same methods on &self, and revm implements it for &T and Arc<T> too. With &self, the executor keeps ownership of one database and lends it to every loop iteration, so everything learned in iteration 1 is still there in iteration 2. The price is what you saw above: internal state must use interior mutability. type Error = OracleError; is an associated type: each implementor picks its own error type.

  • enums-patterns borrowing let Some(over) = over else { return …; }; (line 324) is let-else: bind the pattern or run the else block, which must leave the function. over is an Option<&AccountOverride> borrowed from self.overrides, so nothing is copied.
  • iterators-closures borrowing self.account(addr)?.as_ref().map(to_account_info): as_ref turns Option<OracleAccount> into Option<&OracleAccount>, which matches to_account_info(acc: &OracleAccount), and the function's name is passed where a closure would go.
  • domain An override makes the account exist even when the chain has none (geth does the same), which is how a wallet runs a helper contract it never deployed. Overridden code sets both code_hash and code, because revm may run the inline code or look it up by hash.

The inspector: one hook, several recorders

  • lifetimes smart-pointers Every field is a borrowed reference. &'a dyn SnapStateOracle is a trait object behind a plain reference, not an Arc: the inspector never owns the oracle. The lifetime 'a proves the inspector, and therefore the EVM that owns it, cannot outlive the things it points at. Option<&'a T> is the idiomatic “maybe a recorder”: it is pointer-sized (Rust uses the null value for None) and Copy.
  • interior-mutability CodeNeeded (line 50) is a type alias for RefCell<HashSet<[u8; 20]>>. The inspector holds only a shared &CodeNeeded, yet inserts into it: RefCell moves the borrow check to run time (borrow_mut() panics if another borrow is active). It is enough here because one EVM run happens on one thread. The database needs a Mutex for the same job because its type must be Sync; a RefCell is never Sync, so the compiler would refuse to share it across threads.
  • traits-generics impl<CTX: ContextTr> Inspector<CTX> for RequestInspector<'_> is generic over revm's context type, and '_ says “some lifetime, I don't need to name it”. step runs before every instruction.
  • domain Cancellation per instruction. If the oracle says the request is cancelled, set_action makes the interpreter return with Stop, even mid-way through a loop that reads only cached state. The executor checks again after the run (line 1120), so the stop surfaces as Cancelled, not as a short answer.
  • domain borrowing What code did the run need? On a discovery pass, EXTCODESIZE and EXTCODECOPY record the inspected address (its low 20 bytes of the stack's top word), and the call hook (line 127) records each call's code address. Solidity guards a call with an EXTCODESIZE, and against a placeholder (no code) that guard fails before the call runs, so the target shows up here one pass earlier. if let Some(code_needed) = self.code_needed copies the Option<&…> out of &mut self, which is fine because it is Copy.

concurrency interior-mutability runs: AtomicU64 counts EVM runs behind &self. An atomic is the cheapest interior mutability for a single number, like Java's AtomicLong. Ordering::Relaxed guarantees only that the count itself is not torn or lost; it orders nothing else, which is enough for a statistic. cost() returns CallCost by value: it derives Copy, so the caller gets its own snapshot. The host logs this per call (#532).

The prefetch convergence loop

Before the loop, converge (lines 1208–1231) primes the target's account and code with sentinel off, so the first pass runs the real top-level code. The transaction-object entry points also make a first_wave (lines 1373–1378): the sender, the target and each EIP-7702 delegate, plus their code, in one batch. A discovery pass would otherwise see a delegate only one pass late. Why 12 and not 4? The constant's doc (lines 320–329) gives the measurement: a wallet's recorded RelayAdapt7702 shield transaction made 48 of its 57 reads one round-trip at a time behind the old cap of four.

  • iterators-closures traits-generics converge_runs<T> takes the run as mut run: impl FnMut(Option<&CodeNeeded>) -> Result<T, EvmError>. FnMut means the closure may mutate what it captured, so calling it needs &mut access, hence mut run. The loop does not care what a run is: for a call it is one transaction, for eth_simulateV1 (stop 8) a whole simulated block sequence. Both go through the same db, so the access set is the run's.

  • domain error-handling The order is geth's: request refusals (check_tx, a nonce contradicting an override), the fee cap against the base fee, then buyGas (the sender must hold gas × fee cap + value). The algorithm is geth's estimator: a first “optimistic” probe at what the run drew plus the call stipend, times 64/63 (a nested call withholds 1/64 of its gas), then a bisection skewed low that stops within 1.5 %. ENSv2: when v1 no longer speaks for a name

ENSv2 is ENS's new registry design, live on Sepolia during its beta (issue #671). For a name that ENSv2 decides, the v1 registry and BaseRegistrar this file reads no longer speak for its ownership: their entries may be empty (a name registered only in ENSv2) or stale (an expired v1 entry). So resolve_ownership first asks ENSv2's Universal Resolver whether v1 still decides the name, and refuses if it does not. The record reads are not gated this way.

  • enums-patterns error-handling Two let … else statements in a row. Each binds a value or returns Ok(false): no mirror pinned for this chain, or a Universal Resolver that could not walk the name (“unknown is not a yes”). Note what is not folded into “false”: call_address maps only a revert to None; a halt or unavailable state comes back through ? as EnsError::Call, so missing state cannot turn into “v1 decides”.
  • domain Pinned, not recognised. The mirror must be the pinned address and its REGISTRY_V1() must name this registry. A name's ENSv2 owner sets its resolver and could deploy one that answers REGISTRY_V1() correctly; trusting the getter alone would let any owner make an ENSv2 name read as unowned (the #672 review). Where ENSv2 is live but no mirror is pinned (mainnet right after activation), every ownership read is refused.

Reverse resolution and CCIP-Read

reverse_resolve reads the claimed primary name from the resolver of the exact <hex>.addr.reverse node, calling name(bytes32) directly with no supportsInterface probe: old reverse resolvers predate ERC-165 and halt on the probe. Only an address without its own reverse resolver walks up to a wildcard resolver on addr.reverse or reverse (new, #671), which is how ENSv2 primary names on Sepolia answer. Either way the claim is then checked forward.

  • enums-patterns ownership The match works on the owned result of resolve_address, so its patterns can move values out. Ok(Some(fwd)) if fwd == address is a guarded arm. Ok(_) | Err(EnsError::InvalidName(_)) folds a mismatch and a malformed claim into “no verified name”, so a malicious reverse record cannot force an error. The OffchainLookup arm moves lookup (the Box) and wrapped out of the old error into a new one that also carries the claim.
  • ownership claimed: String is taken by value. The first arm moves it into Some(claimed), the third into reverse_claim; only one arm runs, so the compiler accepts both moves.
CCIP-Read, end to end

The resolver reverts with OffchainLookup. revert_outcome (lines 925–935) checks the 4-byte selector after a length check, so data[..4] cannot panic, and decodes the tuple; any other revert is “no record”. A second OffchainLookup keeps the original wrapped flag, and the host enforces the recursion cap.
